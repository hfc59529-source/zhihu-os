# 新流程样本完整归因收益回收清单

用途：下一轮复盘时，确保每篇新流程样本同时带回生产链路、完整归因和收益数据。

执行边界：

- 只回收事实、归因证据和结果数据。
- 不直接修改参数库、不新增 ACTIVE、不修改 Prompt 或生产协议。
- 没有 `Production ID ↔ article_id` 映射时，只记录 Trace 状态，不做变量有效性判断。
- 收益数据必须进入 `data/review_data_snapshots.csv` 同一行，不单独散落记录。

## 01｜样本准入

| 字段 | 要求 |
|---|---|
| Production ID | 必填，必须来自新流程 |
| Topic ID | 必填 |
| article_id | 必填 |
| 问题标题 | 必填 |
| 问题链接 | 必填 |
| 回答链接 | 必填 |
| 发布时间 | 必填 |
| 数据窗口 | T0 / T24 / T72 / T7D / REVIEW_DAY |
| trace_status | COMPLETE / PARTIAL / BROKEN |

准入判断：

- `COMPLETE`：可进入完整归因。
- `PARTIAL`：只能做有限归因，必须写缺失字段。
- `BROKEN`：只保存事实，不做变量判断。

## 02｜结果数据

| 字段 | 来源 | 要求 |
|---|---|---|
| 阅读 | 知乎创作中心内容管理 | 必填 |
| 赞同 | 知乎创作中心内容管理 / 回答页 | 必填 |
| 收藏 | 知乎创作中心内容管理 / 回答页 | 必填 |
| 评论 | 知乎创作中心内容管理 / 回答页 | 必填 |
| 喜欢 / 感谢 | 知乎创作中心内容管理 | 可见则填 |
| 折叠状态 | 内容管理 / 回答页 | 必填 |
| 收益 | 知乎收益分析 / 致知计划收益明细 | 必填；未采集写 UNKNOWN |
| 千阅读收益 | 由收益和阅读计算 | 收益与阅读均存在时必填 |
| earnings_source | 收益来源入口 | 必填 |
| earnings_collected_at | 收益采集时间 | 必填 |
| earnings_window | 收益统计窗口 | 必填 |
| earnings_match_status | MATCH_BY_ARTICLE_ID / MATCH_BY_TITLE_DATE / UNMATCHED / NOT_COLLECTED | 必填 |

## 03｜生产归因证据

| 分类 | 必填项 |
|---|---|
| 选题层 | 题型、读者真实困惑、读者原始理解、实际读者范围 |
| Semantic Freeze | Reality、Main Gap、Transformation 是否有冻结记录 |
| 执行层 | ACTIVE 结构、主变量、首屏类型、核心机制 |
| 参数层 | Claude 声称调用、GPT / 人工确认生效、遗漏参数、误用参数、冲突参数 |
| 正文层 | 正文版本、QA 结论、是否 Patch、Patch 是否确认有效 |
| 发布层 | 发布稿版本、发布链接、发布时间 |

## 05｜批次复盘输出

下一轮回来时，至少输出：

1. 新流程样本列表。
2. 每篇 `Production ID ↔ article_id` 映射状态。
3. 每篇互动数据和收益数据。
4. 每篇完整归因。
5. 与历史基线的分位数对照。
6. 是否满足 Observation 条件。
7. 是否满足参数治理条件。

## 06｜禁止项

- 禁止用 Claude 自报替代 GPT / 人工确认。
- 禁止在收益缺失时判断收益变量有效。
- 禁止把折叠样本归因为正文失败。
- 禁止用 UNKNOWN Production ID 样本判断参数有效性。
- 禁止因单篇低表现直接建立 Observation。
