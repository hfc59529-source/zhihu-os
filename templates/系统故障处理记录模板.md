# 系统故障处理记录模板

用途：把异常处理限制在可定位、可验证、可最小修复的工程闭环内。此模板只用于记录和门禁，不新增正式对象；若需要沉淀为系统观察，转入 `data/Milestone_Observations.md`。

## 基本信息

```text
Record ID：
日期：
记录人：
关联 Production ID：
关联文件 / 链接：
当前状态：OPEN / OBSERVING / TESTING / VALIDATED / CLOSED
```

## 1. Goal

```text
本次原目标：
可观察指标：
验收标准：
```

## 2. Evidence

只写事实、数据、原文证据，不写解释。

```text
实际发生了什么：
关键数据：
原文 / 日志 / 截图证据：
```

## 3. Location

先定位层级，再解释原因。

收益链路偏离层级：

```text
发布 / 曝光 / 点击 / 阅读 / 完读或信任 / 转化 / 收益 / 不适用
```

生产链路偏离层级：

```text
Topic Package / INPUT / DECISION / COMPILE / WRITE / AUDIT / REVIEW / RELEASE / 不适用
```

定位依据：

```text
为什么认为偏离从这一层开始：
为什么不是上一层：
为什么不是下一层：
```

## 4. Hypothesis

默认只允许 1-3 个候选原因。没有证据时保留为候选，不得写成结论。

```text
候选原因 1：
候选原因 2：
候选原因 3：
当前最可能原因：
证据强度：弱 / 中 / 强
```

## 5. Intervention

默认只改一个主要变量。

```text
本轮最小改动：
改动对象：产物 / 模块 / 规则 / 架构
是否只改一个主要变量：是 / 否
若否，归因状态：不可归因
不改动项：
```

故障升级判断：

```text
单次异常：只修当前产物或记录 Observation
重复异常：检查对应模块
稳定复现：修改模块规则
跨模块冲突：进入架构调整
本次属于：
```

## 6. Validation

```text
验证指标：
观察窗口：
对照基准：
通过标准：
失败后回退方式：
```

## 7. Governance Gate

新增规则、字段、模块或对象前必须填写。

```text
是否新增系统复杂度：是 / 否
新增内容：
它解决的稳定复现问题：
它改变哪个决策：
它增加的执行成本：
它的验收方式：
是否已有更小改动可以解决：
最终治理结论：记录 / 修产物 / 查模块 / 改规则 / 调架构 / 不处理
```

## 8. Result

```text
执行动作：
验证结果：
是否升级为 Observation：
Observation ID：
是否修改 Parameter / Runtime Rule：
证据引用：
关闭说明：
```
