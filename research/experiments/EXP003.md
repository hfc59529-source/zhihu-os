# EXP003 - Composition 层控制强度与 Reading Progression 关系实验

## 实验基本信息

**实验编号**：EXP-COMPOSITION-003

**实验日期**：2026-08-09 启动

**研究对象**：生产链路中 Composition（成文）层的约束强度，与正文是否形成持续阅读动力（Reading Progression）之间的关系。不研究"哪句话写得好"，研究"系统该不该规定怎么组织信息释放顺序"。

## 背景

ZH-20260809-001（选题：为什么工人宁愿联合加班也不愿联合涨薪）Draft-v1 完成后，复盘发现：正文逻辑正确、结构完整、Gap 也命中了，但高度疑似复现此前"平台给曝光但没人读"的模式。

排查现有四层协议（`知乎正文推理协议 V1.0.md` / `知乎正文表达协议 V3.md` / 整体审核七项清单 / `知乎内容质量参数库_V2.md`）发现：

- 推理协议全部约束"判断对不对"，无一条约束"判断何时交付"。
- 表达协议 EP-07 只要求首屏给一个继续阅读的理由，EP-10 甚至把"首屏反差后第一次解释"列为推荐的推进峰值位置——即协议本身认可"开头抛反差，紧接着交出机制"这种结构。
- QA 七项清单全部检验判断质量（接住情绪/层层递进/真机制/认知反转/可迁移/可执行/不像AI），没有一项检验"读者读到第二段时手上是否还有一个未解开的问题"。
- `知乎内容质量参数库_V2.md` 的"阅读节奏"分类下列了"信息释放节奏"一词，但从未像 IV-01（信息增量）那样展开成 L2/L3/L4 可执行规则、评分标准或生产最低要求——是一个从未被实例化的空位。
- 已退休的 Production Card 模板（`templates/Production Card模板.md`）中存在 `续读动力` `核心判断位置` 两个字段，说明旧设计曾隐约意识到这件事，但只是孤立填空项，不是完整的状态迁移序列；且当前正式生产链已不经过 Production Card 这一层，连这两个残缺字段也不再存在。

初步诊断：当前生产目标可概括为 Judgment Delivery + Judgment Justification（判断交付 + 判断证成）——Gap 提炼出唯一核心判断后，案例和机制的角色是"证明这个判断成立"，不是"延迟兑现、制造未解问题"。四层协议均未要求做这个区分。

## 竞争假设

诊断出问题后，出现两个方向不同的修复假设：

```text
H1｜能力缺失假设
系统缺少 Reading Progression 的中间表示（如 J0-J7 状态迁移图）
→ 修复方向：新增 Progression Map / Reading Progression Protocol，写入正式协议

H2｜能力被抑制假设
Claude 本身具备组织阅读推进的写作能力，只是现有系统对 Composition 层管得过细
（Card 字段顺序、结构库 ACTIVE 骨架、EP 系列表达规则）抑制了这种能力
→ 修复方向：做减法，把系统职责收缩到 Research / Judgment / Boundary，
  Composition 完全交还给 Claude 的写作判断
```

H1 会继续增加系统复杂度，H2 是做减法。按"生产归生产，研发归研发，先验证再抽象"的系统治理原则，且近期已多次因单篇问题被引导做减法修正，H2 应优先验证，而不是默认走 H1。

## 控制变量设计

同一 Production ID（ZH-20260809-001）下生产三版草稿，Question / Answer_Benchmark_Top3 / Gap / 事实材料 / 唯一核心判断全部锁定不变，只改变信息释放顺序的生成方式：

| 分组 | 生成方式 | 变化状态 | 对应文件 |
|------|---------|---------|---------|
| V1（Baseline） | 当前系统默认约束生成 | Judgment Delivery + Justification：首段给结论，随后逐层证明 | `productions/ZH-20260809-001/Draft-v1.md` |
| V2 | 显式外加 Progressive Judgment Structure（J0-J7 状态迁移图） | 强制 Question → Partial Answer → New Question → Partial Answer → Synthesis 的分层释放 | `productions/ZH-20260809-001/Draft-v2-progression-experiment.md` |
| V3 | 移除一切结构强制（不套 Card 字段顺序、不套 J0-J7），只给 Writer Role 指令："Production Card 是研究材料不是大纲；核心判断和事实边界不可改，怎么组织、何时释放由你决定，唯一目标是让读者持续读下去" | Claude 自主决定信息释放顺序 | `productions/ZH-20260809-001/Draft-v3-writer-authority.md` |

## 已知混淆变量（Confound）

**Experimenter Effect**：V3 撰写时，Claude 已知晓本次诊断背景（知道正在被测试"是否具备自主组织阅读推进的能力"），这可能已经影响了写作决策，不是干净的"系统零介入"对照组。真正干净的 V3 需要另一个不知情的实例只拿到 Question + Top3 + Gap + Facts + Core Judgment + Writer Role 指令、不知晓这是实验，本次条件下无法做到。解读 V3 结果时必须计入此项混淆。

## 当前允许记录的 Observation（不构成结论）

```text
OBS-RP-001

对象：ZH-20260809-001

控制变量：
Question / Top3 / Gap / Facts / Core Judgment 基本固定

V1：
当前系统约束生成
→ Judgment Delivery + Justification

V2：
显式加入 Progressive Judgment Structure
→ 出现明显的分层信息释放

→ Claude 自发采用"场景先行、判断后置"

V3 阅读效果 > V2
V2 阅读效果 > V1
Reading Progression 提高知乎阅读量
（以上均需真实平台数据支撑，当前只有生成阶段的结构观察，无发布后数据）
```

## 发布与数据采集边界

同一问题连续发布三版会造成账号、时间、初始分发、重复内容识别、题目生命周期互相污染，导致比现状更难解释，因此**不对 V1/V2/V3 做同题三版发布 A/B/C**。

本轮只发布一版：**V3**（作为生产候选），理由不是"已证明 V3 效果最好"，而是它承担了当前最有价值的现实验证——系统减少对 Composition 层的控制后，真实平台结果能否恢复。

发布后按系统既有平台指标采集（阅读量、千阅读收益、盐粒收益、完读代理信号、评论类型），不临时新增"读起来更顺""更自然"等主观指标。
