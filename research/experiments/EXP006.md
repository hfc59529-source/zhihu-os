# EXP006 — Process Mining：人工"真实感"判定的四个候选信号

Status：FROZEN AT DISCOVERY LAYER（不进入生产层，不写入任何 Prompt）

## 背景

EXP005 把 Question Understanding Gate 降级为 CANDIDATE 后，发现真正有效的人工判断力可能不在"生成前多想一步"，而在**否决 Judgment/正文时用的标准**。本实验对多个历史真实会话（知乎系统 + 今日头条，均为内容生产场景，不含系统架构讨论会话）做 Process Mining，专门找"模型/系统自评合格 → 人工明确否决"的成对样本，尝试反推这个否决标准。

方法：只记录原始对话中出现过的"对/不对/看不下去/跑偏了"等真实判定文本，与其否决对象的原文并列，不预先假设理论，等多个独立样本出现后再归纳。

## 样本来源

- Session `local_d0cc697c`（领导提拔决策机制分析）：同一篇《哪些人会被提前PASS》的 V1→V2→V3 Core Claim 迭代。
- Session `local_93189e7d`（知乎回答文案生成，EXP004 原始记录）：工人加班/涨薪题的 Judgment 候选1/2/3 筛选。
- Session `local_9b5aa173`（今日爆点话题采集完成）：司机捡手机索1888元 V2→V3→V4 三轮 Quality Review，以及后续5篇正负对照样本。

## 发现的四个候选信号

| 信号 | 含义 | 证据状态 |
|---|---|---|
| A｜Subject Ownership（主语所有权） | 这句话此刻站在谁的处境里说——是读者本人，还是被分析对象（领导/组织/司机） | Candidate |
| B｜Explanation Target（解释目标） | 这句话是否还在回答读者原来那个问题，还是偷换成了另一个问题 | Candidate |
| C｜Abstraction Level（抽象层级） | 读者能否直接拿自己的现实经验验证这句话，还是被拉进一个分析模型/专业词汇 | Candidate |
| D｜Generation Source（生成来源） | 下一句话是被上一句话制造的张力/问题逼出来的，还是被"下一个待覆盖的字段"逼出来的 | Candidate，跨样本证据相对最强（5篇正负对照，方向一致） |

### 样本证据（节选）

**A（主语漂移）**——V2 被 Claude 自评 8.5/10（反转、场景感达标），用户否决：
> 用户期待的是："哪些人会被PASS？为什么？"而我后面写着写着，主题变成了："领导如何判断风险。"

**B（问题漂移）**——工人题候选3被否：
> 它实际上把问题改成了"为什么工人判断抗争不划算"……离原题的那个反常识现象反而远了。

**C（抽象层漂移）**——"风险"被进一步否决，改为"用了你我会更累"：
> "风险"还是领导视角。……"用了你，我会更累"……这比"风险管理"更生活化，也更符合读者感知。

**D（字段驱动 vs 意义驱动）**——1888元 V3 被两轮否决，且 A/B/C 均未命中（主语、解释目标、抽象层全程未漂移）：
> 每一句单独都有来源，但合起来没有一个中心命题统领……下一句话的来源应该主要是：上一句话提出了什么问题？而不是：Radar 下一个字段是什么？

D 用"删除转场词后前后句是否仍能自然衔接"作为操作性测试，反查5篇历史正文（3篇当时判"差"、2篇当时判"认可"），结果稳定：差稿在"转场词精确落在字段边界／删除后主线断裂／无单一核心问题贯穿"上全部命中 Field-driven；好稿即使有残留，也只在局部过渡句，未污染中心命题和推理链。这是本轮唯一有正负对照、跨样本验证过的信号。

## 关键区分：D 不是 A/B/C 的变体

D 样本证明了一件事：**A/B/C 全部不漂移，文章仍然可以被否决**。这说明"真实感"不是单一变量，至少要拆成两层不同性质的东西：

```text
A / B / C  →  Reader Alignment（读者对齐）
读者在检查："你还是在跟我说这件事吗？"

D          →  Article Coherence（文章整体连贯性）
读者不知道什么叫 Radar/字段/Prompt，只会感觉："你为什么突然跟我说这个？"
```

真实读者不会说出"Generation Source 错误"这种话；这是系统设计者回头分析时才看到的机器层原因。**Reader Signal 和机器诊断必须分开描述**，不能把机器故障描述直接当成读者审核标准去写规则。

## 更重要的结构性发现：这可能根本不是一张评分表

过去的 Quality Review 是静态清单：
```text
完整文章 → 套评分标准 → 结构8分/可读性8.5/案例9分 → PASS
```
但从这几组样本看，人工否决的动作更像一次**连续的阅读模拟**，一步断了就产生"不对"，而不是读完整篇再打分：

```text
我点进来想知道什么？
↓
你现在还在回答我吗？        ← B
↓
你现在还是在跟我说吗？      ← A
↓
你说的东西我现实里认得吗？  ← C
↓
你为什么现在突然说这个？    ← D
↓
我还想不想继续看？
```

这指向一个可能比"四个静态信号"更本质的方向：**Reader Simulation（读者模拟）**——让 AI 从第一句开始只拥有真实读者的初始困惑，逐段更新"我现在知道了什么／我现在自然想知道什么／下一段是不是在回应这个"，而不是事后拿清单核对成品。这个方向本身也只停在 Candidate，不做设计。

## 当前状态（冻结点）

```text
Signal A（Subject Ownership）   Candidate，单样本
Signal B（Explanation Target）  Candidate，两样本（含 EXP005 中的候选3）
Signal C（Abstraction Level）   Candidate，单样本
Signal D（Generation Source）   Candidate，5篇正负对照，证据最强
Reader Alignment vs Article Coherence 的分层  Observation，未验证独立性
Reader Simulation 方向          Observation，未设计、未验证
```

## 明确不做的事

- 不把 A/B/C/D 合并成一条规则。
- 不验证 D 是否独立于 A/B/C（比如找"D 无问题但 A/B/C 有问题"的反例）——下一阶段再做。
- 不写入任何 Production Prompt。
- 不设计 Reader Simulation 的具体实现。

这轮到发现层为止，不进入生产层。下次要推进，应该先做的是 A/B/C/D 的独立性验证，而不是急着把发现变成系统改动——这正是 EXP004/EXP005 反复暴露过的同一个陷阱：找到一个有意思的现象，立刻把它写进 Prompt，系统又多几条规则。
