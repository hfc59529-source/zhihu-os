# EXP004 — Production Prompt 生成顺序故障定位（Author vs Executor）

Status：CLOSED（结论已产出，V6 冻结，进入 Replicated Pattern 验证阶段）

## 背景

EXP003 之后发现：即便 Topic Package 输入质量足够（Top3、Coverage、Gap、Avoid Repetition 齐全），Claude 在正式 Production Prompt 下仍产出"正确但字段化、解释腔"的文章（样本：`productions/ZH-20260809-002/Draft-v1.md`，已标记 CONTAMINATED_SAMPLE，不进发布队列）。本实验目的是定位故障点：是 Topic Package 问题、Claude 能力问题，还是 Production Prompt 问题。

## 方法：分层 A/B 实验

同一 Topic Package（TOPIC-20260809-001，"为什么工人愿意联合加班却不愿意联合涨薪"）：

- **实验 A**：旧 Production Prompt（`Claude正文生产Prompt.md` 修改前版本）→ 字段化、覆盖式，文章"死了"。
- **实验 B**：极简 Judgment Prompt，只要求"如果整篇回答只能让读者记住一句判断，会是什么"，输出3候选+一句理由，不写正文，不生成 Card。→ 判断能力正常，候选2明显最优（"加班可以没有发起人，涨薪必须产生一个"）。
- **实验 C**：锁定候选2，只回答"如果只能证明这句话，怎么讲出来"，不给字段要求。→ 文章结构明显恢复，论证自然生长，案例（2010年停产）从"证明风险高的字段"变成"证明发起人是唯一被处理对象"的论据。

## 结论 1：主故障定位

旧 Prompt 的核心问题不是测辞、不是材料，而是**生成顺序错误**：

```
旧机制：Fields（字段）→ Coverage（覆盖）→ Draft
应为：  Judgment Formation（判断形成）→ Evidence Check（证据检验）→ Card → Draft
```

旧 Prompt 把 Claude 的角色定义为"执行器"（"你是知乎正文执行器，不是系统维护者"），且核心动作是"匹配变量、覆盖参数"，没有任何步骤要求它做 Selection（取舍）。这是 Over-specification：约束层层加码（Parameter→Gap→Intent→Boundary→Card→Fidelity→Quality Review）本意是防错，实际效果是让模型不敢舍弃，只敢覆盖。

## 结论 2：V6 修复方案

在 `templates/Claude正文生产Prompt.md` 做最小修改，不新增系统模块：

1. 开场角色定义："你是知乎正文执行器" → "你先是作者，判断锁定之后才是知乎正文执行器"。
2. 新增 **Judgment Formation Gate**，插在原 Semantic Freeze Gate 之前：自由生成3候选 Judgment（沿用实验B的5条筛选标准）→ 选1个锁定为 J0。
3. 原 **Semantic Freeze Gate** 职责改变：从"独立推导 Reality/Gap/Transformation 三个对象"，改为"用材料检验/收缩 J0 → J1"（Evidence Boundary 作为判断形成后的检查器，而非生成前的控制器）。

## 结论 3：Judgment Fidelity Bug（6a）及修复

用同一样本完整跑 V6（J0→J1→Card→Draft），发现：

- J0（判断形成）：PASS，与实验B候选2一致。
- J1（证据检验收缩）：PASS，把"真正原因"（排他性断言）收缩为"能解释"（非排他表达）。
- Production Card：PASS，六项字段全部服务于 J1，没有反客为主重新字段化。
- **Draft 展开：FAIL** —— 正文阶段偷偷把 J1 已收缩的因果强度重新拉高。例如 J1 说"能解释"，Draft 却写成"组织就是这样处理涨薪"（必然机制断言）、"风险只落在发起人身上"（排他表达），材料实际只能证明"代表承担了更高的可识别风险"，不能证明"唯一对象"或"必然机制"。

**修复**：在执行规则新增 6a：
> 正文不得将 Judgment Formation Gate 中已经收缩的判断（J1）重新强化。若 J1 使用"能解释、可能、部分、之一"等非排他表达，正文中的因果强度不得高于 J1；案例只能证明选题包明确支持的事实关系，不得把相关性或风险不对称扩写为唯一对象、必然机制或排他因果。

重跑 Draft（仅重跑正文层，J0/J1/Card 不变），6a 生效后因果强度与 J1 保持一致。

## 最终判定

```
Topic Package          PASS
Judgment Formation     PASS
J0 → Evidence Check    PASS
J1                      PASS
Production Card         PASS
Draft Growth             PASS
Judgment Fidelity（6a） PASS（修复后）
```

**Production Mechanism：PASS（单样本）。Content Effect：未验证**——本实验只证明 V6 能否按作者判断自然生成逻辑一致、证据不越界的文章，没有证明这类文章在知乎上阅读效果更好，后者必须靠发布数据（L1）判定，不能用单篇读感（L3）代替，参见 [[EXP003]] 已建立的层级纪律。

## 四条可复用结论

1. 旧 Prompt 主要故障：Executor-first + Coverage-driven 压制了作者取舍。
2. Judgment-first 有效：同一 Topic Package 下能形成明显更集中的唯一判断。
3. Semantic Freeze Gate 不需要删除：放到 Judgment 之后，正确承担 Evidence Boundary 职责，不干扰判断形成。
4. 6a Judgment Fidelity 必要：否则 Draft Expansion 阶段会重新提高已被 J1 收缩的因果强度。
