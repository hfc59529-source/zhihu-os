# EXP008 — Distribution Model：高收益回答的播放差异验证

Status：CANDIDATE RESEARCH PROTOCOL（不进入 ACTIVE，不修改 DMPI / 正文协议）

## 背景

知乎系统当前问题已经从“如何写出高收益内容”切换为“高收益内容为什么有的播放高、有的播放低”。

本实验不继续拆正文结构，不把 `P × E × C × A × M` 直接写成生产规则。当前目标只回答一个更窄、可证伪的问题：

```text
在收益能力已经较高的回答里，哪些变量解释了播放量差异？
```

因此先尽量控制 `M｜Monetization` 和 `Exposure Age｜暴露时长`，重点比较：

```text
A：收益能力相近、发布时间相近、播放更高
B：收益能力相近、发布时间相近、播放更低
C：低收益 + 高播放（第二优先级，用于区分流量变量和变现变量）
```

第一轮核心是 matched `A vs B`。如果两篇收益能力和暴露时长相近，但播放差距明显，就优先寻找问题池、进入时机、入口竞争力、互动扩散上的系统差异。

## 母模型

候选分发模型仅作为研究框架：

```text
Revenue ≈ P × E × C × A × M

P = Potential：问题流量潜力
E = Entry：回答入口能力
C = Consumption：正文消费能力
A = Amplification：互动扩散能力
M = Monetization：收益能力
```

当前已相对有证据的是 `M`，正文系统覆盖一部分 `C`。本实验优先验证未知最大的 `P + E + A`。

## 第一轮：历史样本对照

### 分组口径

初始分组使用 `data/l0_content_assets.csv` 的 `views / earnings / earnings_per_1k_views / published_at`，只作为候选样本，不作为结论。

```text
默认不再使用“RPM 中位数 × 累计播放中位数”直接切 A/B/C。

默认使用 Matched Pair：
1. 剔除低播放 RPM 不稳定样本：views < 150 不进入第一轮配对。
2. 控制收益能力：配对两篇 RPM 差异比例 <= 45%。
3. 控制暴露时长：配对两篇发布时间差距 <= 14 天。
4. 保留播放差异：高播放样本 views 至少是低播放样本 2 倍。
```

如果拿不到 24h / 72h / 7d 固定窗口数据，允许临时使用 `views_per_day` 做弱校正，但必须明确标为 `WEAK_MATCHED_CANDIDATE`。累计播放不得单独作为 Distribution 差异证据。

旧的 A/B/C 粗分只保留为样本探索，不进入第一轮验证。

### 只标 10 个变量

第一轮禁止扩字段。每篇只补：

```text
1. question_attention_level：问题关注/浏览量级
2. question_stage_at_publish：new / rising / old
3. existing_answer_count：已有回答数量级
4. high_like_occupied：是否已有高赞回答占位
5. audience_scope：narrow / medium / broad
6. conflict_strength：1-5
7. emotional_charge：1-5
8. first_sentence_judgment：首句是否直接下判断
9. first_100_interest_conflict：前100字是否出现利益冲突/反常识
10. engagement_rates：赞同率、评论率、收藏率
```

### 因果层级

第一轮分析禁止把 10 个变量平铺成相关性表。必须按下列顺序解释：

```text
Question Context
  ↓
Content Entry
  ↓
Initial Distribution
  ↓
Engagement
  ↓
Further Distribution
```

变量分层：

```text
Pre-distribution variables：
question_attention_level
question_stage_at_publish
existing_answer_count
high_like_occupied
audience_scope

Content treatment variables：
conflict_strength
emotional_charge
first_sentence_judgment
first_100_interest_conflict

Post-distribution outcome / mediator：
like_rate
comment_rate
favorite_rate
```

互动率只能作为后置结果或中介变量。禁止从“高播放文章互动率更高”直接推出“互动率导致高播放”。若出现低播放样本互动率更高，优先记录为对单变量互动放量模型的反例。

### 历史标注证据来源

证据来源分两类理解。

Platform-state evidence 用于发布当时的平台状态字段：

```text
question_attention_level
question_stage_at_publish
existing_answer_count
high_like_occupied
```

这些字段必须标注时间证据：

```text
OBSERVED_AT_PUBLISH：发布当时已采集或截图保存
RECONSTRUCTED：可由时间序列、旧快照、上下文较可靠重建
CURRENT_ONLY：只能看到当前知乎状态，不得当作发布时事实
UNKNOWN：无法确认
```

宁可 `UNKNOWN`，也不得把当前问题关注数、回答数、高赞占位回填为发布时状态。

Text-derived annotation 用于根据历史问题文本或回答原文编码的字段：

```text
audience_scope
conflict_strength
emotional_charge
first_sentence_judgment
first_100_interest_conflict
```

这些字段不表示平台历史状态。其 evidence 写 `RECONSTRUCTED` 时，只表示“由历史原文编码”，不是恢复出某个发布时的平台事实。未完成编码前统一写 `PENDING`。

### 盲标工作流

Text-derived annotation 必须盲标。标注员只能使用：

```text
data/distribution_text_annotations_blind.csv
```

盲标表允许出现：

```text
blind_id
title
question_text
answer_text
text_source_status
text_source_path
audience_scope
conflict_strength
emotional_charge
first_sentence_judgment
first_100_interest_conflict
对应 evidence
annotation_status
```

盲标表禁止出现：

```text
pair_id
pair_role
views
earnings
earnings_per_1k_views
views_per_day
like_rate
comment_rate
favorite_rate
```

标注完成后，再通过 `article_id` 或 `data/distribution_text_annotations_blind_map.csv` join 回 matched-pair 表做 Pairwise Difference。平台历史字段另走 evidence collection，不属于文本盲标。

`article_id` 不进入盲标表，只保留在 `data/distribution_text_annotations_blind_map.csv`。若本地历史正文缺失，`answer_text` 保持空，`text_source_status` 写 `TEXT_MISSING`；该样本不得标注 `first_sentence_judgment` 和 `first_100_interest_conflict`。

### 可证伪判断

```text
如果 A 与 B 的问题池大小无系统差异：
  P 假设削弱。

如果 A 明显更早进入问题、竞争更低：
  Timing / Competition 优先。

如果问题条件接近，但 A 首句和前100字明显更强：
  Entry 假设增强。

如果初始播放接近，但 A 的互动率更高且 6h→24h 放量更强：
  Amplification / Consumption 假设增强。
```

第一份报告只做 Pairwise Difference，不做“10 个变量谁最重要”的总排序。

## 第二轮：拆阶段结果

以后每篇回答必须尽量补时间序列，不再只看最终播放。

推荐采集点：

```text
1h / 3h / 6h / 12h / 24h / 72h
```

判断逻辑：

```text
如果 1h 就明显分化：
  问题更可能发生在 P / 发布时机 / 初始竞争。

如果 1h 接近，但 3h 或 6h 后分化：
  问题更可能发生在 E / C / A。

如果 6h 以后停止增长：
  重点回看互动率、收藏率、评论率、完读/停留代理指标。
```

## 第三轮：主动变量实验

历史数据只能发现相关性，不能证明因果。第二阶段开始做控制变量实验。

示例：验证 `Early Entry`。

```text
相似问题
同一正文系统
只改变前100字

A：温和解释型开头
B：判断前置 + 利益冲突前置
```

连续 10-20 篇后比较：

```text
前3小时播放增速
24小时播放
赞同率
评论率
收藏率
最终收益
```

只有稳定胜出，才允许升级为生产候选变量。

## 第四轮：失败预测

发布前必须写预测，发布后核验。

预测格式：

```text

```

如果连续 20 篇预测无法区分高低播放，模型无效，重做。

## 当前优先验证假设

```text
H1：Question Selection 决定主要播放上限。
H2：Early Entry 决定能不能吃到第一轮流量。
H3：Engagement / Consumption 决定是否获得后续放量。
```

本实验的关键问题不是“爆文有哪些特征”，而是：

```text
高收益低播放为什么输给高收益高播放？
```

若最后发现最大差异在问题池和进入时机，下一代知乎系统核心升级应是 `Question Selection / Distribution Gate`，而不是继续扩写正文协议。

## 2026-09-03 研究层修正：二次激活样本

本次 2026-09-03 最近 7 天收益窗口出现一个足以修正分发模型的强观察样本：

```text
样本：体制内，为什么领导一眼就能看出你是老实人？
发布时间：2026-08-18

2026-08-30 观察：
最近 7 天阅读：1,305
最近 7 天收益：72 盐粒
累计阅读：3,711
累计收益：265 盐粒

2026-09-03 观察：
最近 7 天阅读：10,855
最近 7 天收益：520 盐粒
累计阅读：14,238
累计收益：773 盐粒

2026-08-30 至 2026-09-03：
累计阅读增加约 10,527
累计收益增加约 508 盐粒
```

审计判断：

```text
现象判断：高可信
模型修正：高价值
机制解释：暂不成立
生产规则迁移：暂不建议
```

该样本不能证明某类正文可以稳定触发二次放量，但足以推翻一个弱假设：

```text
错过早期流量后，回答基本死亡。
```

EXP008 后续研究层必须显式区分：

```text
Initial Distribution：第一轮分发
Secondary Distribution / Reactivation：二次激活
Long-tail Persistence：长尾持续
```

原有分发链路暂扩展为研究框架：

```text
Question Context
  ↓
Entry
  ↓
Initial Distribution
  ↓
Consumption / Engagement
  ↓
Further Distribution
  ↓
Reactivation
  ↓
Long-tail Persistence
```

同时，`views_per_day` 只能作为无固定窗口时的弱校正指标。它会把以下两类完全不同的分发机制平均成同一个数：

```text
稳定增长：每天稳定 500 阅读
二次激活：前 10 天每天 100 阅读，第 11 天突然 10,000 阅读
```

因此，后续 EXP008 的关键研究问题从单纯的：

```text
高收益低播放为什么输给高收益高播放？
```

扩展为：

```text
为什么有些回答会被知乎重新捞起，而另一些回答在第一轮结束后停止扩散？
```

执行边界：

```text
1. 本条只进入研究层，不修改生产协议。
2. 不新增内容变量，不升级 ACTIVE 参数。
3. 后续优先补充重点样本的时间曲线：发布时间 → 第一轮增长 → 停滞 → 二次增长 → 长尾。
4. 对“老实人”样本重点追踪二次激活触发条件，但不得把单样本解释为可复制规则。
```


### 阶段性策略结论

基于 2026-09-03 复盘，当前不要继续把主要精力放在正文系统优化上。

理由：

```text
1. 播放和变现是两个独立问题。
   “老实人”本期 10,855 阅读 / 520 盐粒，约 48 盐粒 / 千阅读；
   “经理/总监上不去”本期 1,296 阅读 / 239 盐粒，约 184 盐粒 / 千阅读。
   账号内容已经具备较强变现能力，继续提高 RPM 不是当前第一优先级。

2. 知乎分发不是发布后一次性完成。
   “老实人”发布十几天后，在 2026-08-30 至 2026-09-03 之间累计阅读增加约 10,527，
   证明至少存在需要追踪的 Secondary Distribution / Reactivation 现象。

3. 新文章第一轮拿到流量，不代表会继续放量。
   2026-08-25 发布的部分新文第一轮拿到几百至上千阅读，但随后快速停滞。
   下一步真正要解释的是：什么条件让知乎继续分发，甚至重新捞起一篇旧回答？

4. EXP008 方向正确，但目标应进一步收窄。
   暂时不扩变量，不修改生产协议。
   优先研究 Initial Distribution → 停滞 → Reactivation → Long-tail。
```

一句话结论：

```text
知乎系统现在“正文生产”基本够用，下一阶段真正要破解的是 Distribution Gate：
为什么有些文章会获得第二轮放量。
```

若该机制后续被验证，系统升级重点应从“怎么把文章写得更好”，转为：

```text
怎么选题
怎么进入
怎么提高文章被持续 / 再次分发的概率
```
