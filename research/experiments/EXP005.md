# EXP005 — Question Understanding Gate（候选前置门）：CANDIDATE，未采纳入正式 Prompt

Status：OPEN（设计已定，尚未跑真实对照）

## 背景

EXP004 把 V6 判为 Production Mechanism PASS 并冻结。此后在一次诊断性对话中，针对 TOPIC-20260809-001 做了一次"读者视角校准字段是不是真正参与了 Judgment 形成"的人工核对，结论是：这些字段目前是 Soft Dependency（Judgment Formation Gate 可以用也可以不用），存在被忽略的风险。

为把它变成 Hard Gate，设计并短暂写入了 `templates/Claude正文生产Prompt.md`：在 Judgment Formation Gate 之前插入 Question Understanding Gate，显式声明只消费选题包中「原问题/必要上下文/Question Owner/Primary Reader/Reading Motivation/读者真实困惑/提问者真正想知道什么」，禁止读取 Existing_View_Coverage/Possible_Current_Gap/Parameter_Gaps 等答案层材料，先独立锁定 Explanation Target，再进入 Judgment Formation。

在同一 Topic Package（TOPIC-20260809-001）上做了一次单样本推演（非真实 Claude 生成，是本会话内的自评式演练）：旧 Target（选题包第5节，已被"短期确定低风险/长期对抗高风险"污染）→ Gate 处理 → 新 Target（还原为纯比较关系，无机制词）→ 3个候选 Judgment → J0，结果自评为 PASS。

## 为什么降级为 CANDIDATE，未采纳

对同一 session（`local_93189e7d-6262-4f5c-b457-b3b2efa115da`，"知乎回答文案生成"）做 Process Mining，还原了 EXP004 实际发生时的真实人工路径，发现两点与本次设计不一致：

1. **昨天的路径里，Question Understanding 和 Judgment Formation 从未分成两个独立阶段**。实验B是把完整 Topic Package（含读者视角校准等全部字段）一次性交给 Claude，直接问"如果整篇回答只能让读者记住一句判断，会是什么"，没有先抽取 Explanation Target 再生成候选。
2. **真正起到"校验有没有偏离原题"作用的，是 Judgment 生成之后的 Selection 阶段**，不是生成之前的前置门。原始记录：三个候选生成后，用户否掉候选3的理由是"它实际上把问题改成了'为什么工人判断抗争不划算'……离原题的那个反常识现象反而远了"——这是事后校验，不是事前锁定。

也就是说，Question Understanding Gate 不能被论证成"把昨天已经生效的人工步骤自动化"，证据不支持这个说法。它是本次会话新设计、只有单样本自评支持的结构，且这个结构（前置门 + 输入白名单 + 禁止清单 + 失败退回条件）与 EXP004 诊断出的致病模式——过度规定层层加码、压制作者取舍——在形状上相似，有重新把 Author 压回 Executor 的风险。

按系统治理原则（连续同类样本才能升级，不因单篇/单次推演改协议），已将本次改动从 `templates/Claude正文生产Prompt.md` 撤回，恢复到 EXP004 冻结的 V6 版本，不再作为正式生产结构存在。

## 待验证的 A/B 设计（下次真实生产时执行，不是这次跑的）

同一 Topic Package、同一 Claude、同一 Judgment 5条筛选标准，只比较两条路径的 J0：

```text
A｜No-Gate（对照，即当前 V6 实际路径）
完整 Topic Package
→ 直接生成 3 个 Judgment
→ Selection 时检查是否回答原题真正的反常点

B｜Gate（本实验的候选设计）
Reader-context 字段
→ Question Understanding Gate（先独立锁定 Explanation Target）
→ 生成 3 个 Judgment
→ Selection
```

比较三项：

1. J0 是否更贴原题；
2. J0 是否更有取舍、能自然长出文章；
3. B 是否因为前置锁定 Target 而缩小了 A 本可能发现的候选空间（即 Selection 阶段本可能否掉/发现的东西，被 Gate 提前排除了）。

判定规则：

- A、B 差不多 → Gate 没必要存在，删除本实验分支。
- B 稳定减少"回答了另一个问题"，且没有让 J0 变得更平庸、更安全 → 可以考虑把 Gate 重新提交为候选修改，走正常升级流程。
- B 更规整、更安全、但更平庸 → 重复了 EXP004 已经诊断过的错误（为了防偏把作者先框死），判 FAIL，永久放弃这个方向。

## 下一研究对象（比继续设计新 Gate 更值得做）

Process Mining 挖出的真实人工路径可以概括为：

```text
生成多个可能解释
↓
不问"哪个最完整"
↓
而问："哪个真的回答了原题最奇怪的地方？"
↓
否掉偷换问题的 Judgment
↓
锁一个
↓
再做 Evidence Boundary
```

这比本实验设计的前置 Gate 更接近真实有效行为。下一步应该研究的不是"生成前还要加几道理解门"，而是：**用什么标准否掉一个看起来聪明、但实际上回答偏了的 Judgment**（Judgment Selection Rule）。昨天候选3被否，是这个研究方向的第一条真实样本，值得回去逐条拆解否决理由的结构，而不是继续往 Judgment Formation 前面叠新步骤。
