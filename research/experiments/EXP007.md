# EXP007 — Interaction Compiler：稳定冲突题的候选机制工具

Status：CANDIDATE MECHANISM TOOL（不进入 ACTIVE，不新增 Gate，不写入正文术语）

## 背景

本实验来自一次对 Game Structure（博弈结构）视角的系统审计。审计结论不是"博弈论应该进入系统"，而是发现现有知乎系统已经隐含覆盖了多数博弈分析能力：

- `CV002｜利益重分配` 已经要求说明谁获得收益、谁承担成本、谁保留选择权。
- `CV003｜组织视角` 已经要求把个人行为放回权责、流程、评价、授权、资源和风险分配中解释。
- `CV004｜风险传导` 已经要求说明风险从谁传到谁、通过什么机制传导、谁承担最终后果。
- `docs/知乎正文推理协议 V1.0.md` Rule 05 已经要求按"现象 → 机制 → 利益关系 → 行为结果 → 结论"推理。
- Rule 06 已经要求不同主体只能按自身目标推理。
- `runtime/知乎结构库快照.md` TS01 已经要求机制终点落到现金流、资源分配、风险承接、选择权、定价权、组织运行或身份成本。

真正缺口不是新理论，而是：这些变量经常以静态方式分别出现，没有一个后台步骤把多方主体拉到同一个局里推演它们如何互相作用，最终形成一个稳定结果。

因此本实验将 Game Structure 收窄命名为：

```text
Interaction Compiler（交互推演器）
```

它的作用不是解释"谁对谁错"，而是回答：

```text
如果每个主体都按自己的利益做最优选择，他们会互相逼出什么结果？
为什么这个结果明明让某些人难受，却长期稳定存在？
```

## 生产后台四问

原始 Game Structure 的 Players / Incentive / Payoff / Power / Strategy / Risk / Exit / Equilibrium 在审计中被判定为理论上完整，但生产使用偏重。

当前候选四问压缩为：

```text
1. 谁想要什么？
2. 谁承担什么？
3. 每个人怎么做对自己最划算？
4. 为什么所有人都这么做以后，反而形成了现在这个局？
```

前两问用于拉出利益结构。第三问开始交互推演。第四问负责生成机制反转：把"解释一个现象"推进为"解释这个现象为什么会自我维持"。

## 适用题型：Stable Conflict

Interaction Compiler 只适用于稳定冲突题。

识别标准：

```text
多主体
+ 利益不一致
+ 权责不一致
+ 某一方明显难受或吃亏
+ 结果长期存在
```

典型关系：

- 老板 vs 员工
- 上级 vs 下级
- 总部 vs 分公司
- 骨干 vs 组织
- 老员工 vs 新员工
- 合伙人 vs 合伙人

不适用或慎用：

- 单主体成长题
- 纯事实题
- 纯表达题
- 轻情绪陪伴题
- 动作优先的解决型问题
- 不存在长期稳定结果的问题

尤其要注意：TS02 解决题如果强行调用，容易把动作、话术和边界写复杂，降低可执行性。

## 历史 A/B 审计证据

本轮只做历史回看和主观机制质量判断，不构成 Content Performance 证据。

### 1. 老板绕过中层直接给基层下指令

A（现有系统）：信息和责任不能断链；中层价值不是挡在老板和基层之间，而是把越级带来的混乱重新接回管理链条。

B（增加 Interaction Compiler）：老板获得控制感和一手信息，基层获得曝光机会，中层失去指令入口但保留兜底责任；各方理性行动后，形成"指令可以越级，风险仍回到中层"的稳定局。

判断：B 明显增强利益冲突和责任回流感。

### 2. "上面本意是好的，只是下面执行出了问题"

A（现有系统）：责任归属取决于谁掌握决策权、授权权、监督权和纠错权。

B（增加 Interaction Compiler）：上层保留动机解释权和拍板权，执行层承担失败可见成本；只要监督和纠错权不下放，最划算的话术就是"本意好，执行错"，最终形成权力上收、责任下沉。

判断：B 有增益，但现有 IR 已经很接近 Interaction Compiler，边际增益中等。

### 3. 职场形式主义为什么越来越严重

A（现有系统）：撤销与新增在责任归属上的成本不对称，形成单向棘轮。

B（增加 Interaction Compiler）：新增者几乎无失败成本，撤销者承担未来追责；所有人理性选择"多留一项"，最终形成只增不减。

判断：B 与现有优秀机制基本等价，说明系统已隐含覆盖动态互动，只是尚未命名为后台工具。

### 4. 企业二代为什么不愿接班

A（现有系统）：责任全担、权力不给；核心是权责不对等。

B（增加 Interaction Compiler）：上一代保留控制权、安全感和身份，二代承担经营失败、签字责任、员工饭碗；二代退出接班而选择创业，是在避免"无权担责"的劣势局。

判断：B 明显增强"不接班是理性选择"的反转强度。

### 5. 任务给业务骨干，晋升给别人

A（现有系统）：任务分配和晋升分配是两套逻辑；任务测确定性，晋升看长期绑定。

B（增加 Interaction Compiler）：组织把交付风险交给骨干，把长期资源绑定给更可控的人；骨干为了维持评价继续救火，组织因此更有动力继续把风险任务交给他，而不是把资源交给他。

判断：B 明显增强"被培养还是被消耗"的冲突判断。

### 6. 新负责人第一件事该干啥

A（现有系统）：先做权力、关系和信息三重校准。

B（增加 Interaction Compiler）：上级给名义职位但未必给真实授权，原同事测试边界，新负责人承担动作失败成本。

判断：B 有帮助，但副作用明显；解决题更需要动作和话术，强行推演会让内容抽象化。

### 7. 领导拿走任务，失败后又想还给你

A（现有系统）：不是任务还给你，而是失败后的新任务；必须重写权责、资源和留痕。

B（增加 Interaction Compiler）：领导保留调配权和评价权，前任接手者留下失败成本，读者若接回则承担最终验收风险；最优策略不是情绪拒绝，而是把"帮忙"改写成"重新立项"。

判断：B 强增益，能把"别背锅"从情绪建议变成机制判断。

### 8. 高层不行，老板为什么不裁

A（现有系统）：高层绑定客户、资源、团队和责任链，替换成本高。

B（增加 Interaction Compiler）：老板知道高层效率低，但裁掉他的确定性风险大于继续忍受低效成本；高层越感觉危险，越有动力增加资源绑定，提高自己的替代成本。最终形成：老板越觉得他不行，越需要等替代方案；高层越危险，越会增加组织对自己的依赖。

判断：B 最能体现本实验价值：从"解释现象"推进为"解释现象如何自我维持"。

## 初步结论

Interaction Compiler 的有效增益不在"解释利益结构"，而在解释：

```text
为什么每个主体都做对自己最划算的选择后，
会共同制造一个让某些人难受、却长期存在的稳定局面。
```

这能补足部分职场机制文的问题：解释正确，但冲突不够；机制说清了，但没有说明为什么局面会自我维持。

## 副作用

- 容易让正文更抽象。
- 容易把解决型问题写成机制课。
- 如果 Players / Payoff / Equilibrium 等术语进入正文，会显著增加理论感。
- 会增加 COMPILE 成本。
- 对非 Stable Conflict 题价值不足，强行调用会制造复杂度。

对照方式：

```text
A｜未调用 Interaction Compiler 的相邻 Stable Conflict 题

```

比较指标：

- 机制解释深度
- 利益冲突清晰度
- 反转强度
- 金句/判断句质量
- 是否减少"只是在解释一个现象"的感觉
- 发布后的阅读、赞同、收藏、评论、收益
- 生产成本和抽象化副作用

判定规则：

- 只提升主观机制质量，不提升发布表现：保留为手动候选工具，不推进参数。
- 稳定提升 Stable Conflict 题发布表现，且副作用可控：考虑进入 Candidate Parameter 或 Runtime 候选流程。
- 让正文更复杂、更理论化、表现不升反降：关闭实验，不进入系统。
