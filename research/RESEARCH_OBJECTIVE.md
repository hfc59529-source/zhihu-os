# 知乎系统 Research Objective

确认日期：2026-10-09；经营目标更新：2026-10-13（Africa/Nairobi）
状态：用户确认的经营优先级与研究目标；不是已验证的盈利机制、生产规则或数值评分函数。
层级：经营目标约束研究资源配置，高于EXP008等单个实验；生产治理仍以现有权威文件为准。

## 经营目标与评价口径

**知乎系统按照商业项目评价：在可接受的时间、资金和风险约束下，持续创造净收益。**

第一阶段目标：知乎业务月净收益3000元。目标已确认，达成可行性尚未证实；不再以月1000元作为当前目标。平台内容收益是现有业务，咨询等其他知乎业务只有经过真实交易验证，才能进入有依据的经营预测；单笔成交仍不证明可重复收益。

目标层级：盈利决定是否值得继续投入；生产效率服务于盈利；内容资产积累服务于未来盈利。逻辑、系统思维和表达训练属于附带价值，不计入盈利绩效，也不能抵补未达成的现金目标。

净收益须扣除同范围可归属成本。现金成本与实际人工工时分别记录；人工是否折价、单价、共享费用分摊及结算确认口径尚待明确，不能默认成本为0。月工时上限、现金预算、实现期限及持续达标的观察月数均待确认。平台收益折算不等于已提现净收入；成本或结算未知时，净收益保持UNKNOWN。

分别评价经营结果（收入来源、规模、增长）、经营效率（成本、工时及增量回报）与经营决策（未来投入的预期回报、验证成本和风险）。历史投入与未来增量投入分开，沉没成本不自动构成继续或停止的理由。

经营决策顺序：盈利机会 → 预期收益与不确定性 → 投入成本 → 生产或其他经营行动 → 实际收益 → 资源重新配置。这是资源配置原则，不替换Compiler生产节点，不自动新增选题权重。

研究、采集与系统升级必须说明：将影响哪个选题、产量、成本或变现决策；什么结果会改变行动；验证的预算、期限和停止条件是什么。基本质量、诚信与必要运行维护继续遵守；额外复杂度需说明降低成本、提高收益或改善未来决策的价值，不以制度完整度代替经营成效。

CONTINUE / REDUCE / STOP / EXPERIMENT用于具体活动或经营路径。证据不足保持UNKNOWN，可支持预算受限的试验，但不自动支持扩大生产或无限续研。若平台收益不足以支持目标，评估其他变现模式；若整个知乎业务未来回报不值得投入，允许减少或停止。

## 总研究问题

**什么问题值得回答、什么内容能够获得分发、什么阅读能够产生收益、什么内容能够长期存活，以及我们怎么证明自己真的知道原因。**

当前阶段目标：

**比较扩大内容生产、优化现有内容资产、增加知乎变现渠道三种经营机会，再决定有限资源投向哪里。以未来增量净收益评价投入，不以内容质量、播放量、系统复杂度或训练效果代替经营结果。**

这里的“研究目标函数”是研究方向与判定标准，不是将五项合成一个总分，也不预设它们之间已经存在确定的因果关系。

## 五个研究问题

| 维度 | 核心问题 | 必须区分的边界 |
|---|---|---|
| Question Value | 什么问题值得回答？ | 回答机会的价值与最终流量、收益不是同一个结果；评价标准及投入代价需明确 |
| Distribution | 什么内容能够获得分发？ | 阅读不等于曝光；前置条件与后置互动分开，不能从最终互动率倒推原因 |
| Monetization | 什么阅读能够产生收益？ | 阅读与收益口径、归因窗口分别记录；盐粒/阅读不默认为稳定RPM |
| Persistence | 什么内容能够长期存活？ | 初始表现、低速尾流、再激活与长期持续分别观察；不预设必然单向流转 |
| Epistemology / Validation | 我们凭什么认为自己知道原因？ | 相关不等于因果；解释得通不等于能够区分赢家/输家、预测或接受反例 |

前四项研究知乎，第五项约束研究者及系统自身。第五项贯穿每个实验，不是前四项完成后才补做的一步。

每个后续实验应明确关联上述经营决策，并说明回答前四项中的哪一个或哪几个问题，接受第五项检验。机制研究需要区分因果与相关；有限、可逆的经营试验不要求先解释完整平台机制，但不得把试验行动当作已验证规则。若研究结果不会改变经营行动，不占用盈利项目的优先资源。本文件不自动重写历史实验。

## 三个循环与接口

- Production Loop：选题 → 推理 → 内容 → 发布。
- Economic Loop：分发 → 阅读 → 收益 → 长尾；各指标分轨观察，以上顺序不构成已验证因果链。
- Learning Loop：测量 → 假设 → 反例 → 验证 → 人工审核 → 限定推广；允许UNKNOWN、FAILED、INCONCLUSIVE和不推广。

**Evidence-Informed Decision 位于 Learning Loop 回到 Production Loop 的接口。**

它要求依据可用证据、证据局限与明确的不确定性决定如何配置回答机会；证据不足时，可以继续观察、有限探索、推迟判断或拒绝推广。探索不等于已验证规则，也不得绕过现有生产边界。

研究结论若要改变生产规则，仍须经过已有Validation、Human Review和Scoped Promotion Approval，批准绑定具体变更。研究目标获得用户确认，不等于任何候选机制获得生产资格。本研究目标不自动授权修改Topic Selection权重、Compiler、正文Prompt或ACTIVE变量。人工接受、范围明确的数据Finding可进入Production Reference参与人工选题；正式机制规则仍须Validation与限定Promotion。2026-10-09用户另行明确停用了Cluster独立+1，见选题协议；不将此决定伪称为新机制验证。

## 如何证明我们知道原因

任何准备影响生产的机制，都必须说明：

1. 目前观察到的是相关，还是已有足以支持因果的证据？
2. 有没有Loser对照，匹配条件和未控制差异是什么？
3. 找过哪些反例，什么结果会削弱或推翻该解释？
4. 时间顺序是否成立，原因是否确实先于结果？
5. Measurement的身份、发布时间、窗口、来源及收益归因可靠吗？
6. 换一批内容后，预先明确的预测是否还能成立？

无法回答的项目保持UNKNOWN；单个成功案例、事后特征解释、历史累计值和相似题材都不能替代验证。不是每个问题必须得出答案，也不是每次研究都必须产生规则。

机器负责不遗忘、不乱归因、找异常、积累证据；人负责费曼式澄清、定义问题、挑战解释和最终判断。自动化的目标是约束我们把未经验证的解释当成真相。
