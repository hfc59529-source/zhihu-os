# 内容架构总则

Status：ARCHITECTURE_ACCEPTED

Version：1.0

Last Updated：2026-08-05

## 0. 本文件是什么

本文件是知乎系统的**内容语义架构**，回答"一篇内容在语义上经历了哪几个阶段"，不是 Prompt、不是流程、不是模板、不是案例，也不是对 Compiler、执行协议、参数库的替代或简化。

本总则只定义层级（Layer），不定义对象（Object）。每层内部具体包含哪些对象，由各自的对象规范维护和冻结，本总则不负责、也不冻结这些对象。新增或调整对象时，只修改对应的对象规范，不需要改动本总则。

## 2. 四层内容语义架构

本文所称"四层"，仅指内容语义架构，与 [`知乎OS执行协议.md`](知乎OS执行协议.md) 的数据分层（事实层／内容变量层／行为结果层／收益结果层／规则升级层）及 [`知乎内容质量参数库_V2.md`](知乎内容质量参数库_V2.md) 的生产分层（变量库／参数库／Prompt／正文）属于不同维度，不互相替代，也不互相覆盖。

三者关系：

- 数据分层：内容发布后，数据在复盘时如何分级。
- 生产分层：正文生产时，职责如何在变量库、参数库、Prompt、正文之间分离。
- 内容语义架构（本总则）：一篇内容在语义上要经历哪几个阶段，才能构成一次有效的认知转换。

四层冻结如下：

```text
现实
↓
认知落差
↓
认知转换
↓
平台表达
```

新增知识默认归到四层之下，不新增第五层。

## 3. 每层统一格式

每层必须包含：定义、职责、输入、输出、约束、禁止事项。

### 第一层：现实

**定义**：世界真实发生了什么。

**职责**：只保存事实，不保存观点、解释、判断、推理、评论。

**输入**：普通人可代入的真实场景。

**输出**：事实描述。

**约束**：事实必须可验证或可被读者直接代入。

**禁止事项**：不得混入结论、评价、立场。

### 第二层：认知落差

**定义**：这件事为什么值得传播。

**职责**：识别落差类型（例如信息落差、认知落差、决策落差、成本落差——具体落差对象由对象规范定义，本层不冻结）。

**输入**：第一层的事实。

**输出**：一个主落差。

**约束**：一篇内容只锁定一个主落差。

**禁止事项**：不得同时并列多个主落差；不得越过第一层直接讨论表达。

### 第三层：认知转换

**定义**：读者读完后应该形成什么新的理解。

**职责**：说明原认知、目标认知、支撑证据、推理链条、决策更新（具体字段由对象规范定义，本层不冻结）。

**输入**：第二层锁定的主落差。

**输出**：一个认知转换。

**约束**：一篇内容只完成一次认知转换。

**禁止事项**：不得修改上层已锁定的事实和落差；不得在本层讨论表达形式。

### 第四层：平台表达

**定义**：如何把已经完成的认知转换表达出来。

**职责**：标题、开头、长度、节奏、分段、字幕、封面、评论入口、平台适配。

**输入**：第三层锁定的认知转换。

**输出**：最终平台内容。

**约束**：只负责表达，不负责思考。

**禁止事项**：不得重新推理；不得修改事实、认知落差或认知转换。

## 4. 核心原则

**原则一**：一篇内容，只完成一次认知转换。

**原则二**：意义只能由上层决定。下层不能修改上层——现实决定认知落差，认知落差决定认知转换，认知转换决定平台表达。

**原则三**：平台表达层不负责思考，只负责表达，不负责重新分析。

**原则四**：固定调用，按需扩展。运行时固定调用现实、认知落差、认知转换三层，其余按需调用。

**原则五**：每层只有一个主对象（一个主落差、一个认知转换、一个最终版本）——主对象的具体定义由对象规范维护，本总则只要求"唯一"，不冻结对象内容。

**原则六：架构不定义对象**。本总则只定义层级，不冻结层级内部的具体对象。对象的定义、增减由各自的对象规范负责，本文件不因为新增一个对象而需要修改。

## 6. 与知乎OS Compiler的概念关系

本节是概念关系，不是对象等价。以下描述的是"通常由哪个阶段承载"，不是"等于"。

```text
内容架构总则
↓
定义内容语义架构

知乎OS Compiler
↓
定义工程实现
```

两者职责不同，不构成竞争关系；字段定义仍分别由各自文件维护——语义层字段由本总则维护，工程层字段由 [`知乎OS Compiler V1.md`](知乎OS%20Compiler%20V1.md) 维护，本节不改变、不锁定 Compiler 的字段。

- 现实：通常由 Analyzer 输入阶段处理。
- 认知落差：通常由 Analyzer 输出阶段承载相关判断。
- 认知转换：通常通过 Slim IR 进行冻结。
- 平台表达：通常通过 Runtime Assembly 与 Writer 完成。

本总则不是新增一套 Compiler，而是 Compiler 的语义上游：先有语义架构，再有工程编译。Compiler 具体如何实现这四层的语义，由 Compiler 自己的文档决定，本总则不介入、不代管。

## 7. 知识归位原则

已推导出的知识（思维模型、决策成本、人物映射、传播技巧、模式、变量等），先归位到四层之下，不直接新增层级。归位方式：证据 → 抽取 → 归位 → 对象 → 架构审查。对象优先，层级最后。

## 8. 治理规则

新增知识的统一流程：

```text
证据
↓
抽取
↓
归位
↓
对象
↓
架构审查
```

原则：对象优先，层级最后。
