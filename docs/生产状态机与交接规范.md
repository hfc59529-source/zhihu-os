# 生产状态机与交接规范

状态：ACTIVE
日期：2026-08-01

## 核心规则

任何角色完成本阶段后，只能更新状态并交接给下一责任角色，不能替下一角色继续决策。

状态只有在该阶段的必要输出和校验证据全部存在时，才能向下流转。

## Codex 采集与维护边界

Codex 在单篇生产前只负责选题采集与入库，到形成可供生产的选题包为止。Production Card、正文、QA、审核、修正和发布均由 Claude、GPT / 人工或用户接管。

Codex 在系统层负责维护参数库、知识库、样本库和参数调用日志。系统维护只能在 GPT / 人工确认系统问题后执行，不能混入单篇正文生产。

Codex 禁止生成 Production Card、提炼核心观点、设计文章结构、安排段落、生成正文或修正文案。

## Codex 正文禁写边界

Codex 禁止直接创建、改写、润色或替换以下正文类文件的正文内容：

- `Draft-v1.md`
- `Article-v*.md`
- `Article-Patched-v*.md`
- `Article-Final.md`
- `Release-v*.md` 中的正文段落

Codex 不进入正文审核与 Patch。若后续生产角色发现正文问题，由 Claude / 写作角色执行正文修正。

Codex 允许编辑的文件范围：

- `data/Topic_Pool.md`
- `data/topic_candidates/YYYY-MM-DD/TOPIC-YYYYMMDD-NNN.md`
- `data/parameter_call_log.md`
- 参数库、知识库、样本库中经确认需要维护的记录

`Release-v*.md` 不属于 Codex 当前单篇职责。

## 无问题链路

```text
READY_FOR_AUDIT
↓
AUDIT_PASS
↓
READY_FOR_USER_REVIEW
↓ USER_APPROVED
↓
RELEASE_READY
↓
PUBLISHED
↓
DATA_RECORDED
```

即使审计是 Clean Pass，也不能从 AUDIT_PASS 直接跳到 RELEASE_READY。必须先进入用户验收，由用户明确 `USER_APPROVED` 后才能进入 Release。

## 有问题链路

```text
READY_FOR_AUDIT
↓
AUDIT_ISSUE
↓
READY_FOR_PATCH
↓
PATCH_COMPLETED
↓
PATCH_VALIDATED
↓
READY_FOR_USER_REVIEW
↓ USER_APPROVED
↓
RELEASE_READY
```

## 用户拒绝返回路径

```text
READY_FOR_USER_REVIEW
↓ USER_REJECTED
Decision（根据用户指出的问题裁决）
↓
READY_FOR_PATCH
↓
PATCH_COMPLETED
↓
GPT / 人工确认
↓
PATCH_VALIDATED
↓
READY_FOR_USER_REVIEW
```

用户拒绝不是 Codex 修改正文的授权。用户指出的问题由 GPT / 人工裁决是否需要修复；正文修复仍由 Claude / 写作角色执行。

## 修改后确认与发布入口

Audit PASS / Issue = 0 后直接进入 `READY_FOR_USER_REVIEW`，不空跑 Decision，不执行修改后确认。

只有发生 Patch 后，才进入 `PATCH_VALIDATED`，由 GPT / 人工确认修改有效；通过后进入 `READY_FOR_USER_REVIEW`。

只有用户明确 `USER_APPROVED` 后，后续生产角色才能生成或确认 `Release-v1.md`，并将状态更新为 `RELEASE_READY`。

`RELEASE_READY` 是进入 `data/Publish_Queue.md` 的唯一生产状态入口；已存在 `Release-v1.md` 不能单独作为入队依据。

## 用户验收包

进入 `READY_FOR_USER_REVIEW` 时，必须生成或展示用户验收包。验收包不是正文修订文件，不得改写正文，只负责把用户验收所需上下文放在同一处。

用户验收包必须包含：

- Production ID。
- 原知乎问题。
- 真实知乎问题链接。
- 当前正文版本和来源文件，例如 `Draft-v1.md` 或 `Article-Patched-v1.md`。
- 当前状态，例如 `READY_FOR_USER_REVIEW`。
- 完整正文内容。

正文文件（`Draft-v1.md` / `Article-Patched-v1.md`）可以保持纯正文，便于复制到知乎；但交给用户验收时，不得只展示无头正文。

未获得 `USER_APPROVED` 前，不得把 `Release-v1.md` 当作用户验收包或正式发布稿使用。若历史流程已经生成 `Release-v1.md`，只能作为历史参考，不得作为当前入队依据。

## GPT / 人工审核清单

GPT / 人工审核固定使用两张清单，不得每篇重新定义审核内容。

参数审核：

- [ ] 是否回应原问题
- [ ] ACTIVE 是否正确
- [ ] 核心判断是否正确
- [ ] 参数是否调用正确
- [ ] 参数是否遗漏
- [ ] 参数是否冲突

正文审核：

- [ ] 阅读体验
- [ ] 推进节奏
- [ ] 场景
- [ ] 表达自然
- [ ] 重复
- [ ] 收尾

最终结论只能选择：

- PASS
- 正文问题
- 系统问题
