# 单篇复盘执行协议

状态：ACTIVE
日期：2026-08-04

## 用途

本协议用于把已发布文章的结果数据稳定挂回生产链路。它只回答单篇文章的运行事实、初步归因和下一步动作，不直接修改参数库、Prompt 或生产协议。

## 执行原则

1. 先建映射，再做归因。
2. 没有 `Production ID ↔ article_id` 映射时，只能记录 Trace 状态，不能判断变量有效性。
3. 单篇低表现不自动生成 Observation。
4. 只有重复出现或与系统预期明确冲突的问题，才进入 `data/Milestone_Observations.md`。
5. 参数是否生效以 GPT / 人工确认和可验证材料为准，不以 Claude 自报为准。

## 必填字段

| 分类 | 字段 |
|---|---|
| 身份 | Production ID、article_id、问题标题、问题链接、回答链接 |
| 时间 | 发布时间、采集时间、数据窗口 |
| 结果 | 阅读、赞同、评论、收藏、喜欢、收益、千阅读收益 |
| 生产 | 题型、ACTIVE 结构、主变量、首屏类型、核心机制 |
| 执行 | Claude 声称调用、GPT / 人工确认生效、遗漏参数、误用参数、冲突参数 |
| 归因 | 选题层、Question Parsing、核心判断、结构调用、表达、平台折叠或分发、数据窗口 |
| 动作 | 不处理、继续观察、进入单变量实验、建立 Observation、进入参数治理 |

## 数据窗口

标准窗口固定为：

| 窗口 | 说明 |
|---|---|
| T0 | 发布后 0-1 小时初始记录 |
| T24 | 发布后 24 小时 |
| T72 | 发布后 72 小时 |
| T7D | 发布后 7 天 |
| REVIEW_DAY | 当前复盘日补录 |

历史截图、旧抓取和无法确认发布时间的记录统一标记为 `HISTORICAL_BACKFILL` 或 `REVIEW_DAY`，不得直接与标准窗口混比。

## 最小执行流

```text
Production ID
↕
article_id
↓
发布结果
↓
参数触发与实际实现
↓
审核归因
↓
是否形成 Observation
```

## 输出位置

| 输出 | 文件 |
|---|---|
| Production ID 与 article_id 映射 | `data/production_article_map.csv` |
| 文章互动数据与收益数据主快照 | `data/review_data_snapshots.csv` |
| 参数触发、实际实现和结果 | `data/parameter_call_log.md` |
| 全量平台结果资产 | `data/l0_content_assets.csv` |
| 重复问题或系统冲突 | `data/Milestone_Observations.md` |

## 收益采集口径

日常复盘只维护一张主快照表：`data/review_data_snapshots.csv`。

互动数据来自知乎创作中心内容管理页，收益数据来自收益分析页。两者不要求同一入口采集，但必须在同一行保留各自来源：

| 字段 | 说明 |
|---|---|
| interaction_source | 阅读、赞同、评论、收藏、喜欢的来源入口 |
| earnings | 收益数值；未采集写 `UNKNOWN` |
| earnings_source | 收益来源入口；未采集写 `未采集` |
| earnings_collected_at | 收益采集时间 |
| earnings_window | 收益统计窗口 |
| earnings_match_status | `MATCH_BY_ARTICLE_ID` / `MATCH_BY_TITLE_DATE` / `UNMATCHED` / `NOT_COLLECTED` |

若收益页无法提供 article_id，只能按标题、发布时间和内容类型弱匹配，并将 `earnings_match_status` 标为 `MATCH_BY_TITLE_DATE`。
