## 概述

Consistency Engine 是**最终验收层**，检查：
1. 收益目标是否清晰
2. 行为目标是否与收益目标对齐
3. 所有维度是否同时达标
4. 是否真的能转化为收益

组成：
1. **硬规则检查**（机械化脚本）
2. **AI 语义审核**（结构化人工或 AI 判断）
3. **固定输出格式**

---

## 第一层：硬规则检查

由脚本执行。

### 检查项

| 检查项 | 硬规则 | PASS 标准 |
|------|------|---------|
| Monetization Goal 唯一性 | 必须 | 且仅有一个被勾选 |
| Monetization Goal 字段完整 | 必须 | 收益链路、目标用户都已填写 |
| Behavior Goal 与 Revenue Goal 适配 | 必须 | 检查是否是合理的对应关系 |
| Behavior Goal 唯一性 | 必须 | 主目标只有一个 |
| Behavior Goal 字段完整 | 必须 | 4 个字段都已填写 |
| 禁止牺牲项标记 | 必须 | 至少标记 1 项 |
| 基础维度记录 | 必须 | 4 大基础维度都有检查记录 |
| 未处理的 FAIL | 禁止 | 不能有孤立的失败记录 |

## 第二层：AI 语义审核

由 Claude 或人工审核员执行。

### 审核清单（按顺序）

#### 1. 收益目标合理性检查

**问题**：这篇文章的收益目标定位是否合理？是否匹配题目和作者能力？

**审核方式**：
- 读取 Card 中的"Monetization Goal"
- 读取"收益链路"和"目标用户"
- 判断这条链路是否逻辑清晰、可执行

**PASS 标准**：
- 收益目标与题目内容匹配
- 收益链路可信且完整（用户行为 → 最终收益）
- 目标用户明确可识别
- 作者的能力/资源足以支撑这个收益目标

**FAIL 例子**：
- 一个新作者选"好物带货"但没有任何商业资源
- 选"咨询转化"但从未展示过专业能力
- 收益链路写得很模糊，无法评估可行性

**输出**：
```
Revenue Goal Clarity：PASS / FAIL
Goal-Topic Alignment：匹配/部分匹配/不匹配
Feasibility：可行/可疑/不可行
```

---

#### 2. 行为目标对齐检查

**问题**：Primary Behavior Goal 是否真的能帮助实现 Monetization Goal？

**审核方式**：
- 查表对照：这个 Behavior Goal 对该 Revenue Goal 的转化是否有效
- 检查中间链条是否完整（行为 → 利益）

**PASS 标准**：
- Behavior Goal 是实现 Revenue Goal 的必要步骤
- 用户产生这个行为后，真的更可能转化为收益
- 没有更好的替代 Goal

**FAIL 例子**：

```
收益目标：好物带货
行为目标：评论
→ FAIL：评论不会导致购买，应该是"点击链接"
```

```
收益目标：账号积累
行为目标：转发
→ FAIL：转发短期有好处，但长期粘性不如"关注"
```

**输出**：
```
Behavior-Revenue Alignment：完全对齐 / 部分对齐 / 不对齐
Better Goal Available：否 / 是（推荐：___）
```

---

#### 3. 机制真实性检查

**问题**：行为触发机制是否真正进入了正文？是否能真的促成该行为？

**审核方式**：
- 读取"行为触发机制"定义
- 在正文中搜索该机制是否出现
- 判断强度是否足以促成行为

**PASS 标准**：
- 触发机制在正文中明确存在
- 形式符合该 Goal 的特征
- 强度足够（不是隐性的、微弱的）

**FAIL 例子**：

```
收益目标：咨询转化
行为目标：关注
触发机制：展示作者专业差异
检查：正文中有提到经验，但没有具体案例，没有展示专业超越其他答案的地方
→ FAIL：触发机制不足
```

**输出**：
```
Mechanism Present：有/部分/无
Mechanism Strength：强/中/弱
Position Match：在指定位置/在其他位置/不存在
```

---

#### 4. 收益链路可执行性检查

**问题**：从用户产生该行为，到最终收益转化，中间没有断层吗？

**审核方式**：
- 检查正文是否完成了"收益链路"中描述的每一步
- 特别注意链路的最后一步（实际转化）

**PASS 标准**：
- 如果 Goal 是"点击"，有清晰的点击入口
- 如果 Goal 是"购买"，消除了购买顾虑
- 如果 Goal 是"关注"，提示或暗示了后续价值

**FAIL 例子**：

```
收益目标：好物带货
行为目标：点击链接
链路：发现需求 → 认同产品解决 → 信任质量 → 点击购买
检查：正文只讲了需求和产品，没有消除"为什么要现在买"的顾虑，没有清晰的链接
→ FAIL：链路断层在最后一步
```

**输出**：
```
Revenue Conversion Chain：完整 / 部分断层 / 严重断层
Broken Links：{列表，如"消除顾虑缺失"}
```

---

#### 5. 维度冲突检查

**问题**：为了达成 Revenue Goal，是否损害了禁止牺牲的维度？各维度是否互相支持？

**审核方式**：
- 检查"禁止牺牲项"在正文中的体现
- 检查是否为了强化某个参数而削弱了基础维度

**PASS 标准**：
- 所有禁止牺牲的维度都有清晰体现
- 维度之间相互支持，不互相削弱
- 基础维度（问题回应、推理、阅读、可信度）都达标

**FAIL 例子**：

```
收益目标：阅读收益
禁止牺牲项：推理完整、可信度
检查：为了提升首屏留存，全是情绪渲染，没有因果链
→ FAIL：为了阅读留存牺牲了推理完整
```

**输出**：
```
Basic Dimensions PASS：是 / 否
Sacrificed Dimensions：{列表}
Dimension Conflict：无 / 轻微 / 严重
```

---

#### 6. 目标实现质量检查

**问题**：正文是否真的能导致目标行为的发生？强度如何？

**审核方式**：
- 基于行为目标的特征，判断正文的说服力

| 行为目标 | 检查维度 |
|---------|--------|
| 点赞 | 共鸣是否足够强？立场确认是否明确？ |
| 收藏 | 框架是否明确？是否真的值得收藏？ |
| 评论 | 是否留下了值得讨论的点？开放性足够？ |
| 转发 | 观点够鲜明吗？能代表分享者吗？ |
| 关注 | 持续价值预期足够强吗？ |
| 点击 | 购买理由充分吗？ |
| 咨询 | 专业差异明显吗？信任足够吗？ |
| 购买 | 顾虑消除了吗？购买理由强吗？ |

**PASS 标准**：
- 强度达到"中"以上（不能是微弱的可能性）

**输出**：
```
Goal Achievement Strength：强 / 中 / 弱 / 无
Probability of Goal Behavior：高 / 中 / 低
```

---

#### 7. 失败段落定位（若有失败）

**问题**：具体是哪一段出现问题？是内容问题还是表达问题？

**输出格式**：

```
Failed Segments：段落 2、段落 4

段落 2 问题：
  类型：机制缺失
  描述：应该展示的"专业差异"没有出现
  改进：补充 1 个竞品对比

段落 4 问题：
  类型：强度不足
  描述：购买顾虑消除不彻底，仍有"质量靠谱"的疑问
  改进：补充一个用户复购案例或满意度反馈
```
