# 知乎内容质量参数库 V2

Status：ACTIVE

对象类型：Parameter（参数）。与 `production_variable_library.md`（内容变量、认知机制、结构与传播变量领域）共享同一套 Parameter Schema 和生命周期，但保持独立文件——两库管理不同参数域（本库管理质量诊断、表达质量、阅读体验、执行规则），暂不物理合并。是否存在重复 Parameter ID 或权威冲突，留待后续专项检查后再判断是否合并。

## 目标

建立知乎内容质量的唯一参数标准。

后续所有正文优化，必须先进入参数库，经样本验证后，才可能被 Production Card 在具体生产中触发并激活。

本库只管理质量参数，不直接生成正文，不替代变量库，不改写正文生产流程。

本库新增 `QT-QI｜问题理解系统` 作为正文生产的上游识别域。QT-QI 不替代变量库，不替代 PD / RR / RE / BT，不直接生成正文；它负责把用户问题转化为可触发、可禁止、可验证的路由条件。

## 总原则

优化路径固定，且必须先经过 Observation 才能形成参数草案（不得由"发现问题"直接跳到"修改参数"）：

```text
Observation（写入 data/Milestone_Observations.md，记录问题、来源、验证过程）
↓
Parameter DISCOVERED（本库建档）
↓
CANDIDATE（满足最低证据门槛）
↓
REVIEW（进入评审）
↓
ACTIVE（评审通过，具备触发资格）
```

未到 `ACTIVE`，不得同步 Prompt、Production Card 默认触发列表或 QA 协议。

参数由 Production Card 在具体生产中触发并激活；只有确属 Executor Boundary（执行边界）的稳定规则才允许进入 Prompt——Prompt 不得成为第二参数库（见 [系统治理原则.md](系统治理原则.md) 原则六：单一事实来源）。

禁止未经参数库验证，直接修改 Prompt。

禁止新增大量横向参数，优先纵向深挖已有参数。

## 固定层级

```text
L1｜质量维度（Quality Dimension）
↓
L2｜质量参数（Quality Parameter）
↓
L3｜执行规则（Execution Rule）
↓
L4｜底层机制（Underlying Mechanism）
```

## 每层职责

### L1｜质量维度

回答：

内容质量由哪些维度组成？

L1 用来做质量归因，不直接进入 Prompt。

### L2｜质量参数

回答：

这个维度由哪些可观察、可优化的参数组成？

L2 用来定位问题类型，不能写成泛泛的审美判断。

### L3｜执行规则

回答：

AI 如何执行？

L3 必须转化成 Prompt 可以直接执行的规则。

规则必须具体、可检查、可复盘。

### L4｜底层机制

回答：

为什么这个规则成立？

每条规则至少拆解三个层面：

1. 心理机制：为什么符合人的阅读规律。
2. 内容机制：为什么提升内容质量。
3. 平台机制：为什么符合知乎推荐逻辑。

## 知乎质量分假设

知乎内容质量不是单一“深度”决定，而是多维度共同决定。

当前假设：

## L1-L2 参数目录

### 0. QT-QI｜问题理解系统

QT-QI 不是正文质量参数，而是所有内容生成模块的上游入口。

它回答：

```text
这个问题是什么类型？
用户为什么问？
问题为什么会形成？
应该触发哪些生产参数？
AI必须怎么执行？
最后如何验证判断是否有效？
```

固定层级：

```text
L0｜问题分类 Question Taxonomy
↓
L1｜用户问题解析 Question Intent
↓
L2｜问题形成机制 Formation Mechanism
↓
L3｜路由参数 Routing Parameter
↓
L4｜AI执行规则 Execution Rule
↓
L5｜验证指标 Validation
```

#### QT-00｜问题分类

作用：判断问题本质属于哪一种问题类型，决定答案基本形态。

可选类型：

- 事实型：需要确认事实、时间、数据、定义。
- 解释型：需要解释为什么发生。
- 判断型：需要判断对错、优劣、合理性。
- 预测型：需要判断未来趋势和概率。
- 建议型：需要给行动方向。
- 决策型：需要比较方案、权衡风险和收益。
- 情绪型：需要承接感受和降低情绪。
- 价值观型：需要处理立场、意义和价值排序。
- 经验型：需要真实经历、可代入场景和避坑。
- 机制型：需要组织、制度、利益、权力、成本结构推导。

执行规则：

1. 每题必须选择 1 个主类型。
2. 允许选择 1 个副类型，但不得超过 1 个。
3. 主类型决定正文结构和答案形式。
4. 副类型只影响首屏、情绪承接或结尾策略。

#### QT-00.1｜题型价值优先级

作用：防止所有题目都被推导深度、框架增量和认知升级带成解释文。

执行规则：

1. 题型决定内容价值的主要来源，质量参数必须服务用户真实问题。
2. 解释型：主要价值来自机制解释、因果推导和认知增量。
3. 建议型 / 解决题：主要价值来自动作有效性、场景覆盖、话术可用性和执行边界。
4. 决策型：主要价值来自选项比较、取舍条件、风险收益和停止标准。
5. 表达型：主要价值来自可直接使用的话术、语气分寸和关系边界。

建议型 / 解决题硬约束：

1. 机制解释不超过正文 30%。
2. 具体场景、动作、话术和升级条件不少于正文 60%。
3. 认知升级只能在结尾完成，不得反客为主。
4. 框架只作为快速判断器，不得替代场景化方案。
5. 每个建议必须回答：怎么说、怎么做、保护什么边界、对方不配合时怎么办。

解决题正文生成协议：

1. 禁止直接进入解决方案。
2. 必须先识别用户隐藏约束，回答用户为什么“不敢这样办”。
3. 必须用跟随式追问完成“现象→机制→规律→迁移”的底层逻辑推进，让读者知道为什么必须这样做。
4. 必须覆盖 3—5 个高频真实场景。
5. 每个重点场景至少包含一个动作或一句可直接使用的话术。
6. 必须说明动作适用边界。
7. 必须提供对方不配合时的升级方案。
8. 机制必须带用户抵达方案，不得写成培训理论。

解决题防误导规则：

1. 记录不等于自动免责，只能证明过程、降低被简单归责的风险。
2. 交回决策不等于放弃专业提醒，必须说明已知风险、代价和不可逆后果。
3. 自保不等于绕过汇报链或公开对抗，升级必须在正常汇报链条内完成。

#### QI-04.1｜用户隐藏约束

作用：识别用户表面问题背后的限制条件。很多高质量回答真正解决的不是问题本身，而是用户“不能这样办”的现实约束。

输出要求：

1. 识别用户不能做什么。
2. 识别用户害怕失去什么。
3. 识别用户不能承受什么代价。
4. 将隐藏约束写入 Production Card 的 `问题理解触发`。
5. 正文必须先拆隐藏约束，再进入底层逻辑和方案。

常见隐藏约束：

- 不能得罪领导。
- 不能失去工作。
- 不能影响晋升。
- 不能增加太多工作量。
- 不能显得自己能力差。
- 不能破坏关系。
- 不能承担法律、职业或声誉风险。

验证指标：

- 是否回答“用户为什么不能直接照建议做”。
- 是否区分表面问题、真正问题和用户约束。
- 方案是否同时解决问题和约束。

#### QI-01｜提问动机

作用：判断用户为什么此刻提出这个问题。

形成机制：

- 新闻事件触发
- 个人经历触发
- 身边案例触发
- 长期困惑触发
- 搜索需求触发
- 情绪宣泄触发
- 决策需求触发
- 好奇心触发

路由规则：

- 新闻事件触发 + 求解释：首屏优先反常识或异常点。
- 个人经历触发 + 情绪强：先共情，再解释。
- 决策需求触发：优先触发判断标准、方案比较和 BT-01。

#### QI-02｜真实问题

作用：识别用户表层问题背后真正想获得的答案。

形成机制：

- 求解释
- 求判断
- 求建议
- 求验证
- 求安慰
- 求站队
- 求经验
- 求框架

路由规则：

- 求解释：触发组织视角、机制推导、PD-03、PD-08。
- 求判断：触发判断标准、边界条件、认知升级。
- 求建议：触发决策模型、方案比较、BT-01。
- 求安慰：优先 RE 情绪承接，禁止直接反驳。
- 求框架：强化收藏驱动力和可迁移性。

#### QI-03｜当前认知

作用：判断用户现在倾向于怎样解释问题。

形成机制：

- 道德解释
- 能力解释
- 运气解释
- 制度解释
- 人性解释
- 阶层解释
- 信息差解释
- 利益解释

路由规则：

- 道德解释：触发认知校正、组织机制、利益结构，禁止人格审判。
- 能力解释：补充资源、机会、评价权和路径依赖。
- 运气解释：补充结构变量和可控变量。
- 人性解释：触发 PD-07，但必须写成成本选择，不写成人性批判。

#### QI-04｜认知缺口

作用：识别用户缺少哪一段解释链。

可选缺口：

- 缺事实
- 缺因果
- 缺机制
- 缺利益结构
- 缺权力关系
- 缺判断标准
- 缺行动路径
- 缺边界条件

路由规则：

- 缺机制：必须 PD-03。
- 缺利益结构：必须 PD-04。
- 缺权力关系：必须 PD-05。
- 缺判断标准：必须 BT-01 或认知升级。

#### QI-05｜认知目标

作用：判断正文最终要把用户带到哪里。

可选目标：

- 知道事实
- 理解因果
- 看见组织机制
- 建立判断标准
- 降低情绪
- 形成行动选择
- 获得可复用框架
- 完成问题重构

执行规则：

- 认知目标为组织机制：必须 PD-03、PD-04、PD-08。
- 认知目标为判断标准：必须形成可收藏框架。
- 认知目标为降低情绪：禁止开头直接反驳用户。

#### QI-06｜阅读奖励

作用：判断用户读完后愿意继续读、收藏或评论的奖励来源。

可选奖励：

- 被理解
- 反常识
- 新解释
- 新框架
- 可迁移
- 安全感
- 决策感
- 情绪释放

执行规则：

- 新框架 / 可迁移：优先 BT-01。
- 被理解 / 情绪释放：优先 RE 情绪承接。
- 反常识 / 新解释：首屏必须给异常点。

#### QI-07｜情绪状态

作用：判断用户是否带着强情绪进入问题。

可选状态：

- 平静
- 困惑
- 焦虑
- 愤怒
- 委屈
- 失望
- 讽刺
- 求安慰

执行规则：

- IF 情绪状态 == 愤怒 THEN 禁止直接反驳用户。
- IF 情绪状态 == 委屈 THEN 首屏先承接处境，再解释结构。
- IF 情绪状态 == 焦虑 THEN 先降低不确定性，再给判断标准。

#### QI-08｜行为预期

作用：判断正文希望读者产生什么行为。

可选行为：

- 继续读
- 收藏
- 评论
- 转发
- 点赞
- 自我判断
- 做决策
- 避坑

执行规则：

- 行为预期为收藏：触发 BT-01，并输出可复用判断框架。
- 行为预期为评论：触发 BT-02，但必须设置争议边界。
- 行为预期为决策：结尾必须给边界条件和停止条件。

#### PD-01 现象识别

核心问题：文章到底在解释什么现象？

P3 执行节点：

- 表面现象：读者直接看到的行为、结果或冲突。
- 异常点：与常识、预期或表面解释不一致的地方。
- 问题边界：谁、在什么情境下、做了什么、产生什么结果、不讨论什么。
- 事实与判断分离：区分已发生现象、现象解释和价值判断。

P4 叶子节点：

- 行为
- 结果
- 冲突
- 常识偏差
- 预期偏差
- 主体边界
- 情境边界
- 讨论边界
- 事实
- 解释
- 判断

失败表现：

- 一上来就讲大道理。
- 偷换问题。
- 把少数情况说成普遍规律。
- 没解释现象，直接批判人物。

#### PD-02 因果识别

核心问题：是什么直接导致了这个现象？

P3 执行节点：

- 触发事件：最接近现象发生的外部事件。
- 直接原因：最接近结果的原因。
- 深层原因：让直接原因长期存在的原因。
- 结构原因：制度、资源、角色、权责和环境造成的原因。
- 必要条件：没有它，现象是否还会发生。
- 充分条件：有它，现象是否必然发生。
- 相关与因果：禁止把同时出现写成因果。

P4 叶子节点：

- 收入不匹配
- 管理冲突
- 晋升受阻
- 工作风险提高
- 替代机会增加
- 增长停滞
- 管理能力不足
- 权责不匹配
- 激励机制失效
- 内部流动不足
- 触发事件
- 直接原因
- 深层原因
- 结构原因

必须区分：

```text
触发事件
→ 直接原因
→ 深层原因
→ 结构原因
```

失败表现：

- 单因解释复杂问题。
- 把触发事件当根本原因。
- 用标签化解释代替因果链。
- 只有观点，没有因果链。

#### PD-03 机制推导

正式版定义：

从现象开始，持续追问“为什么”，直到得到可迁移的判断，而不是停留在解释层。

推导层级：

L1｜现象解释（What）

- 回答：发生了什么。
- 目的：纠正常见误解，建立正确问题。
- 要求：不下结论，不分析原因，只锁定真实现象。

L2｜直接机制（How）

- 回答：为什么会这样。
- 目的：解释行为背后的直接驱动力。
- 可触发：成本、收益、风险、权力、激励、信息、资源、利益。
- 要求：不能停留在人品评价。

L3｜底层规律（Why）

- 回答：为什么这种机制会长期稳定存在。
- 目的：找到能够跨案例成立的稳定规律。
- 要求：必须比 L2 更底层，禁止只是换一种说法。

L4｜迁移判断（Transfer）

- 回答：以后如何判断。
- 目的：让读者获得现实中的判断能力。
- 输出：判断标准、观察信号、决策依据、可迁移规律。
- 禁止：重复总结。

触发规则：

- 唯一主变量必须完整完成 L1 → L2 → L3 → L4。
- 核心辅助变量至少完成 L2。
- 普通辅助变量允许只解释，不得全部深挖。
- 正文只允许存在一条完整主推导链，禁止多个机制同时深入。

Production Card QA：

- 是否完成 L1-L4。
- 每层是否新增信息。
- 是否出现重复解释。
- 是否最终形成迁移判断。

任一失败，判定 PD-03 Fail。

### 阅读体验｜阅读节奏

【L1】
质量维度：阅读体验

【L2】
质量参数：阅读节奏

【定义】
正文中观点、场景、机制、例子和结论的交替推进方式。

【作用】
降低阅读疲劳，让读者在理解认知的同时持续看到具体画面。

【L3 执行规则】
1. 连续抽象分析不得超过 2 段。
2. 每个核心认知必须对应现实场景。
3. 每 300 字至少出现一次画面。
4. 长短句交替。
5. 禁止连续理论输出。
6. 禁止连续概念堆积。

【L4 底层机制】

① 心理机制
具体事件比抽象概念更容易理解和记忆，画面能降低读者的认知负荷。

② 内容机制
场景承接可以把观点落到经验层，避免正文变成连续判断和分析。

③ 平台机制
阅读节奏影响停留时长、完读率、收藏率和评论意愿。

【验证指标】
- 是否连续两段以上都是抽象分析。
- 是否每个核心观点都有场景承接。
- 是否存在超过 300 字的连续理论输出。
- 是否读者能复述至少一个具体画面。

【失败表现】
- 读者觉得“有道理但累”。
- 正文像分析报告，不像知乎回答。
- 完读率低，收藏弱，评论少。

【优化方向】
- 增加普通职场画面。
- 将连续解释拆成“观点 + 场景 + 推导”。
- 提高故事密度，但不得编造真实案例。

【评分】
1-5 分。

【验证状态】
实验

### RE-08｜AI痕迹控制（AIC）

【L1】
质量维度：阅读体验

【L2】
质量参数：AI痕迹控制

【定义】
正文避免呈现为模板化总结、并列罗列和概念说明，让读者感觉作者是在顺着一个具体问题分析，而不是 AI 在整理资料。

【作用】
把“感觉有 AI 味”转化为可执行、可检查、可复盘的阅读体验标准。

【L3 执行规则】
1. 禁止使用“第一、第二、第三”连续展开。
2. 禁止写“一共三个原因”“三个建议”“三个前提”等数量化并列框架。
3. 禁止使用“归根结底”“本质上”“真正的问题是”代替推导。
4. 禁止连续定义概念。
5. 禁止 PPT 式总结。
6. 禁止教材式结尾。
7. 正文应从具体场景进入，再顺着场景推出判断。
8. 一段只推进一个结论。
9. 前后段落必须形成推导关系，不做横向并列罗列。
10. 允许保留适度留白，不把所有结论都替读者说满。
11. 优先使用问题句、场景句和判断句推进，不用编号句组织正文。

示例：

```text
不要写：
员工会优先保护自己的排名，而不是帮助团队。

优先写：
如果帮助同事，会不会让他超过自己？

当员工开始认真计算这个问题的时候，团队协作其实已经结束了。
```

【L4 底层机制】

① 心理机制
读者对模板化表达很敏感。连续编号、固定总结句和抽象定义会让读者先判断“这是生成文本”，再决定是否继续相信内容。

② 内容机制
人的分析通常是从一个场景、一个异常点或一个具体感受开始，然后逐步追问。AI痕迹控制的核心不是“口语化”，而是让段落之间有自然推导。

③ 平台机制
知乎回答需要建立作者感和可信度。正文一旦像模板总结，评论意愿、停留时间和收藏意愿都会下降。

【验证指标】
- 全文“第一、第二、第三”是否超过 2 次。
- 全文“三个原因”是否超过 2 次。
- 全文“三个前提”是否超过 2 次。
- 全文“总结一下”是否超过 2 次。
- 是否出现“一共三个原因”“三个建议”等并列框架。
- 是否出现“归根结底”“本质上”“真正的问题是”。
- 是否连续两段以上都在定义概念。
- 结尾是否像教材收束或 PPT 总结。

超过阈值：
RE 失败。

终检要求：
AIC（AI Impression Control）评分目标 ≥ 90 分。

低于 90 分：
退回重写。

【失败表现】
- 正文像 AI 在总结资料。
- 段落之间是并列清单，不是推导。
- 开头连续定义概念。
- 结尾用空泛总结替代认知落点。
- 读者能明显感觉到模板味。

【优化方向】
- 从会议、汇报、加班、晋升、绩效等具体场景进入。
- 把并列清单改成“现象 → 机制 → 代价 → 选择”的递进。
- 删除总结提示词，让结尾停在一个可迁移判断或未说满的场景上。
- 每段只处理一个判断，下一段接着解释它为什么成立。

【评分】
100 分制。

扣分规则：
- 出现“第一、第二、第三”连续展开：每次扣 15 分。
- 出现“一共三个原因”“三个建议”“三个前提”：每次扣 15 分。
- 出现“归根结底”“本质上”“真正的问题是”：每次扣 10 分。
- 连续定义概念：每处扣 10 分。
- 出现 PPT 式总结：每处扣 10 分。
- 出现教材式结尾：每处扣 15 分。
- 段落之间主要为并列罗列而非推导：扣 20 分。

低于 90 分不得通过 RE 终检。

【验证状态】
实验

### RE-09｜机械结构检测

【L1】
质量维度：阅读体验

【L2】
质量参数：机械结构检测

【定义】
检测正文是否沿用大模型常见的固定文章骨架，尤其是“问题、原因、建议、总结”或“观点、定义、解释、总结”的机械展开。

【作用】
控制 AI 味的结构来源，让正文从模板化输出转为自然推导。

【L3 执行规则】
1. 禁止使用以下结构：

```text
问题
↓
三个原因
↓
三个建议
↓
一句总结
```

2. 禁止使用以下结构：

```text
观点
↓
定义
↓
解释
↓
总结
```

3. 优先使用以下结构：

```text
观点
↓
冲突
↓
机制
↓
例子
↓
推导
↓
升级
```

4. 每个段落必须承接上一段的问题、冲突或未解释之处。
5. 禁止把文章拆成几个互不影响的并列模块。
6. 禁止用“建议清单”替代结尾认知升级。

【L4 底层机制】

① 心理机制
读者读到机械结构时，会提前预测后文走向。一旦预测过强，阅读就从“探索问题”变成“扫模板”，停留意愿下降。

② 内容机制
机械结构会让文章横向展开，推导链被切断。自然结构应当让每一段都在回应上一段留下的问题。

③ 平台机制
知乎高赞回答通常不是标准议论文提纲，而是围绕一个异常点持续追问，直到形成新的判断框架。

【验证指标】
- 是否出现“问题 → 三个原因 → 三个建议 → 一句总结”。
- 是否出现“观点 → 定义 → 解释 → 总结”。
- 是否存在连续三个以上并列模块。
- 是否用建议清单替代认知升级。
- 是否每段都能回答“它为什么接在上一段后面”。

【失败表现】
- 正文像作文提纲。
- 读者能提前猜到后文结构。
- 中段开始变成原因清单或建议清单。
- 结尾只是把前文重新概括一遍。

【优化方向】
- 用冲突替代定义。
- 用例子承接机制。
- 用追问推动下一段。
- 把建议清单改成一个可迁移判断。

【评分】
100 分制。

低于 90 分不得通过 RE 终检。

【验证状态】
实验

### RE-10｜真人观察感

【L1】
质量维度：阅读体验

【L2】
质量参数：真人观察感

【定义】
正文要像一个人在观察、回想和点破现象，而不是像系统在整理答案。它不追求口水化，而是让读者先产生“我也见过”“就是这样”的点头感。

【作用】
控制“太完整、太正确、太爱解释”的 AI 味，让正文从培训教材感转向真实知乎回答感。

【L3 执行规则】
1. 开头优先从场景、细节、情绪或反常识观察进入，不直接进入抽象定义。
2. 每 300 字至少出现一次具体观察。
3. 每 500 字至少出现一次现实场景、对话或可见动作。
4. 禁止连续使用“观点 → 解释 → 作用 → 总结”的段落模板。
5. 减少“本质、核心、真正、实际上、第一层、第二层、第三层、做了三件事、三个作用”等总结词和分层词。
6. 允许留白、跳跃和一句话成段。
7. 优先让读者点头，再让读者思考。
8. 少解释，多发现；能用一个现场细节说清的，不写四层机制。
9. 解决题可以有话术和动作，但不得写成培训手册。

示例：

```text
不要写：
这类任务的本质是决策权和执行风险错位。

优先写：
很多人都遇到过这种时刻。

领导一句：“这个你推进一下。”

当时觉得没什么。

一个月以后出了问题，他问：“你当时为什么这么理解？”
```

【L4 底层机制】

① 心理机制
读者不是先判断理论对不对，而是先判断“这个人是不是见过真实场面”。观察感能先建立信任。

② 内容机制
真实观察能替代过度解释。很多结论不需要证明到尽头，点破现象后，读者会自动补全推导。

③ 平台机制
知乎高阅读回答常见入口是异常点、生活细节、职场瞬间和一句“你注意没有”。过度完整会降低阅读快感。

【验证指标】
- 开头是否直接进入抽象定义。
- 是否连续 300 字以上没有具体观察。
- 是否连续 500 字以上没有现实场景、对话或动作。
- 是否连续出现“本质、核心、真正、实际上”等总结词。
- 是否出现“做了三件事”“三个作用”“第一层/第二层/第三层”等培训表达。
- 是否让读者感觉像培训教材或系统总结。

【失败表现】
- 内容正确，但读起来累。
- 每一段都在证明自己是对的。
- 全文都是结论，没有观察。
- 读者觉得像课件、汇报或 SOP。

【优化方向】
- 用一个职场瞬间替代抽象开头。
- 把“机制解释”改成“我后来发现一个细节”。
- 删除过密总结句。
- 允许短句和留白。
- 保留不说满的余味。

【评分】
100 分制。低于 90 分不得通过 RE 终检。

【验证状态】
实验

### 推导深度｜人性博弈

【L1】
质量维度：推导深度

【L2】
质量参数：人性博弈

【定义】
正文从机制解释继续下钻到双方利益保护、成本转移和选择权差异。

【作用】
让回答不只解释现象，而是揭示现象背后的行为逻辑。

【L3 执行规则】
1. 正文不得停留在现象描述或机制解释。
2. 必须说明双方各自在保护什么利益。
3. 必须说明谁拥有更多选择权、定价权、退出权或成本转移能力。
4. 必须说明双方行为分别符合什么趋利避害逻辑。
5. 禁止写成道德批判、人格评价或简单归因。

【L4 底层机制】

① 心理机制
读者更容易被“我为什么会这样选择”击中，而不是被单纯观点说服。

② 内容机制
机制解释回答“为什么发生”，人性博弈回答“为什么各方明知如此仍然这样做”。

③ 平台机制
知乎高收藏回答通常提供可迁移解释框架，而不是只回答单个问题。

【验证指标】
- 是否写出至少两方行为动机。
- 是否写出利益保护、成本转移或退出权差异。
- 是否完成问题重构。

【失败表现】
- 正文停在“现象解释正确，但不够狠”。
- 读者觉得顺滑但没记忆点。
- 结论只是总结，没有认知升级。

【优化方向】
- 继续拆解收益方和成本承担方。
- 增加选择权、退出权、定价权视角。
- 将单题答案升级为可迁移框架。

【评分】
1-5 分。

【验证状态】
实验

## 参数深挖规范

### 1. 纵向优先

禁止优先横向增加参数。

新问题必须先归入已有 L1 和 L2。

只有连续样本证明已有 L2 无法解释问题，才允许新增 L2。

### 2. Why 链路

每个参数必须不断回答：

```text
为什么？
为什么？
为什么？
```

至少拆到：

```text
规则
↓
机制
↓
心理
↓
平台
```

如果还能继续拆，则继续。

### 3. 执行化要求

L3 规则必须能直接进入 Prompt。

不能写：

- 更自然
- 更高级
- 更有网感
- 更有力量

必须写：

- 连续抽象分析不得超过 2 段
- 每个机制必须有现实场景承接
- 结尾必须回到唯一主变量
- 禁止新增一级机制

### 4. 验证化要求

每个参数必须有验证指标。

如果一个参数无法被检查、打分或复盘，不允许进入有效状态。

### 17. 信息价值

信息价值不是“文章看起来有内容”，而是读者读完以后，是否获得新的事实、新角度、新解释、新框架、新规律和可迁移判断能力。

本参数用于把“信息价值”从评价维度拆成 AI 可执行、可检测、可评分、可提升的生产参数。

```text
信息价值
→ 信息增量
→ 观点增量
→ 解释增量
→ 框架增量
→ 规律增量
→ 迁移价值
```

#### IV-01 信息增量

参数定义：

读者阅读后，获得阅读前不知道的新信息。核心不是信息数量，而是读者的认知状态是否发生变化。

一级判断：

- 事实增量：读者知道了以前不知道的事实、数据、案例、证据或观察。
- 认知增量：读者对原有概念、边界和抽象层级产生新的理解。
- 决策增量：读者获得新的判断标准、行动方案或默认策略。
- 预测增量：读者能提前判断趋势、风险和后续结果。

二级参数目录：

01 新数据  
02 新案例  
03 新事实  
04 新证据  
05 新观察  
06 新定义  
07 概念升级  
08 边界澄清  
09 判断标准  
10 行动建议  
11 默认策略  
12 趋势预测  
13 风险预警  
14 结果预测

##### IV-01-01 新数据

参数定义：提供新的统计数据、比例、金额、时间、排名、规模或变化幅度。

价值机制：降低质疑，提高可信度，让抽象判断获得可感知重量。

判断标准：

- 是否包含具体数字。
- 数字是否与正文主观点直接相关。
- 数据来源是否可信或可说明。
- 是否改变读者原有认知。
- 是否不是为了装饰而孤立出现。

触发时机：

- 观点之后，用数据补强。
- 结论之前，用数据垫高可信度。
- 反直觉判断之后，用数据降低抵触。

表达方式：

- “一个容易被忽略的数据是……”
- “真正让这个判断成立的，不是感觉，而是……”
- “如果只看表面，你会觉得……但数据里更明显的是……”

适用场景：商业、职场、组织、热点新闻、行业趋势、收入成本、平台机制。

典型案例：讨论裁员时，不只写“公司压力大”，而是补充现金流周期、营收变化、岗位成本或招聘冻结数据。

反例：堆数字但不解释数字与观点的关系。

评分规则：

- 0 分：无数据。
- 1 分：有数字，但与观点关系弱。
- 2 分：有关键数据，并支撑一个核心判断。
- 3 分：数据连续推动论证，让读者改变原有判断。

##### IV-01-02 新案例

参数定义：提供真实或高度真实化的企业、人物、历史、新闻、个人经历或实验案例。

价值机制：降低理解成本，让抽象机制变成读者能看见的具体场景。

判断标准：

- 是否有明确主体、情境、行动和结果。
- 是否能承载正文观点。
- 是否不是孤立故事。
- 是否能帮助读者理解机制。
- 是否具备真实性或现实可信感。

触发时机：

- 抽象解释之后，用案例落地。
- 首屏反常识之后，用案例让读者进入。
- 机制推导中段，用案例承接复杂逻辑。

表达方式：

- “你看很多公司会出现一个场景……”
- “比如一个业务骨干被提成主管以后……”
- “这类事在组织里通常不是这样发生的……”

适用场景：职场管理、创业经营、组织博弈、消费关系、教育成长。

典型案例类型：

- 企业案例
- 人物案例
- 历史案例
- 新闻案例
- 个人经历
- 实验案例

反例：案例很热闹，但无法支持正文判断。

评分规则：

- 0 分：无案例。
- 1 分：有案例，但只是举例说明。
- 2 分：案例能承载一个核心机制。
- 3 分：案例能让读者通过一个场景理解一类问题。

##### IV-01-03 新事实

参数定义：提供读者以前不知道、或没有意识到其重要性的客观事实。

价值机制：直接改变读者的信息底座，让后续观点有新的出发点。

判断标准：

- 是否提供新的事实信息。
- 是否区别于主观判断。
- 是否与题目核心问题有关。
- 是否能改变读者对现象的初始理解。
- 是否可以被经验、资料或常识交叉验证。

触发时机：

- 开头纠偏时。
- 解释机制前。
- 反驳常见答案时。

表达方式：

- “很多人不知道的是……”
- “这件事有一个前提经常被忽略……”
- “真正发生在后台的，不是……而是……”

适用场景：行业事实、组织事实、平台事实、心理事实、商业事实、制度事实。

典型案例：不是“公司因为亏钱才裁员”，而是“公司也会在利润尚可时裁掉未来风险更高、替代性更强或组织成本更高的岗位”。

反例：把个人猜测写成事实。

评分规则：

- 0 分：无新事实。
- 1 分：有事实，但读者可能早已知道。
- 2 分：事实能改变读者对问题的理解。
- 3 分：事实成为全文推导的关键起点。

##### IV-01-04 新证据

参数定义：提供能支撑正文判断的外部材料、真实记录、评论反馈、研究结论或实验结果。

价值机制：它不主要增加知识，而是增加可信度和可验证感。

判断标准：

- 是否有证据来源类型。
- 证据是否支撑正文核心判断。
- 证据是否比单纯观点更可信。
- 是否避免断章取义。
- 是否能被读者理解其证明关系。

触发时机：

- 强判断之后。
- 争议判断之前或之后。
- 文章需要建立可信度时。

表达方式：

- “能证明这一点的，不是态度，而是……”
- “类似现象在评论区经常出现……”
- “如果看真实聊天/访谈/报告，会发现……”

适用场景：热点新闻、行业分析、平台规则、心理研究、组织问题、消费决策。

典型证据类型：

- 官方报告
- 论文
- 采访
- 真实聊天
- 评论区
- 实际实验

反例：引用权威名词，但不说明它证明了什么。

评分规则：

- 0 分：无证据。
- 1 分：有证据名义，但支撑弱。
- 2 分：证据能支撑核心判断。
- 3 分：证据与观点、机制形成闭环。

##### IV-01-05 新观察

参数定义：提出来自日常生活、工作现场、管理现场、消费现场或关系现场的细节观察。

价值机制：知乎读者容易被“没人系统研究但大家天天经历”的观察击中。

判断标准：

- 是否来自具体生活或工作细节。
- 是否能让读者产生“确实如此”的识别感。
- 是否不是泛泛情绪。
- 是否能引出后续解释。
- 是否有场景、动作或微妙差异。

触发时机：

- 首屏制造代入时。
- 抽象解释前。
- 结尾提炼迁移判断前。

表达方式：

- “你有没有发现一个细节……”
- “真正微妙的是……”
- “很多人天天遇到，但很少把它说清楚……”

适用场景：工作细节、生活细节、管理细节、消费细节、关系细节。

典型案例：为什么领导开会总喜欢最后发言，不只是性格强势，而是在保留解释权和最终定义权。

反例：只有情绪吐槽，没有可观察细节。

评分规则：

- 0 分：无观察。
- 1 分：观察存在，但不够具体。
- 2 分：观察具体，并能引出解释。
- 3 分：观察精准到足以成为首屏钩子或核心论证入口。

##### IV-01-06 新定义

参数定义：重新定义一个常见概念，使读者获得更准确、更可传播、更少歧义的理解。

价值机制：改变概念入口，读者后续看同类问题时会换一套语言系统。

判断标准：

- 是否重新定义概念。
- 定义是否比原理解更准确。
- 是否减少歧义。
- 是否更容易传播。
- 是否能支撑后续推导。

触发时机：

- 首屏重构问题时。
- 常见误解之后。
- 文章进入框架前。

表达方式：

- “所谓 A，不是……而是……”
- “如果重新定义这件事，它其实是……”
- “你把 A 理解成 B，很多问题就能解释了。”

适用场景：努力、能力、忠诚、管理、裁员、晋升、工资、资源、选择权。

典型案例：努力不是投入时间，而是提高单位时间价值。

反例：换一个词，但没有提升解释能力。

评分规则：

- 0 分：无新定义。
- 1 分：有定义，但只是换说法。
- 2 分：定义更准确，并支撑正文判断。
- 3 分：定义能成为全文核心句，并具备传播性。

##### IV-01-07 概念升级

参数定义：把原本低层级、局部化的概念，提升为更高层级、更有解释力的概念。

价值机制：统一多个零散现象，提高解释能力和预测能力。

判断标准：

- 是否提高抽象层级。
- 是否能统一多个现象。
- 是否比原概念解释力更强。
- 是否能推导出更多结果。
- 是否避免空泛上纲。

触发时机：

- 多个案例或现象之后。
- 从个体问题转向组织问题时。
- 文章中段需要拔高认知时。

表达方式：

- “这已经不是 A 的问题，而是 B 的问题。”
- “把它放到更高一层看，它其实是……”
- “员工在这里不是一个人，而是组织资产/风险节点/资源接口。”

适用场景：员工到组织资产、工资到风险补偿、岗位到风险接口、客户到现金流入口。

典型案例：把“工资”升级为“组织对风险、替代性和产出稳定性的补偿”。

反例：强行套大词，导致原问题变空。

评分规则：

- 0 分：无概念升级。
- 1 分：有抽象词，但解释力弱。
- 2 分：概念升级能解释多个现象。
- 3 分：概念升级成为文章框架或迁移价值来源。

##### IV-01-08 边界澄清

参数定义：说明判断在什么条件下成立，什么条件下失效，适用于谁、哪个阶段和哪类场景。

价值机制：避免绝对化，提高可信度，也让读者知道如何正确迁移。

判断标准：

- 是否说明成立条件。
- 是否说明失效条件。
- 是否给出例外。
- 是否明确适用对象。
- 是否明确适用阶段。

触发时机：

- 强结论之后。
- 规律表达之后。
- 可能被误读或杠点明显时。

表达方式：

- “这不是说所有……都……”
- “它成立有一个前提……”
- “如果处在另一个阶段，结论会反过来。”

适用场景：组织阶段、行业周期、岗位层级、管理风格、商业模式、个人处境。

典型案例：不是所有领导都这样，而是当组织开始降本、权责收缩、风险上移时，这类行为会更明显。

反例：把局部经验写成普遍真理。

评分规则：

- 0 分：无边界。
- 1 分：有提醒，但不清楚。
- 2 分：边界明确，能减少误读。
- 3 分：边界、例外和适用对象完整，能支持规律沉淀。

##### IV-01-09 判断标准

参数定义：给读者提供判断一个人、一家公司、一种机会或一个选择的标准。

价值机制：把文章从“看懂”推进到“会判断”。

判断标准：

- 是否提出可观察指标。
- 是否说明指标优先级。
- 是否说明变量权重。
- 是否包含例外情况。
- 是否能帮助读者做选择。

触发时机：

- 解释机制之后。
- 进入建议之前。
- 结尾形成收藏价值时。

表达方式：

- “判断这类问题，不要先看……先看……”
- “至少看三个变量……”
- “真正重要的排序是……”

适用场景：老板值不值得跟、公司能不能待、岗位有没有前途、合作对象是否可靠。

典型案例：判断老板值不值得跟，不只看态度好不好，而看资源是否开放、责任是否匹配、承诺是否兑现。

反例：给建议但没有判断依据。

评分规则：

- 0 分：无判断标准。
- 1 分：有标准，但不可观察。
- 2 分：标准明确，可用于当前问题。
- 3 分：标准有优先级、权重和例外，可跨场景使用。

##### IV-01-10 行动建议

参数定义：给出读者可以执行、验证或避坑的行动方向。

价值机制：把认知收益转化为现实收益，提高收藏和复访价值。

判断标准：

- 是否能马上执行。
- 是否区分短期和长期。
- 是否包含避免踩坑。
- 是否包含风险控制。
- 是否有验证方法。

触发时机：

- 判断标准之后。
- 结尾收束前。
- 高情绪问题需要落地时。

表达方式：

- “最稳的做法不是……而是……”
- “你可以先做三件事……”
- “不要急着解释，先验证……”

适用场景：职场沟通、跳槽选择、晋升准备、创业决策、关系处理、消费决策。

典型案例：遇到不授权却要求结果的领导，先确认决策权、评价口径和试错边界，再决定是否投入长期承诺。

反例：喊口号式建议，例如“提升自己”“保持清醒”。

评分规则：

- 0 分：无建议。
- 1 分：建议笼统，难执行。
- 2 分：建议具体，可执行。
- 3 分：建议包含执行顺序、风险控制和验证方法。

##### IV-01-11 默认策略

参数定义：沉淀出读者以后遇到类似问题时可以自动触发的默认处理原则。

价值机制：把单篇内容变成长期决策习惯。

判断标准：

- 是否能压缩成一句默认原则。
- 是否适用于相邻问题。
- 是否能降低读者下次决策成本。
- 是否包含先后顺序。
- 是否不会误导到所有场景。

触发时机：

- 结尾。
- 框架总结后。
- 迁移价值输出时。

表达方式：

- “以后遇到这种情况，默认先……再……”
- “不要先问……先看……”
- “你的默认动作应该从解释，变成观察变量。”

适用场景：领导关系、合作判断、跳槽、谈判、资源交换、风险识别。

典型案例：以后遇见让你反复解释的领导，不要先解释，先观察利益关系、权责边界和评价标准。

反例：默认策略过度绝对，忽略边界。

评分规则：

- 0 分：无默认策略。
- 1 分：有原则，但难自动触发。
- 2 分：策略清晰，能用于相邻问题。
- 3 分：策略短、准、可迁移，读者容易记住并复用。

##### IV-01-12 趋势预测

参数定义：基于现有变量和机制，判断未来一段时间内某类现象会如何变化。

价值机制：让读者获得提前理解未来的优势。

判断标准：

- 是否说明预测对象。
- 是否说明预测依据。
- 是否解释未来变化机制。
- 是否提前预警。
- 是否避免无条件断言。

触发时机：

- 机制解释之后。
- 行业或组织周期判断中。
- 文章需要高级感和前瞻性时。

表达方式：

- “接下来更可能发生的不是……而是……”
- “只要这个变量不变，趋势就会继续……”
- “未来这类岗位/公司/关系会越来越……”

适用场景：行业变化、组织管理、平台生态、岗位价值、消费趋势、社会结构。

典型案例：当组织进入降本周期，管理会越来越重视可替代性、风险隔离和短期现金流。

反例：没有机制支撑的预测。

评分规则：

- 0 分：无预测。
- 1 分：有预测，但无依据。
- 2 分：预测有机制依据。
- 3 分：预测有变量、边界和可观察信号。

##### IV-01-13 风险预警

参数定义：指出某类风险出现前的信号、关键变量、验证条件和停止条件。

价值机制：让读者从事后理解变成事前识别。

判断标准：

- 是否提出前置信号。
- 是否说明关键变量。
- 是否给出验证条件。
- 是否给出停止条件。
- 是否能指导风险控制。

触发时机：

- 组织、职场、创业、关系题的中后段。
- 行动建议之前。
- 文章需要提高实用价值时。

表达方式：

- “出现这几个信号，就要警惕……”
- “真正危险的不是……而是……”
- “判断风险是否成形，看三个变量……”

适用场景：裁员、降薪、晋升受阻、公司现金流、合作破裂、客户流失。

典型案例：公司开始冻结招聘、压缩预算、提高汇报频率，同时强调人效，可能意味着风险开始向岗位传导。

反例：制造焦虑，但不给识别条件。

评分规则：

- 0 分：无风险预警。
- 1 分：有提醒，但信号模糊。
- 2 分：有明确信号和验证条件。
- 3 分：有前置信号、关键变量、验证条件和停止条件。

##### IV-01-14 结果预测

参数定义：说明如果当前变量和机制继续运行，未来会出现什么结果。

价值机制：让读者理解“不改变会怎样”，强化判断和行动动力。

判断标准：

- 是否基于当前机制推导。
- 是否说明时间或阶段。
- 是否指出具体结果。
- 是否说明变量改变后结果是否改变。
- 是否避免恐吓式断言。

触发时机：

- 文章结尾前。
- 行动建议之前。
- 机制链已经完成之后。

表达方式：

- “继续这样下去，最可能出现的不是……而是……”
- “半年以后，你看到的结果通常会是……”
- “如果这个变量不变，结局大概率不会变。”

适用场景：组织失灵、职业发展、管理风险、创业现金流、亲密关系、消费决策。

典型案例：如果公司只培养人、不升级回报机制和组织沉淀机制，结果不是员工更忠诚，而是优秀员工更快被市场重新定价。

反例：直接断言结局，不展示推导过程。

评分规则：

- 0 分：无结果预测。
- 1 分：有结果判断，但无推导。
- 2 分：结果来自机制推导。
- 3 分：结果预测有时间、边界、变量变化和行动含义。

##### IV-01 信息增量总评分

总分按 0-3 记录：

- 0 分：没有任何可识别信息增量。
- 1 分：命中 1-2 个二级参数，但对正文主线支撑弱。
- 2 分：命中 3-5 个二级参数，且至少包含事实增量或认知增量。
- 3 分：命中 6 个以上二级参数，且形成“事实/认知 → 决策 → 预测”的连续增量。

生产最低要求：

- 日常正文：至少命中 2 个二级参数。
- 热点新闻题：必须命中新数据、新事实、新证据或新观察中的至少 2 个。
- 高收藏目标正文：必须命中判断标准、行动建议或默认策略中的至少 1 个。
- 理论沉淀正文：必须命中边界澄清、趋势预测、风险预警或结果预测中的至少 2 个。

#### IV-02 观点增量

核心问题：文章是否提供新的解释角度，而不是只表达态度。

L2 判断参数：

- 新视角：是否换了观察位置。
- 反直觉：是否打破读者默认理解。
- 新评价标准：是否改变判断好坏、对错、值不值的标准。
- 新比较方式：是否建立新的对照关系。
- 新定义：是否重定义问题、角色或结果。

L3 可检测指标：

- 是否出现“真正原因不是……而是……”“表面上是……本质上是……”等重构句。
- 是否把道德评价改成结构评价、利益评价、风险评价或机制评价。
- 是否把单一主体问题改成多方博弈问题。
- 是否提出新的判断标准，例如能力、风险、忠诚、成本、成长。
- 是否建立新因果关系，例如“裁员不是降成本，而是重新分配风险”。

评分：

- 0 分：没有观点，只复述现象或站队。
- 1 分：有观点，但仍是常见结论。
- 2 分：有新的解释角度，并能支撑正文主线。
- 3 分：观点能重定义问题，让读者换一种方式理解整件事。

提升动作：

- 加入“不是 A，而是 B”的问题重构。
- 把人物评价改成机制评价。
- 增加一个反常识判断，并补足后续解释。
- 给出一套新的评价标准或比较对象。

#### IV-03 解释增量

核心问题：文章是否回答了为什么，以及为什么会持续发生。

L2 判断参数：

- 原因解释：是否回答直接原因。
- 机制解释：是否解释原因如何转化为结果。
- 利益机制：利益如何分配、转移或错配。
- 博弈机制：各方如何根据自己的风险和收益行动。
- 心理机制：恐惧、贪婪、安全感、面子、沉没成本如何被激活。
- 组织机制：权责、流程、评价、授权如何制造结果。
- 演化机制：问题为何会反复出现、逐渐放大或路径依赖。

L3 可检测指标：

- 是否回答“为什么是这样”。
- 是否回答“为什么是现在发生”。
- 是否回答“为什么别人看不到”。
- 是否回答“为什么会一直发生”。
- 是否出现机制链：条件 → 触发 → 传导 → 放大/缓冲 → 阈值 → 结果。
- 是否至少命中一种机制：利益、心理、组织、制度、经济、博弈、激励、演化。

评分：

- 0 分：只有结论，没有解释。
- 1 分：有直接原因，但没有机制过程。
- 2 分：有清晰机制，能解释现象发生。
- 3 分：机制能解释现象为何持续、扩散或重复发生。

提升动作：

- 补“为什么现在”。
- 补“中间过程如何发生”。
- 补一个机制类型，并写出传导路径。
- 把“因为人性/因为公司坏”改成利益、风险、权责、激励链条。

#### IV-04 框架增量

核心问题：文章是否给读者一套以后还能继续使用的分析工具。

L2 判断参数：

- 分类框架：是否把对象分成可判断的类型。
- 判断框架：是否给出判断维度。
- 决策框架：是否给出选择顺序或取舍流程。
- 变量框架：是否提取影响结果的关键变量。
- 分析流程：是否形成可复用的分析步骤。

L3 可检测指标：

- 是否出现并列变量列表，例如能力、风险、忠诚、成本、成长。
- 是否出现“判断这类问题，先看……再看……最后看……”。
- 是否出现分类：不是一种人，而是几类处境。
- 是否把单篇问题抽象成变量体系。
- 是否让读者能用同一框架分析相邻问题。

评分：

- 0 分：没有框架，只有单点观点。
- 1 分：有零散分类，但不能复用。
- 2 分：有清晰判断维度或分析步骤。
- 3 分：形成可迁移框架，读者以后遇到类似问题会自动触发。

提升动作：

- 把解释整理成 3-5 个变量。
- 给出“先看/再看/最后看”的判断顺序。
- 把经验判断改成分类体系。
- 将单一建议改成决策流程。

#### IV-05 规律增量

核心问题：文章是否提炼出有边界、有预测力、可被反驳的规律。

L2 判断参数：

- 候选规律：是否提出稳定发生的关系。
- 边界条件：是否说明规律在什么条件下成立。
- 例外条件：是否说明什么情况下不成立。
- 预测能力：是否能预测类似情境下的结果。
- 可证伪性：是否能说清什么证据会推翻这个判断。

L3 可检测指标：

- 是否出现“只要……就容易……”“当……时，通常会……”。
- 是否说明适用对象、场景、阶段和限制。
- 是否主动给出例外，而不是把结论绝对化。
- 是否能推出未来行为、组织反应或结果走向。
- 是否能被事实检验，而不是永远正确的空话。

评分：

- 0 分：没有规律，只有感受。
- 1 分：有类似规律的句子，但无边界。
- 2 分：有边界和例外，能解释一类现象。
- 3 分：具备预测能力和可证伪条件，可进入后续理论验证。

提升动作：

- 把观点改写成“条件 → 倾向 → 结果”。
- 补边界：谁、何时、什么情况下成立。
- 补例外：什么情况下不成立。
- 补预测：如果变量变化，结果会怎样变化。

#### IV-06 迁移价值

核心问题：读者能否把本文的认知带到别的问题里。

L2 判断参数：

- 跨问题：是否能用于分析相邻问题。
- 跨行业：是否能脱离单一行业使用。
- 跨岗位：是否能用于老板、员工、管理者、创业者等不同身份。
- 跨时间：是否能用于过去经验、当前选择和未来判断。
- 默认决策能力：是否能沉淀成读者下次自动触发的思维方式。

L3 可检测指标：

- 是否从当前问题上升到一类问题。
- 是否出现“以后你再看……就不要只看……而要看……”。
- 是否能迁移到裁员、晋升、创业、谈判、合作、管理等相邻场景。
- 是否给出跨身份视角：对老板意味着什么，对员工意味着什么。
- 是否形成一句可带走的判断句。

评分：

- 0 分：只能解释当前问题。
- 1 分：能迁移到一个相邻问题。
- 2 分：能跨多个问题或身份使用。
- 3 分：形成默认思维，读者以后会自动触发。

提升动作：

- 结尾加入“这套逻辑也适用于……”。
- 把当前问题抽象成一类问题。
- 加入跨身份解释。
- 提炼一句可复用判断句。

### 18. 认知奖励（CR｜Cognitive Reward）

状态：ACTIVE

证据数量：执行层修复项

正式版定义：

机制推导完成后，让读者获得新的判断能力，而不是只获得新的知识。

认知奖励不是推导深度。

推导深度解决：

```text
有没有解释清楚。
```

认知奖励解决：

```text
读者有没有持续觉得值得看。
```

边界：

- 不决定正文内容。
- 不替代 PD。
- 不替代 RE。
- 不替代 BT。
- 必须服务 Production Card 的 `认知奖励目标`。
- 不以金句、口号、鸡汤或情绪判断代替判断能力。

正式版类型：

- CR-01｜认知反转：推翻读者原来的解释，输出“原来不是这样”。
- CR-02｜机制发现：揭示别人没有解释清楚的稳定机制，输出“真正决定结果的是这个”。
- CR-03｜判断工具：给读者一个以后还能继续使用的判断标准，输出看什么、怎么判断、出现什么信号、怎么预测。
- CR-04｜信息增量：提供多数回答没有的新变量、新关系、新解释；不能为了新而新，必须真实成立。

触发规则：

- 每篇正文必须指定 1 个主CR。
- 辅助CR最多 1 个。
- 禁止四个全部触发。
- 禁止写泛化参数 `CR｜认知奖励`，必须写具体子参数。

QA 检查：

- 是否真正产生一个新的判断能力。
- 是否只是重复结论。
- 是否只是金句、鸡汤或口号。
- 是否为了制造认知奖励而虚构数据、案例或规律。

任一失败，判定 CR Fail。

历史说明：

本节下方旧 CR 子项保留为历史实验记录。若历史子项命名与正式版类型冲突，Production Card、正文 Prompt 和 QA 统一以本正式版为准。

升级条件：

- 连续 3 篇同向验证有效：CANDIDATE → REVIEW。
- 累计 10 篇同向验证有效：REVIEW → ACTIVE。

失效条件：

- 连续 5 篇验证无改善。
- 或收藏率、评论率、阅读完成度、停留表现、盐粒收益等核心指标下降。

触发原则：

每次只允许选择一个 CR 子参数作为唯一实验参数。

禁止写：

```text
唯一实验参数：
CR｜认知奖励
```

必须写：

```text
唯一实验参数：
CR-01｜认知反转
```

#### CR-01 认知反转

核心问题：文章是否能在每推进一层机制时，推翻或升级读者上一层理解。

L3 执行规则：

- 每推进一层机制，至少产生一次认知位移或反转。
- 反转不是故意制造金句，而是让解释从表层判断进入更底层机制。
- 反转链必须服务唯一主变量，不得新增正文外变量。

可检测指标：

- 认知反转次数最低 3 次。
- 推荐 4-6 次。
- 至少一次反转必须发生在正文中段，避免只有开头和结尾有认知奖励。

失败表现：

- 一开头说完核心观点，后文只是在重复解释。
- 每一层都只是补充细节，没有改变读者理解。
- 反转脱离主变量，变成新的观点分叉。

示例结构：

```text
第一层：领导不知道。
第二层：领导知道。
第三层：他不是知道，他是在计算。
第四层：他不是计算员工，他是在计算风险。
```

#### CR-02 段落信息增量

核心问题：每个自然段是否都新增了信息、判断、机制、概念或场景。

L3 执行规则：

- 每个自然段必须新增一个可识别的信息点。
- 连续解释同一件事不得超过 2 段。
- 如果同一判断需要展开，第二段必须进入原因、边界、例外、机制或读者处境。

可检测指标：

- 连续解释同一件事不得超过 2 段。
- 删除任一自然段，如果文章没有少一个新信息，则该段无效。
- 正文不得出现连续 3 段都在解释同一个 A 的情况。

失败表现：

- A 解释一遍后，连续多段换说法继续解释 A。
- 段落之间只有语气变化，没有信息推进。
- 用抽象判断填充篇幅。

#### CR-03 概念产出

核心问题：正文是否产出可以被读者记住、收藏和复用的新概念。

L3 执行规则：

- 正文至少出现 2 个新概念。
- 新概念必须可命名、可复用、可迁移。
- 概念必须从正文机制中自然长出来，不得为了造词而造词。

可检测指标：

- 新概念最低 2 个。
- 至少 1 个概念必须能用于相邻问题。
- 概念出现后，正文必须给出一句解释或使用场景。

合格示例：

- 风险账户
- 交付信用
- 组织容忍窗口
- 可替代成本
- 管理风险信号

失败表现：

- 只有普通词组，没有新的判断框架。
- 概念无法脱离当前题目复用。
- 概念与正文机制无关。

#### CR-04 阅读奖励间隔

核心问题：读者是否会在过长篇幅内没有获得新认知，从而退出阅读。

L3 执行规则：

- 正文必须控制认知奖励间隔。
- 每个阅读奖励可以是新认知、新判断、新概念、新框架、新反转或新的身份代入。
- 阅读奖励必须真实推进内容，不能用口号或情绪句替代。

可检测指标：

- 最长阅读奖励间隔不得超过 500 字。
- 推荐每 300-500 字出现一次明确认知奖励。
- 正文完成后必须记录最长奖励间隔估算值。

失败表现：

- 连续大段机制说明，没有新的理解变化。
- 中段出现 600 字以上的解释平原。
- 只有开头有反常识，后文没有继续奖励。

#### CR-05 身份回扣

核心问题：文章解释组织、平台、领导或机制后，是否及时回到读者处境。

L3 执行规则：

- 每完成一段组织、领导、平台或机制解释，应回扣读者身份。
- 回扣不是安慰，而是告诉读者“这对你意味着什么”。
- 不得连续 800 字只讲组织、领导或平台，不回到读者。

可检测指标：

- 身份回扣最低 2 次。
- 至少 1 次应出现在正文中段。
- 可使用“如果你是……”“你会发现……”“这对普通人真正意味着……”等结构。

失败表现：

- 全文都在讲领导、组织、平台，读者不知道和自己有什么关系。
- 只在结尾给建议，中段没有身份代入。
- 身份回扣变成泛泛鸡汤。

#### CR-06 可传播/可收藏句

核心问题：正文是否产出可被评论区引用、截图传播或收藏复看的表达和框架。

L3 执行规则：

- 正文至少出现 2 句可传播短句。
- 正文至少出现 1 个可收藏框架。
- 可传播句必须来自机制判断，不得脱离正文逻辑。

可检测指标：

- 可传播短句最低 2 句。
- 可收藏框架最低 1 个。
- 可收藏框架应包含 3-5 个判断变量、信号或步骤。

合格示例：

```text
领导管理的不是时间，而是风险。
组织不是记录你的摸鱼，组织更新的是你的可替代成本。
组织优化的不是人，组织优化的是不确定性。
```

失败表现：

- 有漂亮句子，但不能代表正文机制。
- 有列表，但不是可复用框架。
- 传播句与唯一主变量无关。

### 19. 传播参数（SP｜Spread Parameters）

状态：CANDIDATE

作用：

控制正文为什么会传播，而不是传播成什么行为。

回答的问题：

```text
为什么用户愿意点赞、评论、收藏、分享？
```

边界：

- 不决定正文写什么，PD 负责推导与机制。
- 不决定阅读是否舒服，RE 负责阅读体验。
- 不决定是否获得认知奖励，CR 负责持续新认知。
- 不决定行为目标，BT 负责行为转化。
- 只负责提高内容的传播动力。

升级路径：

```text
CANDIDATE
→ REVIEW
→ ACTIVE
→ DEPRECATED
→ ARCHIVED（长期无恢复证据后归档）
```

升级条件：

- 连续 3 篇同向验证有效：CANDIDATE → REVIEW。
- 累计 10 篇同向验证有效：REVIEW → ACTIVE。

失效条件：

- 连续 5 篇验证无改善。
- 或点赞、评论、收藏、分享、阅读完成率、停留时间等核心指标下降。

#### L2｜传播机制

传播参数拆为六大传播机制：

| 参数编号 | 传播机制 | 作用 | 影响目标 |
| --- | --- | --- | --- |
| SP-01 | 冲突机制 | 制造观点碰撞，提高评论率与停留 | 评论、阅读停留、点赞 |
| SP-02 | 身份认同机制 | 提高读者代入感 | 收藏、评论、关注 |
| SP-03 | 情绪驱动机制 | 激活情绪表达欲 | 评论、分享、点赞 |
| SP-04 | 社交货币机制 | 让内容值得转发 | 分享、收藏 |
| SP-05 | 利益价值机制 | 让读者觉得有实际价值 | 收藏、分享 |
| SP-06 | 新奇机制 | 制造信息新鲜感 | 点击、阅读完成率 |

#### SP-01｜冲突机制

作用：制造观点碰撞，提高评论率与停留。

典型机制：

- 观点冲突
- 身份冲突
- 利益冲突
- 价值观冲突
- 认知冲突
- 现实反差

影响目标：

- 评论
- 阅读停留
- 点赞

##### SP-01-01｜观点冲突

参数名称：观点冲突

作用：让正文呈现两个可被读者明确感知的观点碰撞。

影响目标：评论、阅读停留、点赞

触发条件：题目本身存在常见误解、主流答案分歧或可反驳的表层判断。

禁用边界：不得为了冲突制造虚假对立；不得脱离唯一主变量新增争议。

推荐位置：首屏 / 主体

验证指标：首屏是否出现可识别的观点碰撞；评论区是否出现站队、补充或反驳。

证据等级：CANDIDATE

状态：CANDIDATE

##### SP-01-02｜身份冲突

参数名称：身份冲突

作用：呈现不同身份在同一问题上的立场差异。

影响目标：评论、阅读停留、点赞

触发条件：题目涉及员工与领导、消费者与商家、普通人与平台、父母与子女等身份差异。

禁用边界：不得煽动身份仇恨；不得把复杂机制简化为群体攻击。

推荐位置：首屏 / 主体

验证指标：是否写清不同身份的利益、约束或感受差异；评论是否出现身份代入。

证据等级：CANDIDATE

状态：CANDIDATE

##### SP-01-03｜利益冲突

参数名称：利益冲突

作用：揭示谁获益、谁承担成本，从而提高讨论动力。

影响目标：评论、阅读停留、点赞

触发条件：题目背后存在收益分配、成本转移、责任转移或资源竞争。

禁用边界：不得凭空推断具体人获利；不得替代 PD 的利益结构推导。

推荐位置：主体

验证指标：是否明确收益方与成本承担方；评论是否围绕公平、责任或资源分配展开。

证据等级：CANDIDATE

状态：CANDIDATE

##### SP-01-04｜价值观冲突

参数名称：价值观冲突

作用：让读者围绕公平、效率、自由、责任、忠诚或体面等价值判断产生表达欲。

影响目标：评论、点赞、分享

触发条件：题目天然涉及价值排序差异，且正文需要解释不同选择为何成立。

禁用边界：不得进行道德审判；不得用价值冲突替代事实和机制解释。

推荐位置：主体 / 结尾

验证指标：是否呈现至少两种价值排序；评论是否出现价值立场表达。

证据等级：CANDIDATE

状态：CANDIDATE

##### SP-01-05｜认知冲突

参数名称：认知冲突

作用：制造“原来不是这样”的理解反差，提升停留与点赞。

影响目标：阅读停留、点赞、评论

触发条件：读者已有常识解释，但正文能提供更底层解释。

禁用边界：不得故意反常识；不得牺牲准确性追求惊讶感。

推荐位置：首屏 / 主体

验证指标：是否出现明确的旧理解与新解释；是否带来继续阅读的追问。

证据等级：CANDIDATE

状态：CANDIDATE

##### SP-01-06｜现实反差

参数名称：现实反差

作用：用理想与现实、口号与执行、表面与后台的差异制造传播张力。

影响目标：评论、阅读停留、点赞

触发条件：题目存在公开说法与真实运行之间的落差。

禁用边界：不得阴谋论化；不得编造后台事实。

推荐位置：首屏 / 主体

验证指标：是否写出表面叙事与现实机制的差异；读者是否产生“确实如此”的反馈。

证据等级：CANDIDATE

状态：CANDIDATE

#### SP-02｜身份认同机制

##### SP-02-01｜身份标签

参数名称：身份标签

影响目标：评论、收藏、关注

触发条件：题目对应清晰人群，如打工人、管理者、应届生、宝妈、创业者、消费者。

禁用边界：不得贴侮辱性标签；不得扩大到无关人群。

推荐位置：首屏

验证指标：首屏是否出现清晰身份指向；评论是否出现“我就是”类反馈。

##### SP-02-02｜处境代入

影响目标：收藏、评论、关注

触发条件：题目涉及困境、选择、压力、资源不足或无法改变的环境。

禁用边界：不得替读者虚构极端处境；不得把代入写成情绪消费。

推荐位置：首屏 / 主体

验证指标：是否写出具体处境、限制和选择成本；评论是否出现经历补充。

状态：CANDIDATE

##### SP-02-03｜经历认同

参数名称：经历认同

影响目标：评论、收藏、关注

触发条件：题目对应普遍经历，如加班、汇报、晋升、消费踩坑、关系拉扯。

禁用边界：不得伪造个人经历；不得用单一经历代表所有人。

推荐位置：主体

验证指标：是否出现可识别的经历细节；评论是否出现“我也遇到过”。

状态：CANDIDATE

##### SP-02-04｜情绪认同

影响目标：评论、点赞、关注

触发条件：题目存在委屈、愤怒、焦虑、释然、希望或共鸣。

禁用边界：不得煽动情绪替代解释；不得放大恐惧或羞辱读者。

推荐位置：首屏 / 主体

状态：CANDIDATE

##### SP-02-05｜价值认同

参数名称：价值认同

作用：让读者觉得正文替自己守住某种判断标准。

影响目标：收藏、评论、关注

触发条件：题目涉及努力、尊严、公平、边界、责任、成长等价值判断。

禁用边界：不得写成站队口号；不得压制合理反方。

推荐位置：主体 / 结尾

验证指标：是否明确正文维护的价值标准；评论是否出现认同或转发理由。

触发条件：题目涉及付出不被看见、责任不对等、解释权不足或被误解。

证据等级：CANDIDATE

状态：CANDIDATE

##### SP-03-04｜希望

参数名称：希望

作用：让读者看到可理解、可判断或可改善的可能性。

影响目标：点赞、收藏、分享

## 参数触发规范

正文生产四层职责固定分离：

```text
变量库
决定：
写什么。

参数库
决定：
怎样写。

Prompt
负责：
执行参数。

正文
负责：
输出内容。
```

变量库不得承担表达质量判断。

参数库不得决定正文主题、变量和核心机制。

Prompt 不得新增未经参数库验证的质量规则。

正文不得绕过 Production Card 自行添加变量或机制。

CR 子参数只能作为唯一实验参数逐项触发，不得整组触发。

Production Card 中不得写泛化的 `CR｜认知奖励`，必须精确到 `CR-xx｜参数名`。

## 复盘验证接口

后续复盘不再直接评价文章好坏。

统一评价：

1. 哪个参数有效？
2. 哪个参数失效？
3. 哪个参数需要继续深挖？
4. 哪个参数可以进入 Prompt？
5. 哪个参数应该降级或废弃？

复盘必须区分两类参数：

- 内容参数：原因变量，包括信息增量、解释增量、主变量、首屏、结构、评论机制、认知奖励、传播参数。
- 收益参数：结果变量，包括单篇盐粒收益、千阅读收益、7天累计收益、30天累计收益。

收益参数不参与正文生产，不作为 Production Card 的生产变量；收益参数是裁判内容变量是否具有商业价值的结果层指标。

知乎盐粒收益复盘只使用 `收益分析 → 致知计划 → 内容收益明细`。普通 `收益分析 → 全部` 页面不是盐粒收益复盘口径，不得用来判断内容变量是否赚钱。

行为结果层必须使用可归属后台数据。公开问题页会混入同题其他答主内容，不能作为本人回答的阅读、赞同、收藏、评论来源。阅读、赞同、收藏、喜欢、分享、正向互动率、关注者转化只认 `内容管理 -> 单篇内容 -> 数据`；本人回答评论只认 `内容管理 -> 单篇内容 -> 查看评论` 或 `评论管理 -> 单篇回答评论`。公开页只可用于正文、首屏、结构提取，且必须匹配 answer_id。

最终判断口径：

```text
参数是否命中
+
收益是否提高
+
是否连续复现
=
是否升级为规则
```

### 参数状态治理协议

低频不等于低价值。

参数治理不得仅依据触发次数淘汰参数。低频至少可能来自三种原因：

1. 参数没有独立价值。
2. 最近周期没有遇到适用题。
3. 路由没有正确触发。

参数是否保留，必须同时检查四个维度：

| 维度 | 判断内容 |
| --- | --- |
| 适用机会 | 最近周期是否出现适合触发该参数的题 |
| 触发命中 | 出现适用题时，系统是否正确触发 |
| 结果贡献 | 触发后是否改善阅读、收益、收藏、评论或正文质量 |
| 能力重叠 | 该参数能力是否已被其他参数完全覆盖 |

适用机会不得用实际触发次数代替。否则路由漏调会被误判为参数无用。

每 20 篇或每月执行一次参数审计，与现有复盘节奏一致。每个参数至少记录：

- 适用题数量。
- 实际触发数量。
- 应触发未触发数量。
- 触发后的结果表现。
- 与其他参数的重叠程度。
- 当前参数状态。
- 下一周期处理。

关键指标：

```text
触发命中率 = 实际触发次数 ÷ 适用机会次数
有效贡献率 = 出现正向结果的触发次数 ÷ 有效触发次数
```

参数状态采用五级管理，不允许直接物理删除：

| 状态 | 含义 |
| --- | --- |
| ACTIVE | 正常触发，已有证据支持 |
| LOW-FREQ | 低频但有明确适用场景，继续保留 |
| OBSERVE | 触发少或贡献不明确，进入观察周期 |
| MERGED | 与其他参数高度重叠，合并到上级参数 |
| DEPRECATED | 验证无独立贡献，停止日常触发但保留历史记录 |

进入 `DEPRECATED` 后，只能从生产路由隐藏，不得删除历史证据，防止以后重复创建。

只有同时满足以下条件，才允许进入 `DEPRECATED`：

1. 连续两个审计周期适用机会充足。
2. 该参数被实际触发，或完成过对照验证。
3. 没有稳定正向贡献。
4. 与其他参数高度重叠，或删除后正文没有明显损失。

如果最近 40 篇只有 2 篇适用，且 2 篇触发后均有效，该参数应进入 `LOW-FREQ`，不得淘汰。

如果连续两个复盘周期无独立贡献，先进入 `OBSERVE`；完成对照验证后，才允许转为 `MERGED` 或 `DEPRECATED`。

治理对象不是低频参数，而是长期没有独立贡献的参数。

### 验证状态

- 候选：发现问题，但尚未验证。
- 实验：正在 20 篇样本中观察。
- 有效：已通过一轮样本验证。
- 稳定：连续多轮验证有效。
- 废弃：连续两个复盘周期无独立贡献，并完成对照验证后，进入 DEPRECATED。

### 评分

每个参数默认 1-5 分：

- 1 分：完全缺失。
- 2 分：弱执行。
- 3 分：基本满足。
- 4 分：执行清晰。
- 5 分：执行稳定且明显提升质量。

### Prompt 同步条件

参数同步到 Prompt 前必须同时满足：

1. 问题重复出现。
2. 参数能稳定解释问题。
3. L3 执行规则可以直接执行。
4. 验证指标清晰。
5. 不与 Production Card 字段冲突。
6. 不引入新变量。
7. 不改变正文生产流程。
8. 收益结果不低于账号、同题型或同结构的可比中位数。
9. 至少一轮样本中没有出现“内容评分高但收益低”的反证。
10. 已生成变量验证卡，且变量证据等级至少为“有效”。

## 禁止事项

- 禁止把参数库写成 Prompt。
- 禁止用参数库直接生成正文。
- 禁止未经验证就扩展正文生产流程。
- 禁止把表达偏好伪装成质量参数。
- 禁止为了单篇正文问题新增一整套参数。
- 禁止参数库决定“写什么”。
- 禁止 Prompt 直接新增未入库规则。
