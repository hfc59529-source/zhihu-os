# 参数服务映射表

版本：PARAM-SERVICE-MAPPING-FINAL

核心原则：每个参数必须能回答"它服务五个目标中的哪一个"。回答不了，就不调用。

---

## 五个成品目标

```
1. 接住情绪/困惑
2. 帮用户看懂
3. 核心认知反转
4. 举一反三（迁移）
5. 可执行动作
```

---

## 参数服务映射

### 目标 1：接住情绪/困惑

**核心机制**：读者进入时的心理状态要被准确命名和接纳

| 参数/做法 | 具体表现 | 为什么有效 |
|---------|--------|---------|
| **场景具体化** | 开头用读者熟悉的日常场景 | 降低进入门槛，减少陌生感 |
| **困惑命名** | 准确指出读者想说但说不出来的问题 | "啊，就是这个感受！" |
| **情绪识别** | 识别并命名情绪状态 | 被理解会产生共鸣 |
| **反差呈现** | 展示期望和现实的矛盾 | 激发继续读的动力 |
| **共同经历** | 暗示这是普遍困惑，不是个人问题 | 减少自我否定感 |

**验收标准**：
- 读者一开始能感到"被理解"
- 困惑被准确命名，不模糊、不过度解释

**参数来源**：
- 结构库中的"开头"设计
- 问题理解（QI 系列）
- 共鸣机制（来自已有参数）

---

### 目标 2：帮用户看懂

**核心机制**：用户不是直接获得答案，而是跟随正文的推导过程看懂

| 参数/做法 | 具体表现 | 为什么有效 |
|---------|--------|---------|
| **层层递进** | 每一段都是上一段的自然延续 | 不跳跃，读者不会掉队 |
| **因果链完整** | 为什么→所以→推导→终点 | 逻辑自洽，易于跟随 |
| **概念控制** | 新概念出现时解释，不堆砌 | 易于理解，不累 |
| **对比说明** | 用反例或对照来澄清 | 减少理解偏差 |
| **进度明确** | 读者知道现在讲到哪了 | 不会突然发现理解错了 |

**验收标准**：
- 读者能跟上逻辑，不感到跳跃
- 每一段的因果关系都清晰
- 新概念不过多

**参数来源**：
- 推理质量（PD 系列）
- 结构的递进设计
- 因果追问链

---

### 目标 3：核心认知反转

**核心机制**：用户原来的理解被改变，产生新的看法

| 参数/做法 | 具体表现 | 为什么有效 |
|---------|--------|---------|
| **反常识呈现** | 与常规理解相反的观点 | 冲击产生关注和思考 |
| **机制解释** | 说出反常识背后的原因 | 不是简单对立，而是理解原理 |
| **人性博弈** | 解释各方角色为什么会这样选择 | 深化理解，建立对人性的认知 |
| **核心判断** | 明确说出"所以，真实情况是..." | 给出新的观点框架 |
| **验证** | 用例子或逻辑验证这个反转 | 不是凭空否定，是有根据的 |

**验收标准**：
- 有明确的认知反转点（不是模糊的改变想法）
- 反转有机制支撑，不是断言
- 用户能看到"为什么原来的理解会错"

**参数来源**：
- 推理深度
- 机制解释（已有的因果链框架）
- 人性博弈分析

---

### 目标 4：举一反三（迁移）

**核心机制**：用户能把这个认知推广到其他类似场景

| 参数/做法 | 具体表现 | 为什么有效 |
|---------|--------|---------|
| **边界条件** | 明确说出这个规律何时适用、何时不适用 | 用户知道如何判断是否适用 |
| **通用原则** | 从具体案例提炼出通用规则 | 可以迁移到更多场景 |
| **迁移示例** | 给出 2-3 个不同场景的应用 | 用户能看到可能性 |
| **判断标准** | 给出判断"是否适用"的方法 | 用户能自己判断 |
| **同类问题** | 明确指出"这个思路也适用于..." | 直接告诉用户迁移方向 |

**验收标准**：
- 不是只讲一个具体案例
- 有清晰的边界和应用范围
- 用户能想到其他场景可以用这个逻辑

**参数来源**：
- 结构库中的迁移设计
- 边界条件参数
- 通用性判断

---

### 目标 5：可执行动作

**核心机制**：用户读完后能做出具体的判断或动作

| 参数/做法 | 具体表现 | 为什么有效 |
|---------|--------|---------|
| **决策动作** | 给出"遇到这种情况，你可以..." | 用户有具体选项 |
| **判断标准** | 给出"判断的方法是..." | 用户能自己做决策 |
| **责任边界** | 明确"你该负责什么，不该负责什么" | 用户知道边界，避免过度负责 |
| **第一步** | 如果要行动，第一步是什么 | 降低行动门槛 |
| **风险提示** | 如果做这个选择，要注意什么 | 用户有心理预期 |

**验收标准**：
- 不是"你应该这样想"，而是"你可以这样做"
- 有具体的判断标准或动作选项
- 用户读完能立即应用

**参数来源**：
- 结构库中的行动设计
- 决策框架（已有参数）
- 具体建议

## 调用规则

### 生成 Production Card 时

1. **先填五项成品目标**
   - 必须明确，每项不超过 50 字

2. **设计每一段，标注服务的目标**
   ```
   段 1：接住困惑和情绪 [目标 1]
   段 2：铺垫和层层递进 [目标 2]
   段 3：反转和机制 [目标 3]
   段 4：迁移和边界 [目标 4]
   段 5：行动和判断 [目标 5]
   ```

3. **检查映射完整性**
   - 每个成品目标都被至少一段服务
   - 没有段落不知道自己的作用
   - 没有参数是"闲置"的

### 调用参数时

**问题**：这个参数/做法服务哪个目标？
- **能清晰回答**→ 调用
- **模糊或多个目标** → 不调用或简化
- **答不上来** → 删除

**例子**：

```
参数：认知升级
问：它服务哪个目标？
答：...嗯，好像可以支持目标 3、也可以支持目标 2...
结论：不调用。太模糊，容易平均用力。

参数：具体场景举例
问：它服务哪个目标？
答：首先接住情绪（目标 1），其次帮用户理解（目标 2），
    也能验证认知反转（目标 3）。
结论：调用，但主要作用是目标 1 和 2。
```

---

## 参数不增不减

这个映射表**不删除**现有参数库，不新增参数。

它只是说明：已有参数应该怎么用，才能服务这五个目标。

核心改变：
- **从**：平均调用所有参数
- **到**：有目的地调用参数，每个参数都有分工
