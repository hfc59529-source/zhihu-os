# 知乎平台样本学习协议

版本：PLATFORM-SAMPLE-V1.0

状态：ACTIVE

## 核心判断

知乎OS进入第二阶段后，平台高表现样本负责发现规律，账号历史数据负责验证规律。

不得再把自己的历史文章作为主要规律发现对象。自己的文章只用于判断平台变量证据是否适合本账号、本题型和当前表达风格。

## 采集边界

知乎平台样本采集以职场赛道为唯一主赛道。

主采集范围：

- 领导与下属
- 晋升与加薪
- 职场关系
- 权力与资源分配
- 组织决策
- 责任与背锅
- 离职与职业选择
- 员工与老板视角
- 基层与中层处境
- 职场沟通与博弈

主采集样本占比：70% 至 80%。

辅助采集范围：组织管理和商业认知。

只采能够迁移到职场回答里的内容：

- 组织为什么做出错误决策
- 管理者如何分配资源
- 公司为什么提拔某类人
- 利益如何影响行为
- 风险为什么向下传导
- 决策权与责任为什么分离

辅助采集样本占比：20% 至 30%。

心理学不得作为独立采集赛道，只能作为解释职场行为、组织关系或决策问题的辅助证据。

禁止单独采集：

- 原生家庭
- 亲密关系
- 情绪疗愈
- 人格测试
- 焦虑抑郁
- 心理疾病
- 纯心理学科普

只有当心理学内容直接服务于职场问题时，才允许作为解释材料进入样本分析。例如：

- 为什么员工不敢反对领导
- 为什么人会服从错误决策
- 为什么职场中容易自我怀疑
- 为什么能力强的人反而不被提拔

禁止因某篇内容使用心理学概念，就将样本归入心理学赛道。

核心原则：

```text
只采职场。
心理学、管理学、经济学都只是解释职场问题的工具。
```

## 采集入口优先级

知乎平台样本采集分为两种任务，不得混用：

1. 选题候选采集：寻找本账号近期可以回答的问题。
2. 爆款变量训练采集：寻找平台高表现样本，用于变量提取和统计。

创作中心入口主要用于选题候选采集，不等同于爆款变量训练入口。

知乎平台样本采集不得用外部搜索结果替代知乎站内采样。

### 选题候选入口

用于判断“这题值不值得本账号回答”，不直接承担爆款变量训练职责。

| 优先级 | 入口 | 用途 | 权限 |
| --- | --- | --- | --- |
| P0 | 创作权益 -> 近期热点 -> 职场 -> 小时榜 | 发现近期热点职场榜问题，记录热力值、关注增量、浏览增量、回答增量和赞同增量 | 优先采集 |
| P1 | 创作中心 -> 等你来答 -> 推荐问题 | 账号匹配入口，用于发现平台认为本账号可能适合回答的问题 | 优先采集 |
| P2 | 创作中心 -> 等你来答 -> 邀请回答 | 账号邀请入口，用于补充已有明确邀请的问题 | 辅助采集 |
| P3 | 创作中心 -> 问题搜索 -> 知乎热词 / 知乎热题 / 全网热点 | 热点迁移入口，用于补充可迁移到职场、组织管理、商业认知的公共议题 | 辅助采集 |
| P4 | 知乎站内搜索 `职场` / 组织管理 / 商业认知关键词 | 兜底入口，用于补足职场垂直问题样本 | 不得替代 P0/P1 |

独立校验：

| 编号 | 工具 | 用途 | 权限 |
| --- | --- | --- | --- |
| H1 | 职场日榜 / 职场周榜 / 知乎热榜 `/billboard` / 首页热榜 `/hot` | 校验候选题或相邻议题是否具备持续热度、公共关注、议题扩散性或可迁移热点背景 | 只调整排序权重，不作为采题入口 |

### 30天选题入口实验

状态：ACTIVE

目的：不预设哪个入口最好，而是连续积累本账号、本赛道的入口数据，30天后再判断各入口的投入权重。

固定日采样：

- P0｜创作权益：近期热点 -> 职场小时榜 1题
- P1｜等你来答：推荐问题 1题
- P2｜等你来答：邀请回答 1题（当天没有则跳过）
- P3｜问题搜索：知乎热词 / 知乎热题 / 全网热点中可迁移题 1题
- P4｜站内搜索：职场 / 组织管理 / 商业认知关键词兜底 1题（可选）
- H1｜职场日榜 / 职场周榜 / 知乎热榜 / 首页热榜只做热度校验，不作为采题入口

榜单口径：

- P0 采题默认使用职场小时榜。
- 职场日榜、职场周榜、知乎热榜和首页热榜只用于 H1 热度校验。
- 小时榜用于捕捉当天新机会；日榜 / 周榜 / 热榜用于判断候选题是否存在持续热度或公共扩散性。
- 日榜 / 周榜 / 热榜不得替代小时榜成为当天主采样入口。

轻量筛选流程：

```text
题目
↓
Answer_Benchmark_Top3 快速采集
↓
是否值得生产
```

执行规则：

- 每天先写入 `data/Topic_Pool.md`，再选择当天生产题。
- 选题只在采集当天有效；旧 Topic Pool 和旧候选池不得直接复用为当天生产题。
- P0、P1 已取得至少 3 个符合账号方向且可被 Trigger Candidate 解释的候选题时，P2-P4 只做补充，不再强制逐入口采满。
- 当天 Topic Pool 完成后，先做 H1 热榜校验，再用 `data/trigger_candidate_ranking.md` 排序，输出 `Daily_Topic_Top3`，再决定当天生产题。
- 选题阶段对正式候选题采集 `Answer_Benchmark_Top3`，不生成 Card 和 Draft。
- Trigger Candidate 只决定生产优先级，不得绑定 ACTIVE、结构、参数或正文方向。
- `Answer_Benchmark_Top3` 输出竞争环境、`Existing_View_Coverage`、`Possible_Current_Gap`、现有参数命中和参数缺口；`Possible_Current_Gap` 不是正文方向，Production Card 可以采用、拒绝或重新推导。
- `Answer_Benchmark_Top3` 发现的新效果只能写入 `New_Parameter_Observations`，状态统一为 `待审核`。每条缺口必须记录 `Gap_ID`、`Source`、`Occurrence_Count`、`Occurrence_Refs` 和 `Review_Result`。Codex 不得直接创建、推进或激活参数。
- 当天原则上只生产 1 篇；产能允许时最多 2 篇。
- 不得因为某个入口看起来顺手，就跳过其他固定入口的日采样。
- 不得在30天实验期内提前下结论调整入口权重。
- 发布后表现回填到 `data/Topic_Pool.md`，用于统计“入池数、最终生产数、发布后表现”。
- 未经过 Topic Pool 的题不得直接进入新 Production；异常情况必须记录为异常样本，不纳入入口优劣统计。

### 爆款变量训练入口

用于判断“平台高表现回答到底怎么写”。必须区分平台当前推荐样本和历史赞同样本，不得把二者混用。

| 优先级 | 入口 | 用途 | 权限 |
| --- | --- | --- | --- |
| T0 | 待生产问题页当前默认排序回答 | 找平台当前优先展示给新用户的样本 | 生产优先入口 |
| T0.5 | 知乎站内搜索职场核心关键词，并筛选高赞回答 | 找职场赛道长期高赞样本 | 长期规律研究入口 |
| T1 | 知乎热榜 `/billboard`、首页热榜 `/hot` 中可迁移到职场/组织/商业认知的问题 | 找当前平台高热样本 | 热度训练入口 |
| T2 | 创作中心 -> 问题搜索 -> 知乎热题 / 全网热点 | 找近期高热候选，再筛选高赞回答 | 辅助训练入口 |
| T3 | 创作中心 -> 推荐问题 / 邀请回答 | 只在回答赞同和评论达到门槛时进入训练 | 条件训练入口 |

### Answer_Benchmark_Top3 平台样本来源

知乎“默认排序”不等于“赞同数排序”。采样标准会影响整个研究结论，因此所有 `Answer_Benchmark_Top3` / Top5 样本必须记录 `Sample Source`。

| 样本来源 | 用途 | 生产权限 |
|---|---|---|
| 默认排序 Answer_Benchmark_Top3 | 学平台当前推荐逻辑，观察新用户首先可能看到的同题回答 | 日常生产默认使用 |
| 赞同数 Answer_Benchmark_Top3 | 学长期优质内容和历史高赞结构 | 长期规律研究使用 |
| 最新回答 Answer_Benchmark_Top3 | 学当前竞争环境和新回答切入方式 | 可选补充 |

执行规则：

- 日常生产默认使用 `默认排序 Answer_Benchmark_Top3` 作为主要分析对象。
- 历史赞同数排序只作为长期规律研究对象，不得冒充平台当前推荐样本。
- 同一次分析如果混合默认排序与赞同排序，必须标注为 `Mixed`，并说明每类样本用途。
- 所有样本记录必须写明：默认排序 / 赞同排序 / 最新回答 / Mixed。
- 不得再把“高赞 = 平台推荐”作为默认假设。

爆款训练最低门槛：

- 单题 Top1 回答赞同数建议不低于 300；低于 100 默认不得作为爆款训练样本。
- Top5 中至少 3 条回答赞同数达到 100 以上，或该题具备明显高收藏、高评论、高热度信号。
- 若是低竞争新题，可作为账号实验题，但不得作为平台爆款变量训练题。
- 推荐问题只说明账号匹配，不说明平台爆款；推荐问题中的低赞回答不得用于提炼爆款变量。

执行规则：

- 日常采集先看 `近期热点`，再按职场主赛道边界过滤。
- `推荐问题` 是账号匹配型入口，优先记录推荐理由、所属话题、浏览量、回答数、关注数和提问时间。
- 同时出现在 `近期热点` 和 `推荐问题` 的问题，选题优先级上调，但仍需通过爆款训练门槛后，才可进入变量训练。
- `近期热点` 中的非职场题，只有能迁移到组织管理、商业认知或职场行为解释时，才允许进入候选池。
- `/billboard` 和 `/hot` 只能作为全站热度参照，不等同于职场样本池。
- 站内搜索得到的问题只能作为补充样本，不得冒充平台热点采集结果。
- 外部搜索引擎结果不得作为知乎平台样本来源，只能用于找回入口或校验公开 URL。

## 三层数据源

```text
L1｜平台样本
发现规律
↓
L2｜账号实验
验证规律
↓
L3｜ACTIVE变量
生产触发
```

### L1｜平台样本

职责：从知乎平台高表现和低表现样本中抽取统计变量，并回写 `production_variable_library.md` 的同一条变量记录。

包含：

- 问题样本
- TOP回答
- 评论样本
- 失败样本
- 变量证据

L1只负责发现候选规律，不直接影响 Production Card。

平台样本分析完成后，禁止写入第二套变量库。日常 Codex 选题采集中的 `Answer_Benchmark_Top3` 只允许命中已有参数和提交 `待审核` 参数缺口，不得直接新增或推进参数。只有经用户审核确认进入参数治理流程后，才允许按 `production_variable_library.md` 的权威规则处理。

写入规则：

- 若变量已存在，只更新平台样本数、平台命中数、平台命中率、平台证据强度、反例和备注。
- 若变量不存在，先记录为 `New_Parameter_Observations`，状态为 `待审核`；经用户审核批准后，才可按去重规则检查同义变量，并决定是否创建候选参数记录。
- 不得因为样本来源不同，创建同义重复变量。
- 单篇高赞回答不得直接创建正式参数，不得直接进入 ACTIVE，不得立即影响所有后续生产。

参数缺口审核结果只允许四种：

| Review_Result | 后续动作 |
|---|---|
| 驳回 | 关闭缺口，不入库 |
| 合并 | 归入已有参数，填写 `Merge_Target` |
| 候选参数 | 进入 Candidate 前置验证 |
| 正式参数 | 极少发生，必须由用户明确批准 |

`Occurrence_Count` 和 `Occurrence_Refs` 用于累计独立问题中的重复出现次数，只提供审核依据，不自动升级。

编号规则：

- 参数缺口：`Gap-001`
- 候选参数：`Candidate-001`
- 正式参数：`PD-09` / `RR-02` / `CR-01`

`Source` 固定可选值：高赞Top3 / 用户发布结果 / 人工审核 / 老师样本 / 历史数据库 / 评论区 / 数据复盘。

### L2｜账号实验

职责：用本账号发布结果验证平台变量证据。

包含：

- Production Card
- 正文
- 发布数据
- 单篇复盘
- 实验结果

L2不直接生产新规律，只判断候选规律在本账号是否有效。

216篇历史文章和后续发布文章不创建账号专属参数。验证结果统一回写 `production_variable_library.md` 同一变量记录中的账号证据字段。

### L3｜ACTIVE生产触发

职责：只调用经过验证、具备触发资格的变量。

包含：

- 已验证变量
- 适用题型
- 参数
- Prompt调用说明
- Production Card调用说明

日常生产只允许读取 `production_variable_library.md` 中 `当前状态=ACTIVE` 且 `触发资格=是` 的变量，不允许直接读取平台样本、单篇复盘或未验证候选变量。

## 平台采样固定字段

### 第一层：问题

每个问题必须先创建一条问题级记录。

固定记录：

| 字段 | 说明 |
|---|---|
| 问题标题 | 知乎问题标题 |
| 问题链接 | 知乎问题链接 |
| 所属赛道 | 职场为唯一主赛道；组织管理、商业认知只能作为辅助来源；心理学不得独立归类 |
| 题型 | 领导下属 / 晋升加薪 / 职场关系 / 权力资源 / 组织决策 / 责任背锅 / 离职选择 / 职业发展等 |
| 发布时间 | 问题创建或可见发布时间 |
| 关注人数 | 判断问题热度 |
| 回答数量 | 判断竞争密度 |
| 采样时间 | 本次采样时间 |
| 有效样本数 | 本次纳入分析的有效回答数 |
| Sample Source | 默认排序 / 赞同排序 / 最新回答 / Mixed |
| 样本可信度 | 本次样本是否足以支撑生产判断 |
| 页面加载深度 | 本次实际读取到页面第几条回答 |
| 是否可能遗漏 | 是否可能因动态加载、登录态、排序机制或不可读回答遗漏样本 |
| 竞争程度 | 低 / 中 / 高 |
| 主要已有答案方向 | 已有回答主要怎么答 |
| 可提供的内容增量 | 本账号还能补什么 |

目的：判断问题是否值得回答。

### 第二层：样本回答

日常每个进入正式候选的问题默认采集 `Answer_Benchmark_Top3`；长期变量训练任务可采集有效平台样本 Top5。

变量提取前置条件：

- 只采问题不构成完整平台样本。
- 每个进入长期变量提取的问题，必须完成有效 Top5 回答采集。日常 Topic Package 中的 `Answer_Benchmark_Top3` 只承担同题 Benchmark、现有参数匹配和参数缺口观察，不单独构成参数升级依据。
- 每条有效回答必须形成“回答原文层 + 回答拆解层”两层记录。
- 未完成 Top5 回答正文读取的问题，状态只能是 `QUESTION_ONLY`，不得进入长期变量提取、变量统计、参数升级或 Production Card 升级。已完成 `Answer_Benchmark_Top3` 的日常题，只能服务当前题目语境和待审核观察。
- 若回答因盐选、权限、删除、折叠、广告、偏题或不可完整读取而失效，必须继续向下补样，直到获得 5 条有效回答；若全题不足 5 条，标记 `INSUFFICIENT_VALID_ANSWERS`。

有效平台样本定义：按本次 `Sample Source` 的排序口径采集，并排除无效样本。日常生产默认按当前页面默认排序采集；长期规律研究可按赞同数排序采集。

必须尽量排除：

- 盐选节选或明显不可完整读取的回答
- 广告、引流和无实质内容回答
- 与题意偏离的高赞回答
- 因发布时间极早占据排名、但已明显过时的回答

如果页面前5条中存在无效样本，必须继续向下补足 5 个有效样本。

Top5 内部分层（长期变量训练使用）：

| 层级 | 范围 | 分析重点 |
|---|---|---|
| 头部样本 | Top1 至 Top3 | 核心判断、解释路径、正文结构、高赞原因 |
| 补充样本 | Top4 至 Top5 | 验证共同点、寻找差异观点、防止只模仿一个答案 |

动态调整规则：

| 问题情况 | 抓取数量 |
|---|---|
| 日常普通问题 | 有效 Top5 |
| 回答总数不足5篇 | 全部有效回答 |
| Top5观点高度一致 | Top5即可 |
| Top5分歧明显 | 补到Top8 |
| 高价值、高竞争题 | Top10 |
| 新问题、回答数量少 | Top3或全部 |
| 只需快速生产 | Top3轻分析 |

不要每题都抓 Top10，避免采集和分析成本失控。

每篇有效回答创建一条回答级记录。

固定记录：

| 字段 | 说明 |
|---|---|
| 回答排名 | 本次采样中的有效排名 |
| Sample Source | 默认排序 / 赞同排序 / 最新回答 / Mixed |
| 回答链接 | 回答链接 |
| 作者 | 作者名称或匿名 |
| 发布时间 | 回答发布时间 |
| 赞同 | 赞同数 |
| 评论 | 评论数 |
| 正文读取状态 | FULL / PARTIAL / UNREADABLE |
| 正文全文 | 可完整读取时保存到样本记录，用于变量提取前的原始证据审计；不得直接进入 Production Card |
| 正文定位 | 原回答URL、采样时间、有效排名、不可读原因 |
| 核心结论 | 该回答最终判断 |
| 切入角度 | 从什么角度进入 |
| 解释机制 | 主要解释机制 |
| 结构路径 | 正文展开顺序 |
| 案例类型 | 个人经历 / 职场场景 / 行业观察 / 无案例等 |
| 首屏方式 | 反常识 / 身份代入 / 利益相关 / 冲突 / 疑问等 |
| 结尾方式 | 判断句 / 行动建议 / 互动 / 收束等 |
| 收藏点 | 可复用判断、清单、模型或标准 |
| 评论触发点 | 站队、补充经历、质疑、求助等 |

回答原文层用途：

1. 判断首屏为什么能留住人。
2. 判断阅读节奏、段落推进和认知奖励出现位置。
3. 判断推导深度到第几层。
4. 判断收藏点、评论触发点和传播奖励来自哪一段。
5. 给变量提取提供原始证据，而不是根据问题摘要推断。

回答原文层不得替代变量层。原文用于分析，长期生产触发仍只读取变量统计、ACTIVE变量和运行时快照。

不得长期保存 Top1、Top2、Top3、Top4、Top5 这种排名结构作为生产资产。排名只用于采集当时定位样本。

长期保存对象必须改为变量：

- FV：首屏变量
- PD：推导深度变量
- RR：阅读体验变量
- CR：认知奖励变量
- BT：行为转化变量

回答全文和排名不进入生产链，只用于完成变量标注和证据归因。

### 第二点五层：问题级聚合结论

逐篇结构化分析后，必须生成一份问题级聚合结论。

聚合结论字段：

| 字段 | 说明 |
|---|---|
| Top5共同观点 | 高表现回答重复最多的核心判断 |
| Top5共同结构 | 高表现回答共同使用的结构路径 |
| 重复最严重的内容 | 本账号必须避免重复的观点、案例或表达 |
| 观点分歧 | Top5之间明显不同的解释方向 |
| 用户未被满足的问题 | 已有回答没有解决的疑问、场景或边界 |
| 本篇差异化方向 | 本账号可以提供的新机制、新边界或新判断 |
| 推荐结构 | 建议调用的既有 ACTIVE 结构 |
| 推荐变量 | 建议进入运行时快照的变量 |
| 禁止重复表达 | 不能照搬、改写或复用的表达方式 |

只有问题级聚合结论可以进入 Production Card 生成前分析。

Top5 回答原文、逐篇拆解细节和排名信息不得直接进入 Production Card。

### 第三层：正文变量拆解

不分析全文心得，只拆参数。

固定拆解：

| 模块 | 变量 |
|---|---|
| 首屏 | 是否反常识、是否制造冲突、是否提出疑问、是否利益相关、是否身份代入 |
| 正文 | 是否有机制解释、是否有推导、是否有规律、是否有迁移、是否有收藏点 |
| 表达 | 句长、段长、换段频率、标题密度、留白、短句比例 |
| 结构 | 第一观点、主机制、转折、案例、结尾、互动方式 |

输出必须参数化，禁止只写“这个写得好”“这个像爆款”。

### 第四层：评论区

每个问题固定采集 Top20 评论。

分析字段：

| 字段 | 说明 |
|---|---|
| 为什么评论 | 反驳、补充、共鸣、求助、提问、吐槽 |
| 讨论对象 | 观点、案例、身份、方法、事实、情绪 |
| 是否误解 | 用户误读了什么 |
| 二次需求 | 评论里出现的新问题或新需求 |

评论区优先用于发现用户真实关心点，不直接作为正文观点来源。

### 第五层：变量共同点统计

共同点输出必须是变量统计，不是规律总结。

格式：

| 变量 | 样本命中数 | 命中率 | 说明 |
|---|---:|---:|---|
| 组织视角 | 4/5 | 80% | 是否从组织而非个人解释 |
| 利益解释 | 4/5 | 80% | 是否解释利益分配 |
| 机制推导 | 5/5 | 100% | 是否给出因果机制 |
| 身份代入 | 3/5 | 60% | 是否让读者进入角色 |
| 短段表达 | 5/5 | 100% | 是否短段推进 |

### 第六层：反向分析

每个问题至少补充同题低表现回答样本。

比较字段：

| 字段 | 成功样本 | 失败样本 |
|---|---|---|
| 首屏变量 | 命中情况 | 缺失或误用 |
| 机制解释 | 命中情况 | 缺失或浅层 |
| 身份代入 | 命中情况 | 缺失或错位 |
| 收藏点 | 命中情况 | 缺失或不明确 |
| 表达节奏 | 命中情况 | 冗长、密集或空泛 |

输出：

- 成功变量
- 失败变量
- 可实验变量

## 样本可信度记录

每次 `Answer_Benchmark_Top3` 或 `Top5` 分析末尾必须记录样本可信度：

```text
## 样本可信度
默认排序：★★★★★ / ★★★★☆ / ★★★☆☆ / ★★☆☆☆ / ★☆☆☆☆
赞同排序：★★★★★ / ★★★★☆ / ★★★☆☆ / ★★☆☆☆ / ★☆☆☆☆
样本数量：
页面加载深度：
采集时间：
是否可能遗漏：
Sample Source：
采用理由：
```

评分原则：

- 默认排序样本用于日常生产时，若页面可完整读取当前默认排序前 3 条有效回答，默认可信度为 `★★★★★`。
- 赞同排序样本用于长期规律研究时，若能明确按赞同数排序并完整读取 Top3，默认可信度为 `★★★★☆`；低于默认排序一档，是因为它解释长期累计表现，不直接等于当前推荐展示。
- 页面无法确认排序、回答不可完整读取、加载深度不足或混合来源时，必须降级并说明原因。

## 日常生产采样路径

```text
问题
↓
采集问题级记录
↓
抓取 Answer_Benchmark_Top3（默认排序优先）
↓
保存每篇回答原文层
↓
逐篇结构化分析
↓
生成 Existing_View_Coverage / Possible_Current_Gap
↓
匹配现有参数库
↓
记录 New_Parameter_Observations（待审核）
↓
生成 Topic Package
↓
交给 Claude
```

平台样本在日常生产中承担两个作用：

1. 本篇竞争分析：判断同题已有回答覆盖了什么、当前可能还有哪些空白。
2. 参数库真实样本校验：检查现有参数是否能解释高赞回答中的有效效果，并记录待审核缺口。

禁止把 `Answer_Benchmark_Top3` 直接合成一篇。禁止让 Claude 重复采集同题高赞回答。

禁止把每篇回答拆出的所有参数永久写入参数库。

禁止在缺少 Top5 回答正文的情况下输出爆款变量报告、参数升级建议、Production Card升级或 Prompt升级。

## 变量证据卡

平台分析不输出独立“规律”，只输出变量证据。

变量证据卡不是第二套变量库，只是写入 `production_variable_library.md` 的审计材料。

变量提取报告禁止停留在描述层。报告最终目标不是总结爆款，而是生成可进入 `production_variable_library.md`、知乎内容质量参数库、Production Card 和 Prompt 审核流程的生产参数。

每个候选变量必须使用以下字段：

| 字段 | 要求 |
|---|---|
| 变量名称 | 用可复用参数名，而不是现象描述 |
| 变量编码 | 按 FV / PD / RR / RE / BT / CR 等类别编码，未分配时标记 `TEMP` |
| 变量定义 | 说明变量是什么 |
| 生效机制 | 说明为什么有效，必须包含用户行为或平台传播逻辑 |
| 证据统计 | 样本数、命中数、命中率、来源 |
| 证据等级 | DISCOVERED / CANDIDATE / REVIEW / ACTIVE / DEPRECATED / ARCHIVED |
| 适用题型 | 什么题调用 |
| 触发条件 | 什么场景下调用 |
| 禁用边界 | 什么题不能调用 |
| Production Card 调用方式 | 默认调用 / 条件调用 / 禁止调用 |
| Claude Prompt 调用方式 | 写入Prompt / 留在参数库 / 只做本题Card |
| 升级建议 | 新增 / 修改 / 合并 / 淘汰 / 继续观察 |

变量统计不得停在“出现了”。每个高频变量必须回答：

```text
为什么出现
↓
为什么有效
↓
触发了什么阅读/收藏/评论/推荐行为
↓
什么时候会失效
```

不满足上述字段的报告，只能标记为 `V0_DESCRIPTIVE_REPORT`，不得进入参数库、Production Card升级或 Prompt升级。

```text
变量编码：
变量名称：
变量大类：FV / PD / RR / CR / BT
适用题型：
平台样本数：
平台命中数：
平台命中率：
成功样本：
失败反证：
证据强度：
建议状态：DISCOVERED / CANDIDATE / DEPRECATED
写入动作：更新已有变量 / 创建DISCOVERED变量 / 合并同义变量 / 废止
备注：
```

示例：

```text
变量编码：FV-03
变量名称：首屏反常识判断
变量大类：FV
适用题型：职场组织题
平台样本数：40
平台命中数：32
平台命中率：80%
成功样本：平台问题样本ID列表
失败反证：同题低赞回答ID列表
证据强度：B
建议状态：CANDIDATE
写入动作：更新已有变量FV-03的平台证据字段
备注：仅建议进入账号实验，不直接升级ACTIVE
```

## 账号验证升级规则

平台变量进入账号实验后，必须经过本账号数据验证，且验证结果只能回写同一变量记录。

```text
平台样本发现变量
↓
写入 production_variable_library.md
↓
账号实验
↓
按千阅读收益、互动率、收藏率、关注转化验证
↓
更新当前状态与生产触发权限
```

默认判断：

- 平台样本达到最低证据门槛：`DISCOVERED → CANDIDATE`。
- 账号连续 3 篇同向验证：`CANDIDATE → REVIEW`。
- 账号累计 10 篇同向验证，且收益表现稳定：`REVIEW → ACTIVE`。
- 失效、冲突、长期低于账号基准或已被替代：`DEPRECATED`。

成功口径优先级：

```text
千阅读收益 > 收藏率 > 评论率 > 关注转化 > 阅读量
```

## 日常生产边界

日常 Production Card 的内容变量只能读取 `production_variable_library.md`。

平台样本、失败样本和评论拆解不得直接进入日常生产。只有写入同一变量记录、完成账号验证，并在 `production_variable_library.md` 中标记为 `ACTIVE` 且触发资格=是后，才允许被 Production Card 触发并激活。

## 去重规则

变量名称相近时，优先合并证据。

只有定义、触发机制或行为结果明显不同，才允许拆为两个变量。

禁止因不同样本来源创建重复变量。
