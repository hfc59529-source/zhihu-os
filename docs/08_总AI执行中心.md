## 权威定位

本页是知乎系统 AI 调用协议的唯一权威。

它不存放知识结论，不替代变量库，不生成正文。

它只规定：

- AI 生产前读取什么。
- AI 生产中调用什么。
- AI 生产后检查什么。
- 不同模块之间如何分工。

## Codex 职责边界

Codex 在单篇生产前只负责选题采集与入库，到“形成可供生产的选题包”为止。

单篇选题采集固定读取并执行：

- `docs/Codex选题采集协议.md`
- `templates/选题包模板.md`
- `data/Topic_Pool.md`

Codex 不生成 Production Card，不提炼核心观点，不设计文章结构，不生成正文。选题包保存后，Codex 任务结束，等待 Claude 接管。

Codex 的长期职责是系统维护：

- 维护参数库。
- 维护知识库。
- 维护样本库。
- 维护参数调用日志。
- 在 GPT / 人工连续确认同类系统问题后，修复参数、Prompt 或调用规则。

系统维护固定读取并执行：

- `docs/Codex系统维护协议.md`
- `templates/参数调用日志模板.md`
- `data/parameter_call_log.md`

系统维护不得改正文，不得做单篇表达优化。

## 运行模式纪律

知乎OS默认进入日常生产模式。日常生产只负责产出可发布正文，不承担系统研发任务。

日常生产流程：

```text
问题
↓
主变量
↓
一句核心机制
↓
正文
↓
发布
↓
记录数据
```

日常生产最多检查三件事：有没有跑偏、有没有太像 AI、有没有实际收藏点。

日常生产过程中禁止修改协议、新增参数、优化 Prompt、重构 Notion，禁止把单篇问题直接升级成系统规则。

系统升级仅在以下任一条件满足时启动：

1. 连续 3 篇出现同一种问题。
2. 数据验证证明某个规律失效。
3. 新发现跨题型通用规律。

除此之外，一律禁止修改系统。系统升级必须遵守“先验证，再抽象”。

3. 结构库有可用 ACTIVE 结构。

没有同题 Top3 平台样本，不得单独阻塞日常 Production Card 生成。

## AI质量维度调度协议

正文生成前，调度器必须读取：

1. Production Card
2. 变量库中与当前唯一主变量和辅助变量相关的内容
3. 知乎内容质量参数库中满足以下条件的参数：
   - 是否默认：是
   - 适用于：知乎正文
   - 调用阶段：正文生成
   - 优先级：P1 / P2 / P3

调度器只加载参数，不解释参数，不新增参数，不改写参数。

质量参数调度前，必须先运行 `QT-QI｜问题理解系统`：

```text
L0 问题分类
↓
L1 用户问题解析
↓
L2 问题形成机制
↓
L3 路由参数
↓
L4 AI执行规则
↓
L5 验证指标
```

QT-QI 是上游识别层，负责判断问题类型、用户为什么问、需要怎样的答案形态，以及应调用或限制哪些 PD / RR / RE / BT。QT-QI 不替代变量库，不决定核心机制原文，不计入质量参数核心/辅助调用数量。

参数读取后必须按四组完成调用：

1. `PD｜推导深度`：负责现象、因果、机制、利益、权力、博弈、人性和认知升级。
2. `RR｜阅读体验`：负责认知负荷、信息密度、认知缓冲、阅读节奏、现实承接、阅读奖励、阅读疲劳检测和认知吸收校验。
3. `RE｜表达体验`：负责视觉块、停顿、呼吸感、新概念速度、AI痕迹、机械结构和真人观察感。
4. `BT｜行为转化`：负责阅读、收藏、评论、点赞、关注和分享的正文动作。

任一Claude 正文只调用 PD、不调用 RR、RE 或 BT，视为质量参数调用不完整，不得交给 Claude 正文生产节点。

### 质量参数调用规则

正式 Production Card 前必须读取质量参数库中满足以下条件的默认正文参数：

```text
是否默认=是；
适用于=知乎正文；
调用阶段=正文生成；
优先级=P1/P2/P3。
```

Production Card 只记录参数分层调用结果和 `本篇重点执行`。读取参数库不等于调用全部参数，禁止以“默认调用或条件触发”为理由判定全部参数均调用。

每篇必须明确区分强制底线参数、本篇核心调用参数、本篇辅助调用参数、本篇不调用参数。正文内容参数控制在 3-6 项，表达参数控制在 2-4 项。行为目标只允许设置 1 个主要目标、最多 1 个次要目标。QA 参数不计入正文调用数量，只在生成后和终检阶段执行。未调用参数必须明确记录原因。

`本篇重点执行` 只保留本题最关键的 5-10 条质量要求，例如推导深度、机制解释、利益分析、场景承接、阅读节奏、收藏驱动力、AI 痕迹控制、评论驱动力。

禁止把质量参数库的内部路由、评分标准、命中特征、未调用原因或审计过程写入 Production Card。

### PD 参数路由器

正式 Production Card 前必须先运行 PD 参数路由器。

路由器只根据题目特征命中参数，不允许人工凭感觉指定参数。

后台质量参数检查固定压缩为：

```text
强制底线参数：
本题重点检查：
本题辅助检查：
不进入Claude卡的参数：
行为目标：
结构实例化风险：
1.
2.
3.
```

本篇重点执行只写对当前题目最有约束力的质量要求，不写路由过程。
- 哪些 PD 调用了但效果不好。
- 哪些 PD 应该升级、降级、合并或废弃。

## 规则升级权限

任何生产问题不得直接升级为总 Prompt 规则。

新增规则前必须先判断 `Rule Type × Scope`。

```text
Rule Type：
Action / Structure / Mechanism / Expression / Opinion / Evidence

Scope：
Global / Topic / Card / Hypothesis
```

执行路由：

```text
Action + Global → 总协议 / 正文 Prompt / 通用 QA
Action + Topic → 对应题型结构 / 题型参数
Mechanism + Topic → 候选规律，验证后才可进入 ACTIVE
Opinion + Card → 本题 Production Card
Evidence + Card → 本题证据或历史弱参考
无法判断 → HYPOTHESIS，不进入正式生产调用
```

总协议只固化通用动作，不固化单题答案。

题型能力只固化该题型反复成立的判断动作。

本题策略只能留在 Production Card，不得进入总 Prompt、通用 QA 或全局参数。

`HYPOTHESIS` 是候选规则，不是正式规则。必须等待多篇样本验证后，才允许申请进入题型能力或 ACTIVE 规律。

## 禁止事项

- 禁止把质量维度规则直接塞进 Skill006。
- 禁止 Skill006 理解或创作质量规则。
- 禁止绕过质量参数库直接修改 Prompt。
- 禁止质量参数库新增变量。
- 禁止质量参数库修改 Production Card 结构。
- 禁止正文模型自行决定读取文件。
- 禁止把单篇正文失败中的本题机制、本题表达或本题答案升级为全局规则。
