# 系统治理原则

版本：GOVERNANCE-PRINCIPLE-V1.5

状态：ACTIVE（这是原则，不是协议；不占用协议冻结期）

## 与"生产审计决策流程 V1.0"的关系

[生产审计决策流程 V1.0](生产审计决策流程.md) 已冻结，连续跑 10 篇期间不新增节点、不改职责、不改协议。

本文件记录的不是流程节点，而是**修改流程时必须遵守的前置条件**，以及**10 篇结束后的固定复盘节点**。两者层级不同：协议管"怎么生产"，本文件管"什么时候、凭什么可以改生产方式"。

## 原则一：Evidence Driven（证据驱动）

任何协议修改，必须先回答两个问题：

```text
为什么改？
证据是什么？
```

反例（不构成升级理由）：
- "我觉得这样更合理"
- "以前一直这样，感觉该调整了"

正例（构成升级理由）：
```
为什么改？
发现 Default Ranking ≠ Upvote Ranking。

证据是什么？
知乎真实页面对比。
```

没有证据，协议不升级。前 10 篇 Production 期间，即使发现协议本身有问题，也先记录证据，不立即改协议，统一在 ZH-MILESTONE-010 复盘时处理（除非同一类问题在第 7 篇前重复暴露，触发生产审计决策流程 V1.0 里已经写好的例外条款）。

## 原则二：Production Card 冻结的是认知目标，不是固定句式

**Semantic Target ≠ Literal Target。**

Production Card 中的"核心反转句"等字段规定的是**认知目标**——读者读完后必须获得的判断，而不是必须逐字出现的句子。审核时验证标准是**语义一致**，不是**字面一致**。

例：Card 规定核心反转句"这不是任务回来了，是风险换了个包装回来了"。只要正文能让读者明确得到"别人交给你的不是机会，而是风险"这个认知，无论具体怎么措辞（"风险只是换了一层包装""真正交到你手里的不是机会""接回来的往往不是项目，而是历史问题"……），都算兑现 Card，不需要逐字还原。

**为什么加这条**：机械要求逐字复现会让 Production Card 退化为模板填空，抹杀 Claude/Codex 在具体表达上的空间，长期会让所有产出的首屏句式趋同，反而制造新的规整化风险。

**如何应用**：Audit 阶段发现"正文与 Card 措辞不同"，不能直接判定为不一致；必须先判断认知/判断本身是否传达到位，再决定是否构成 Issue。（首次应用见 ZH-20260801-003 Decision_Log.md Issue-01）

## 原则三：零 Issue 也是合法结果

**Audit ↓ Issue = 0 ↓ 直接 Final Validation ↓ Release**，不强制每篇都必须走 Audit → Issue → Patch。

Draft 干净、无可归入七类证据标准的问题，不代表 Audit 没做，代表 Production 阶段这次一次通过。**不要求 Claude 为了证明审计"有价值"而制造一个 Issue**——这是很多编辑流程会退化出的通病，审计者为了自证存在感，倾向于"改一点"。

**为什么加这条**：ZH-20260801-004 是首个 Clean Pass 样本（Audit 未发现 Issue，GPT Final Validation 直接 PASS，Draft-v1.md 本身即为 Release 依据，无需生成 Article-Patched 版本）。这证明 Production 阶段本身可以一次通过，不是所有文章都必须经过 Patch。

**理想分布（假设，待 10 篇验证）**：约 70% Draft 直接 Release，约 30% Draft 经 Patch 后 Release。如果比例走向 100% 都需要 Patch，说明 Production 阶段（Codex）在退化，应回头检查 Codex 生成质量，而不是继续加强 Audit/Patch 环节。

**统计口径**：Production Ledger 新增 Audit Result 列（Issue / Clean Pass），供 ZH-MILESTONE-010 统计 Clean Pass 率、平均 Issue 数、Patch 率、Final Validation 通过率。

## 原则四：做信息隔离，不做对象膨胀

系统新增能力时，优先修改已有对象的规则，不新增平行对象。

默认修改字段，禁止新增对象。只有当现有对象无法表达，且连续多个案例证明字段无法承载时，才允许新增对象。

新增对象前必须先回答：

```text
能不能放进已有对象？
能不能通过新增字段表达？
能不能通过修改触发条件、禁用边界、状态或权重解决？
```

当前固定三类承载：

| 承载对象 | 保存内容 | 禁止内容 |
|---|---|---|
| `production_variable_library.md` | 已验证、已生效的正式参数规则 | 审核阶段刚发现的问题、未验证假设 |
| `data/Milestone_Observations.md` | 待判断问题、平台验证过程、最终结论 | 直接修改后的正式参数 |
| 参数库内简洁变更日志 | 参数为什么改、从哪个 Observation 改、改了什么 | 独立 Evidence 系统、独立 Change Log 系统 |

执行边界：

1. 审核发现问题，只写 Observation。
2. 未完成平台验证，不改正式参数。
3. 验证结果不支持，Observation 关闭，不进入参数库。
4. 验证结果支持，才修改对应参数字段。
5. 每次参数修改必须关联 Observation ID。
6. 不新增独立 Trigger、Evidence、Change Log 系统。

最终闭环：

```text
生产
↓
审核
↓
Observation
↓
平台验证
↓
参数修改判断
↓
更新参数库
↓
记录变更
```

## 原则五：状态报告只报事实

Codex 在生产、审核、发布链路中的收口输出必须像流水线状态报告，只报告事实，不做项目复盘、不做价值评价、不扩展建议。

禁止输出：

- 今天最大的成果
- 这比单纯完成一篇文案更有价值
- 第一次完成某某闭环
- 建议新增审核原则
- 与当前节点无关的阶段复盘

统一输出格式：

```text
当前状态：
READY_FOR_XXX

已完成：
✓ ...

未完成：
□ ...

阻塞项：
...

下一步：
...

下一步责任人：
...
```

状态命名必须区分“已完成”和“等待执行”。例如：

- `READY_FOR_BODY_GENERATION` 表示等待正文生产，不表示正文已生成。
- `BODY_GENERATED` 表示正文已生成。
- `READY_FOR_AUDIT` 表示等待审核。
- `READY_FOR_LINK_REPLACEMENT` 表示等待真实链接替换。
- `READY_FOR_RELEASE` 表示发布前所有阻塞项已清空。

## 原则六：单一事实来源

任何内容知识只能存在于一个权威位置。系统允许多个对象协作，但不允许多个对象同时维护同一类内容规则。

| 内容 | 唯一权威 |
|---|---|
| 正文结构、核心判断、场景要求、禁用边界、收尾要求 | Production Card |
| 正文模型执行边界 | Claude Executor Prompt |
| 生产状态、角色交接、发布顺序 | 流程文档 |
| 程序化校验规则 | Validator / QA 协议 |
| 参数定义、变量状态、验证证据 | 参数库 / 变量库 |

治理规则：

1. Production Card 是正文阶段唯一内容权威。
2. Prompt 只允许承载执行边界，不得承载内容知识、历史参数、推理模型或正文结构。
3. QA 只检查正文是否符合 Production Card，不得引用 Production Card 之外的历史参数体系作为内容标准。
4. Release 只记录 Production Card Version、Audit Result、Validation Result 和 Release Decision，不得重新引入旧参数版本或旧协议版本作为发布依据。
5. 如果同一条内容知识同时出现在两个对象中，视为需要治理；优先保留权威对象，删除或降级非权威对象。

目标链路：

```text
Production Card
↓
Executor Prompt（只执行，不解释内容）
↓
正文
↓
QA（只审 Card 一致性）
↓
Release
```

## 系统当前的三层结构

| 层级 | 内容 | 状态 |
|---|---|---|
| 生产层 | 知乎问题 → Top3 平台样本 → Production Card → Draft → Audit → Decision → Release | 已稳定，可连续生产 |
| 研究层 | Top3 样本来源拆分为 Default / Upvote / Latest（不再混用"高赞=平台样本"） | 本轮新稳定 |
| 参数层 | Observation → 平台验证 → 参数修改判断 → 参数库回写 | 只改已有权威对象，不新增平行系统 |

## 里程碑：ZH-MILESTONE-010

固定复盘节点，在第 10 篇 Production 完成后触发。只做四件事：

1. **参数治理**：哪些 Candidate 参数连续出现，哪些只是偶然
2. **流程复盘**：Audit 提出的问题里，重复率最高的是哪几类，是否说明 Production 阶段存在固定短板
3. **Top3 采样效果分析**：Default Top3 训练出的文章，是否比 Upvote Top3 更接近知乎真实分布
4. **生产质量趋势分析**：Production Card 是变短了还是变复杂了

**在 ZH-MILESTONE-010 之前，禁止改协议**，只允许按 Evidence Driven 原则记录证据。
