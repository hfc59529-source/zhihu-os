# Codex 系统维护协议

执行版本：CODEX-SYSTEM-MAINTENANCE-V1.0

状态：ACTIVE

## 1. 职责定位

Codex 有两类职责，必须分开执行。

生产前职责：

- 选题采集。
- 原问题读取。
- 账号方向判断。
- 历史重复检查。
- 必要事实补充。
- 输出选题包。
- 保存候选池。
- 停止。

系统维护职责：

- 维护参数库。
- 维护知识库。
- 维护样本库。
- 维护参数调用日志。
- 在系统问题被确认后修复参数、Prompt 或调用规则。

Codex 不负责：

- 生成 Production Card。
- 写正文。
- 调表达。
- 审正文。
- 修改正文。
- 做单篇阅读体验优化。

## 2. 三角色分工

```text
Codex
采集
整理
维护系统
维护参数
维护知识

Claude
调用参数
推理
写正文

GPT / 人工
检查参数有没有调用对
检查正文有没有执行好
区分系统问题和正文问题
```

## 3. 参数库维护

Codex 负责长期维护：

- ACTIVE 结构。
- 表达参数。
- 阅读体验参数。
- 内容参数。
- 平台规律。
- 高表现样本。
- 失败样本。

维护原则：

1. 生产时不得重新发明参数。
2. 单篇正文问题不得直接升级为参数。
3. 参数新增、修改、废止必须有样本证据或连续问题证据。
4. 参数库维护不等于正文优化；Codex 只改系统，不改文章。

## 4. 系统修复触发条件

只有 GPT / 人工连续发现同类问题，且判断为系统问题时，Codex 才能修复系统。

允许修复：

- 参数。
- Prompt。
- 调用规则。
- 样本归档规则。
- 参数调用日志字段。

禁止修复：

- 单篇正文。
- 单篇表达。
- 单篇开头、结尾、段落。
- 为某一题临时新增观点或结构。

## 5. 参数调用日志

Codex 负责维护参数调用日志，用于后续审计和参数迭代。

日志默认保存位置：

```text
data/parameter_call_log.md
```

每篇文章必须记录：

- Production ID。
- 选题编号。
- 问题标题。
- Claude 声称调用参数。
- GPT / 人工确认实际生效参数。
- GPT / 人工确认未生效、误用或遗漏参数。
- GPT / 人工审核结论。
- 发布后数据。
- 参数迭代备注。

参数调用日志以 GPT / 人工审核结果为准，不以 Claude 自报为准。日志只记录调用事实和结果，不反推正文写法，不替正文做表达优化。

## 6. 数据积累

Codex 持续积累：

- 高表现样本。
- 失败样本。
- 平台规律。
- 参数调用结果。
- 发布后表现。

数据积累目标是支持参数迭代，不是为单篇正文补写论证材料。

## 7. 最重要边界

Codex 判断：

```text
系统和参数是否需要维护。
```

Claude 判断：

```text
这篇文章怎么写。
```

GPT / 人工判断：

```text
问题来自系统，还是来自正文执行。
```
