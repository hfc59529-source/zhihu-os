# 知乎正文推理协议（Reasoning Protocol）V1.0

Status：ACTIVE

## 协议定位

本协议位于 Production Card 与 Claude 正文生产 Prompt 之间。

```text
Production Card
↓
知乎正文推理协议 V1.0
↓
Claude 正文生产 Prompt
↓
正文
```

本协议只约束 AI 的正文生成前推理过程。

它控制：

- 如何判断。
- 如何建立因果。
- 如何提出观点。
- 如何生成概念。

它不控制：

- 写什么。写什么由 Production Card 决定。
- 怎么说。怎么说由表达协议决定。
- 正文结构。正文结构由结构库和 Production Card 决定。

## Rule 01｜禁止伪反常识

目的：防止 AI 为了制造冲突而制造冲突。

任何反常识观点必须同时满足：

- 现实能够成立。
- 可以举出现实场景。
- 本质解释比传统解释更完整。

禁止为了吸引注意故意制造以下表达关系：

- 不是 A，而是 B。
- 相反关系。
- 完全不是。
- 全部都是。
- 永远如此。

如果只是表达技巧，不属于认知升级。

## Rule 02｜禁止绝对化推理

正文所有判断必须经过：

```text
判断
↓
成立条件
↓
边界条件
↓
反例检查
```

错误：

```text
领导都会……
```

正确：

```text
很多领导在以下条件下……
```

出现以下绝对化词，必须自动降级并重新检查：

- 一定。
- 全部。
- 永远。
- 必然。

## Rule 03｜概念预算

一篇正文的概念预算：

| 概念层级 | 数量上限 |
| --- | --- |
| 一级核心概念 | <= 1 |
| 二级概念 | <= 3 |
| 三级概念 | <= 5 |

新增概念必须回答：

- 是否真的提高理解。
- 是否已有旧概念可以表达。

如果不能提高理解，禁止新增。

例如：

- 资源账户。
- 信号模式。
- 岗位锁定。

如果多个概念表达同一件事，只保留一个。

## Rule 04｜现实优先

任何场景必须优先符合现实发生概率高，而不是理论上能够解释。

场景判断分为：

- 高频。
- 中频。
- 低频。

只有高频场景允许作为正文主案例。

中频场景只能作为辅助说明。

低频场景不得作为正文主案例。

## Rule 05｜机制优先

正文禁止直接下结论。

必须遵守以下推理链：

```text
现象
↓
机制
↓
利益关系
↓
行为结果
↓
结论
```

禁止用价值判断代替机制。

## Rule 06｜角色一致性

不同主体只能按自身目标推理：

- 领导只能按领导目标推理。
- 员工只能按员工目标推理。
- 组织只能按组织目标推理。

禁止：

- 让领导站在员工角度思考。
- 让员工拥有组织信息。
- 让组织像具体个人一样产生情绪。

## Rule 07｜因果检查

每个观点必须先回答：

```text
为什么？
```

每个为什么必须继续追问：

```text
为什么？
```

直到不能继续解释。

正文只保留最后一层机制，不展示推理过程。

## Rule 08｜AI味过滤

出现以下语言时，必须自动检查是否只是语言增强：

- 本质就是。
- 说白了。
- 归根结底。
- 真正的。
- 不是……而是……。
- 组织不会……。
- 领导都会……。

如果没有新增信息，删除。

## Rule 09｜传播真实性

每一句必须满足：

```text
真实 > 有力量
```

不是：

```text
有力量 > 真实
```

知乎首先相信，其次传播。

## Rule 10｜最终校验

正文生成完成后，必须自动检查：

1. 有没有伪反常识。
2. 有没有绝对化。
3. 有没有新增垃圾概念。
4. 有没有低概率案例。
5. 有没有机制缺失。
6. 有没有 AI 金句。
7. 有没有角色越界。

全部通过，正文完成。

任一项不通过，返回 Claude 正文生产 Prompt 重新推理并生成正文。

## 系统边界

本协议只约束 AI 推理。

不得新增正文结构。

不得新增当前 `templates/Production Card模板.md` 之外的 Production Card 字段。

不得修改表达协议。

不得修改结构库。

不得修改参数库。

仅作为正文生成前的推理约束层。
