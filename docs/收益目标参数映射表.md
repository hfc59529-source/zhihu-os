## 核心架构

```
Monetization Goal（收益目标）
  ↓
  决定了哪些参数要优先强化
  ↓
Primary Behavior Goal（行为目标）
  ↓
  决定了用户需要产生什么行为
  ↓
Content Mechanism（内容机制）
  ↓
  决定了正文必须出现什么
```

---

## 基础参数（全文必须 PASS）

任何收益目标都不能牺牲。

| 维度 | 检查内容 | PASS 标准 |
|------|---------|---------|
| 问题回应 | 正文是否真正回答了提问？ | 主线始终围绕提问核心 |
| 推理完整 | 因果链是否成立？ | 至少 3 层推导，终点明确 |
| 阅读顺畅 | 用户是否能不掉队？ | 无被动语态堆砌、无跳跃式转折 |
| 可信度 | 是否有事实支撑？ | 具体场景或例子，无绝对表述 |

## 收益目标映射表

### 收益目标 1：阅读收益（广告/致知）

**商业模式**
- 广告依赖阅读量、停留时间、页面访问
- 致知产品依赖完读率、互动率

**最终收益指标**
- 阅读量（PV）
- 停留时间
- 完读率
- 互动（点赞+评论+收藏）

**需要的用户行为链**
```
点击进来 → 决定继续读 → 完读 → 互动
```

**关键转化点**
- 首屏 100 字：决定继续读或离开
- 中段 200 字：决定坚持到底还是中途退出
- 结尾 100 字：决定是否互动

**重点强化参数**

| 参数 | 强化理由 | 实现方式 |
|------|--------|--------|
| **首屏留存** | 高 | 核心困惑/反差在 150 字内呈现 |
| **阅读推进** | 高 | 每一段都有续读动力，不能有知识断层 |
| **完读率** | 高 | 结尾回收，不要提前结束 |
| **互动触发** | 中高 | 留下可讨论的点或情绪共鸣 |
| **题目热度** | 中 | 选题要有搜索热度或讨论度 |
| **题目匹配** | 中 | 确保正文直击题目核心 |
| **情绪感染** | 中 | 情绪流畅，易于代入 |
| **框架复用** | 低 | 不是主目标 |
| **可信度深度** | 中 | 足够的例子，但不需要数据堆砌 |

**禁止牺牲**
- 阅读顺畅：任何复杂都会降低完读率
- 题目回应：漂移题目会影响搜索引流

**行为目标通常是**
- 点开 + 完读 + 互动（点赞或评论）

### 收益目标 2：咨询转化

**商业模式**
- 通过专业能力展示，引导用户咨询或付费指导

**最终收益指标**
- 咨询数量
- 咨询质量（意向程度）
- 付费转化率
- 客户单价

**需要的用户行为链**
```
理解问题 → 认可专业性 → 关注 → 进一步咨询
```

**关键转化点**
- 第 1 段：准确诊断用户问题
- 第 2-3 段：展示问题解决的复杂性（引出需要咨询）
- 第 4 段：展示作者专业能力和经验
- 第 5 段：明确咨询价值和可能的后续合作方向

**重点强化参数**

| 参数 | 强化理由 | 实现方式 |
|------|--------|--------|
| **问题诊断** | 高 | 准确指出用户的真实问题，不是表面问题 |
| **专业差异** | 高 | 展示与其他答案不同的专业洞察 |
| **信任感建立** | 高 | 通过经验、案例、理解深度建立信任 |
| **留有空间** | 高 | 不要把所有答案都给，暗示咨询能得到更深入指导 |
| **用户被理解** | 高 | 让用户感到被准确理解，不是套话 |
| **可信度** | 中高 | 具体案例，但不需要数据 |
| **推理深度** | 中高 | 深度推理能建立专业感 |
| **阅读顺畅** | 中 | 复杂可以接受，但不能难懂 |
| **框架可复用** | 低 | 不是主目标 |
| **互动触发** | 低 | 不是主目标 |

**禁止牺牲**
- 问题回应：错误诊断没有咨询价值
- 可信度：无法建立信任，没有转化

**行为目标通常是**
- 关注 + 私信咨询

### 收益目标 3：好物带货

**商业模式**
- 通过产品推荐获得佣金或直接销售

**最终收益指标**
- 点击率
- 购买率
- 转化价值

**需要的用户行为链**
```
发现需求 → 认同该产品解决 → 信任质量 → 点击购买
```

**关键转化点**
- 第 1 段：准确识别用户潜在需求
- 第 2 段：解释为什么这个需求值得解决
- 第 3 段：介绍产品如何满足需求
- 第 4 段：消除购买顾虑（价格、质量、后悔）
- 第 5 段：清晰的购买入口和理由

**重点强化参数**

| 参数 | 强化理由 | 实现方式 |
|------|--------|--------|
| **需求识别** | 高 | 准确指出用户可能有的未被满足的需求 |
| **使用场景** | 高 | 具体场景展示产品如何解决问题 |
| **风险降低** | 高 | 消除购买顾虑（非必需、低质量、被坑）|
| **对比决策** | 中高 | 为什么选这个而不是其他，但不贬低竞品 |
| **购买理由** | 中高 | 清晰的理由支撑购买决策 |
| **可信度** | 中高 | 真实体验或用户反馈 |
| **行动入口** | 中 | 链接清晰、易于点击 |
| **题目匹配** | 中 | 产品要真的解决题目问题 |
| **推理完整** | 中 | 逻辑通顺，不是强行推荐 |
| **情绪感染** | 低 | 理性决策为主 |

**禁止牺牲**
- 可信度：低信任没有转化
- 需求识别：推荐的产品要真的有用

**行为目标通常是**
- 点击链接 + 购买

### 收益目标 4：产品付费（盐选/数字产品）

**商业模式**
- 通过专业内容或深度产品吸引用户付费购买

**最终收益指标**
- 购买数
- 转化率
- 客户获取成本

**需要的用户行为链**
```
发现内容价值 → 想要深入了解 → 确认值得付费 → 购买
```

**关键转化点**
- 第 1-2 段：唤起对问题的重视
- 第 3 段：展示浅层答案不够
- 第 4 段：暗示付费产品能提供什么
- 第 5 段：收藏价值 + 付费指引

**重点强化参数**

| 参数 | 强化理由 | 实现方式 |
|------|--------|--------|
| **内容深度** | 高 | 免费部分要有见地，但留有空间 |
| **框架价值** | 高 | 呈现可结构化的知识或方法 |
| **稀缺性** | 中高 | 强调这类知识/方法的稀缺性 |
| **收藏价值** | 中高 | 长期可复用的内容 |
| **专业可信度** | 中高 | 作者能力和品质 |
| **付费理由** | 中 | 为什么值得付费（节省时间、更系统等）|
| **推理完整** | 中 | 逻辑清晰，不是碎片 |
| **可信度** | 中 | 内容有基础支撑 |
| **阅读顺畅** | 中 | 深度可以，但要易懂 |
| **情绪感染** | 低 | 不是主目标 |

**禁止牺牲**
- 内容深度：浅显没有付费价值
- 框架价值：碎片化内容没有结构价值

**行为目标通常是**
- 收藏 + 关注 + 购买

### 收益目标 5：账号积累（长期资产）

**商业模式**
- 通过稳定输出和粉丝积累，建立作者品牌和商业价值

**最终收益指标**
- 粉丝数增长
- 粉丝质量（活跃度、付费倾向）
- 粉丝LTV（生命周期价值）

**需要的用户行为链**
```
认可内容 → 产生持续预期 → 关注 → 长期消费 + 未来付费
```

**关键转化点**
- 整篇：一致的风格和品质
- 结尾：明确的作者立场或持续承诺

**重点强化参数**

| 参数 | 强化理由 | 实现方式 |
|------|--------|--------|
| **认知深度** | 高 | 提供大多数人没想到的洞察 |
| **可信度稳定** | 高 | 每个判断都有充分支撑，不轻易反转 |
| **判断稳定性** | 高 | 不翻车、不自相矛盾 |
| **风格一致** | 中高 | 这篇与之前内容有明确的风格认可 |
| **持续价值预期** | 中高 | 读完后期待下一篇 |
| **专业差异** | 中 | 展示持续的专业能力 |
| **推理完整** | 中 | 严谨的思考过程 |
| **情绪真实** | 中 | 不是冷冰冰的，有真实的态度 |
| **多角度性** | 低 | 可以有强立场 |
| **框架可复用** | 低 | 不是主目标 |

**禁止牺牲**
- 推理完整：不严谨会伤害可信度
- 可信度：错误会伤害长期资产

**行为目标通常是**
- 关注 + 持续阅读

## 行为目标的用途

同一个行为目标，在不同收益目标下，其优先级和实现方式完全不同。

**例子：关注**

| 收益目标 | 关注优先级 | 为什么要关注 | 强化点 |
|---------|---------|-----------|--------|
| 阅读收益 | 低 | 获得推荐权重 | 互动 > 关注 |
| 咨询转化 | 高 | 进一步沟通入口 | 专业信任 + 未来可咨询 |
| 好物带货 | 低 | 长期导流 | 购买 > 关注 |
| 产品付费 | 中 | 长期消费者 | 内容粘性 |
| 账号积累 | 高 | 核心目标 | 持续价值预期 |

## 参数调用规则

1. **先确定 Monetization Goal**
   - 只能一个
   - 决定了所有后续的参数调度

2. **再确定 Primary Behavior Goal**
   - 为了实现收益目标，需要用户产生什么行为
   - 可以有多个中间行为，但主要 Goal 只有一个

3. **基础参数检查（前置）**
   - 所有 Goal 都必须检查
   - 任何一项 FAIL，整体 FAIL

4. **收益参数检查（后续）**
   - 根据 Monetization Goal 查表
   - 强化理由"高"的参数必须 PASS
   - 强化理由"中"的参数也需要 PASS
   - 强化理由"低"的参数不是主审核，但也不能完全缺失

5. **禁止牺牲项检查**
   - Production Card 中勾选的"禁止牺牲项"必须在正文中真正体现
