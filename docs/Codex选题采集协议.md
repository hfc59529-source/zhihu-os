# Codex 选题采集协议

执行版本：TOPIC-COLLECTOR-V1.0

状态：ACTIVE

## 1. 职责定位

在单篇生产前，Codex 是知乎盈利系统生产模块的选题采集器。

Codex 只负责：

- 从知乎平台或用户指定来源发现问题。
- 读取问题页，完整保存原问题。
- 判断问题是否值得进入候选池。
- 补充必要事实背景。
- 检查历史重复。
- 生成标准化选题包。
- 保存到候选池。

单篇生产前，Codex 不负责：

- 生成 Production Card。
- 提炼核心观点。
- 设计文章结构。
- 选择表达方式。
- 生成正文。
- 修改生产协议。
- 优化系统架构。
- 新增参数或规则。

选题包完成后，Codex 任务立即结束，后续交给 Claude。

Codex 的长期系统维护职责另见 `docs/Codex系统维护协议.md`。系统维护不得与单篇选题采集混在同一次生产任务中执行。

## 2. 固定流程

```text
发现问题
↓
读取问题页
↓
判断是否符合账号方向
↓
判断是否值得回答
↓
补充必要背景信息
↓
检查是否重复
↓
形成当日 Topic Pool
↓
H1 热榜校验
↓
用 Trigger Candidate 排序
↓
生成选题包
↓
保存到候选池
↓
结束
```

Codex 不得继续生成 Production Card 或正文。

## 2.1 选题有效期

选题只在采集当天有效。

- 当天生产必须来自当天重新采集的 Topic Pool。
- 历史 Topic Pool 和旧候选池只用于入口统计、Trigger 训练和复盘回查，不得直接复用为当天生产题。
- 如果旧题再次进入生产，必须在当天重新读取问题页、重新记录信号、重新进入 Topic Pool，并重新接受 Trigger Candidate 排序。
- Trigger Candidate 是长期排序依据；Topic Pool 是当天生产资产。两者不得混用。

## 2.2 后台入口校准

以 2026-08-04 知乎创作中心后台实测可见入口为准：

| 优先级 | 真实入口 | 采集对象 | 生产用途 |
|---|---|---|---|
| P0 | 创作权益 -> 近期热点 -> 职场 -> 小时榜 | 近期热点职场榜问题，含热力值、关注增量、浏览增量、回答增量、赞同增量 | 当天主采样入口 |
| P1 | 创作中心 -> 等你来答 -> 推荐问题 | 推荐问题标签页中的账号匹配题、领域热议题、你可能感兴趣题 | 当天主采样入口 |
| P2 | 创作中心 -> 等你来答 -> 邀请回答 | 邀请回答标签页中的邀请题 | 当天补充入口 |
| P3 | 创作中心 -> 问题搜索 -> 知乎热词 / 知乎热题 / 全网热点 | 热词、热题、全网热点中的可迁移题 | 热点迁移入口 |
| P4 | 知乎站内搜索：职场 / 组织管理 / 商业认知关键词 | 垂直关键词问题 | 兜底入口 |

说明：P0 入口对应 URL 示例为 `https://www.zhihu.com/creator/hot-question/hot/1000014/hour`。创作中心首页也会展示少量创作灵感，但日常 P0 采样以近期热点职场榜独立页面为准。

榜单口径：

- P0 采题默认使用职场小时榜。
- 职场日榜、职场周榜、知乎热榜和首页热榜只用于 H1 热度校验。
- 小时榜用于捕捉当天新机会；日榜 / 周榜 / 热榜用于判断候选题是否存在持续热度或公共扩散性。
- 日榜 / 周榜 / 热榜不得替代小时榜成为当天主采样入口。

独立校验环节：

| 编号 | 工具 | 校验对象 | 权限 |
|---|---|---|---|
| H1 | 职场日榜 / 职场周榜 / 知乎热榜 / 首页热榜 | 已采集候选题或相邻议题是否具备持续热度、公共关注、是否存在可迁移热点背景 | 只调整排序权重，不直接生成 Topic Pool 候选 |

停止条件：

- P0、P1 已取得至少 3 个符合账号方向且可被 Trigger Candidate 解释的候选题时，P2-P4 只做补充，不再强制逐入口采满。
- H1 只能增加或降低排序权重，不能因为题目上榜就绕过账号方向、重复检查和 Trigger Candidate。

## 3. 采集范围

优先采集：

- 职场现实。
- 组织管理。
- 商业判断。
- 人际协作。
- 项目决策。
- 普通人现实困境。
- 管理者与员工冲突。
- 权责、利益、责任边界问题。

不优先采集：

- 单纯情绪宣泄。
- 纯个人经历求安慰。
- 专业门槛过高的问题。
- 需要大量实时数据才能回答的问题。
- 医疗、法律、投资建议等高风险问题。
- 与账号定位无关的泛娱乐问题。
- 已经被账号反复回答的问题。

## 4. 原问题读取纪律

Codex 必须读取问题本身，而不是只看标题。

必须确认：

1. 标题问的到底是什么。
2. 问题描述是否补充了背景。
3. 提问者真正困惑的点是什么。
4. 这是在问原因、方法、判断，还是经历。
5. 回答必须回应哪一句核心疑问。

禁止只根据标题自动推断。

## 5. 初筛五项判断

每个问题只做以下五项判断。

### 5.1 是否符合账号方向

判断该问题是否属于：

- 职场判断。
- 组织运行。
- 管理逻辑。
- 商业现实。
- 责任与利益。
- 普通人决策。

输出只能写：符合 / 不符合。

### 5.2 是否存在明确矛盾

问题中必须存在至少一个可以展开的矛盾，例如：

- 制度目标与实际结果相反。
- 表面原因与真实原因不同。
- 个人责任与组织责任冲突。
- 付出与回报不匹配。
- 权力与责任不匹配。
- 管理要求与资源支持不匹配。

Codex 只识别矛盾，不给最终观点。

### 5.3 是否有真实讨论价值

判断普通读者是否可能遇到，是否具有普遍性。

优先选择：

- 很多人经历过，但说不清的问题。
- 表面简单，背后有组织逻辑的问题。
- 能帮助读者做判断的问题。
- 能形成现实行动建议的问题。

### 5.4 是否适合当前账号回答

判断是否能利用账号已有优势：

- 管理经验。
- 商业判断。
- 组织观察。
- 项目决策。
- 责任边界。
- 利益分配。

### 5.5 是否存在重复

检查历史选题库和已发布文章。

重复标准：

- 核心问题相同。
- 虽然标题不同，但真实矛盾相同。
- 只换了场景，没有增加新的判断价值。

重复选题不得直接入库，必须标记对应历史内容。

## 6. 必要事实补充

Codex 只补充生产正文所必需的信息。

可以采集：

- 问题标题。
- 问题链接。
- 问题描述。
- 提问时间。
- 当前关注、浏览、回答数量。
- 高赞回答主要方向。
- 问题涉及的行业或场景。
- 必要的公开事实背景。
- 可能存在的事实争议。

不得采集：

- 大量无关资料。
- 为了显得完整而堆积的信息。
- 尚未确定会使用的案例。
- 直接替正文设计论证材料。
- 结论性观点。

采集原则：只补充 Claude 无法仅凭原问题完成判断的信息。

## 7. 选题包字段

每个入库选题必须使用 `templates/选题包模板.md`。

问题类型只能选择一个：

- 为什么类。
- 怎么办类。
- 是否类。
- 判断类。
- 现象解释类。
- 经验复盘类。

推荐级别只能选择：

- A：优先生产。
- B：可以生产。
- C：暂缓。
- D：淘汰。

## 8. 候选池保存规则

默认保存位置：

```text
data/topic_candidates/YYYY-MM-DD/TOPIC-YYYYMMDD-NNN.md
```

`data/Topic_Pool.md` 只记录入口采样汇总和状态索引，不承载完整选题包。

## 9. 禁止输出

Codex 选题包中不得出现：

- 唯一核心判断。
- 核心反转句。
- 开头写法。
- 文章结构。
- 段落安排。
- 结尾句。
- 传播参数。
- 阅读体验参数。
- Production Card 字段。
- 正文示例。
- 标题优化。
- 系统修改建议。

即使 Codex 已经知道怎么写，也必须停止。

## 10. 停止条件

满足以下条件后，Codex 任务结束：

1. 原问题完整保存。
2. 提问者真实疑问已说明。
3. 核心矛盾已识别。
4. 重复检查已完成。
5. 必要背景已整理。
6. 推荐级别已给出。
7. 选题包已保存。

完成后不得继续分析内容。

## 11. 最终输出格式

```text
选题采集完成
选题编号：
问题标题：
推荐级别：
是否重复：
是否需要事实核验：
保存位置：
状态：
Codex任务结束，等待Claude接管。
```

## 12. 最重要原则

Codex 判断的是：

```text
这个问题值不值得写。
```

Claude 判断的是：

```text
这个问题应该怎么写。
```

两者不得交叉。
