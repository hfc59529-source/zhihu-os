# 知乎OS执行协议

执行版本：ZH-RUNTIME-V3.0-TEACHER / TOPIC-COLLECTOR-V1.1

## 1. 强制执行原则

## 0.0 Codex 执行边界

Production Card 已退出 Codex 日常生产主链。Skill006、Skill007、Card 校验、Claude 版 Production Card、正文推理校验、正文 QA、Patch Validation 和 Release 均不得由 Codex 在单篇任务中执行。

```text
Codex 选题包
↓
Claude 消费 Topic Package 并推理
↓
Claude 生成正文
↓
GPT / 人工固定清单审核
↓
GPT / 人工确认实际生效参数
↓
Codex 写入参数调用日志
```

知乎盈利系统有两个入口：

1. 用户输入型：用户上传知乎选题截图、问题截图、回答截图，或给出一个知乎选题。
2. 系统自采型：Codex 从知乎首页、创作中心推荐问题、邀请回答、问题搜索、创作榜单等入口采集候选，并推荐一题。

两个入口只影响选题来源，不改变 Codex 的职责边界。Codex 默认只执行选题采集与入库，到“形成可供生产的选题包”为止。

用户输入型必须执行以下流程：

1. 截图识别
2. 选题提取（必须同时保存题目原文和真实知乎问题链接）
3. 读取原问题和问题描述
4. 选题初筛
5. 必要事实补充
6. 历史重复检查
7. 生成标准选题包
8. 保存到候选池
9. 停止，等待 Claude 接管

系统自采型必须先执行：

```text
知乎入口采集
↓
候选池整理
↓
输出 Daily_Topic_Top3
↓
选题准入判断
↓
采集正式候选题 Answer_Benchmark_Top3
↓
现有观点覆盖分析
↓
现有参数命中检查
↓
参数缺口记录（待审核）
↓
生成标准 Topic Package
↓
保存到候选池
↓
停止
```

选题包完成后，Codex 不得继续执行历史资产压缩、ACTIVE 老师结构实例化、ACTIVE 规律回流、后台质量参数检查、Production Card 校验、正文生产、正文 QA、Patch、Validation 或 Release。正文生产由 Claude 后续接管，审核归因由 GPT / 人工接管。

## 1.1 题目链接保存纪律

选题包入库之前必须完成题目链接保存。

执行规则：

1. 用户输入知乎链接时，直接保存该链接。
2. 用户输入截图时，若截图中可识别链接，必须保存；若截图无法识别链接，必须在生成正式选题包前要求用户补充真实链接。
3. 系统自采题目时，必须在候选池中同时保存题目、来源入口和真实问题链接。
4. 只有题目文字、没有真实知乎问题链接时，可以记录为待补充线索，但不得生成正式选题包。
5. 禁止使用占位链接进入正式选题包；占位链接只允许用于本地校验测试，并必须标注 `TEST_ONLY`。

未完成选题包入库，不允许交接给 Claude。

选题包生成后，当前 Codex 任务无条件结束。用户要求“生产正文”“写回答”“调用正文节点”“按完整链路生产”或类似指令时，Codex 也只能输出 Claude 交接信息，不得继续执行正文、QA、Patch、Validation、Release 或 Production Card。

## 1.2 Codex / Claude / GPT 边界

Codex 的单篇生产前职责是：

- 采集与保存题目、真实知乎问题链接。
- 读取问题页，完整保存原问题、问题描述和必要上下文。
- 判断是否符合账号方向、是否存在明确矛盾、是否有讨论价值、是否适合当前账号回答。
- 输出 `Daily_Topic_Top3`：当天筛选出的前三个候选问题，对象是问题，用于选题排序。
- 对进入正式候选的问题采集 `Answer_Benchmark_Top3`：同一问题下默认排序前三条有效高赞回答，对象是回答，用于同题 Benchmark、语境校准和参数发现。
- 完成 `Existing_View_Coverage`、`Possible_Current_Gap`、`Existing_Parameter_Matches` 和 `New_Parameter_Observations`。
- 检查历史选题库和已发布文章是否重复。
- 补充必要事实背景。
- 生成标准化 Topic Package 并保存到候选池。

Codex 的长期系统维护职责是：

- 维护参数库、知识库和样本库。
- 维护 `data/parameter_call_log.md`。
- 在 GPT / 人工连续确认同类系统问题后，修复参数、Prompt 或调用规则。
- 积累高表现样本、失败样本和平台规律。

Codex 的禁止动作：

- 不得生成 Production Card。
- 不得提炼唯一核心判断。
- 不得设计文章结构、段落安排、开头写法或结尾句。
- 不得调表达。
- 不得审正文。
- 不得直接写 `Draft-v1.md` 正文。
- 不得因 `Answer_Benchmark_Top3` 发现新效果而直接新增、推进或激活参数。
- 不得把参数缺口写成正式参数；参数缺口只能提交为 `待审核`。
- 不得直接改写、润色或替换 `Article-v*.md` / `Article-Patched-v*.md` / `Article-Final.md` 正文。
- 不得在 Patch 未完成、Patch Validation 未通过、用户未验收时修改 `Release-v*.md` 的正文段落。
- 不得把审核建议直接执行成正文 Patch。
- 不得在用户未 `USER_APPROVED` 前，把 `Release-v1.md` 当作用户验收包或发布稿使用。

Claude / 写作角色负责：

- 只消费 Codex Topic Package 判断怎么写。
- 基于 Topic Package 中的 `Answer_Benchmark_Top3`、已有参数命中和参数缺口提示进行推理。
- 锁定 Explanation Target（一致解释目标）：所有段落共同回答同一个读者真实困惑，不得在正文中切换解释对象。
- 根据选题包生成正文。
- 根据 Audit_Report 和 Decision_Log 执行 Patch。
- 生成正文变更记录。
- 不重新打开知乎采集同题高赞回答。

GPT / 人工负责：

- 检查参数有没有调用对。
- 检查正文有没有执行好。
- 审核 Codex 提交的参数缺口，决定删除、合并、建立候选参数或继续观察。
- 检查正文是否出现 Explanation Target Drift（解释目标漂移）、跳题、断层或观点堆叠。
- 确认实际生效参数。
- 判断问题来自系统，还是来自正文执行。
- 只有连续同类问题被确认为系统问题时，才反馈 Codex 进入系统维护。

Codex 不进入单篇正文 QA / Audit / Patch Validation。Codex 只在系统问题成立后维护参数、Prompt、调用规则或参数调用日志。

## 0.1 生产 / 系统研发分离纪律

知乎OS默认进入日常生产模式。日常生产的目标是最快速度产出可发布正文，不承担系统研发任务。

日常生产只做：

```text
问题
↓
主变量
↓
Explanation Target（一致解释目标）
↓
唯一核心判断
↓
正文
↓
发布
↓
记录数据
```

日常生产最多执行三个轻量检查：

- 有没有跑偏。
- 有没有 Explanation Target Drift（解释目标漂移）。
- 有没有太像 AI。
- 有没有实际收藏点。

日常生产过程中禁止：

- 修改协议。
- 新增参数。
- 优化 Prompt。
- 重构 Notion。
- 把单篇问题升级成系统规则。

系统升级只能在以下任一条件满足时启动：

1. 连续 3 篇出现同一种问题。
2. 数据验证证明某个规律失效。
3. 新发现跨题型通用规律。

除此之外，一律禁止修改系统。

系统升级必须遵守：

```text
第一篇出现
↓
记录
↓
第二篇出现
↓
记录
↓
第三篇仍出现
↓
证明这是系统问题
↓
升级协议
```

原则：生产归生产，研发归研发。先验证，再抽象。不要一边开车一边修发动机。

## 0.2 第二阶段学习闭环

知乎OS第二阶段的学习对象从本账号历史文章切换为知乎平台高表现样本。

职责固定为：

```text
L1｜平台样本：发现变量
↓
L2｜账号实验：验证变量
↓
L3｜ACTIVE变量：生产触发
```

本账号历史文章不再承担“发现规律”的主要任务，只用于验证平台变量是否适合本账号。

平台样本必须按照 `docs/知乎平台样本学习协议.md` 采集和统计：

- 问题样本
- 高表现回答
- Top20评论
- 同题低表现回答
- 变量证据卡

采集边界固定：

- 主赛道只有职场，样本占比 70% 至 80%。
- 组织管理和商业认知只作为职场内容的辅助样本来源，样本占比 20% 至 30%。
- 心理学不得作为独立采集赛道，只允许作为解释职场行为、组织关系或决策问题的辅助证据。
- 禁止因样本使用心理学概念，就将样本归入心理学赛道。

采集入口固定：

- P0：创作权益 -> 近期热点 -> 职场 -> 小时榜，作为日常平台采样主入口。
- P1：创作中心 -> 等你来答 -> 推荐问题，作为账号匹配型优先入口。
- P2：创作中心 -> 等你来答 -> 邀请回答，作为账号邀请补充入口。
- P3：创作中心 -> 问题搜索 -> 知乎热词 / 知乎热题 / 全网热点，作为热点迁移入口。
- P4：知乎站内搜索职场、组织管理、商业认知关键词，只作为垂直样本兜底。
- 外部搜索结果不得作为知乎平台样本来源。

独立热度校验：

- H1：职场日榜、职场周榜、知乎热榜 `/billboard` 或首页热榜 `/hot`，只校验已采集候选题或相邻议题的持续热度、公共关注和议题扩散性，不作为采题入口。

榜单口径：

- P0 采题默认使用职场小时榜。
- 职场日榜、职场周榜、知乎热榜和首页热榜只用于 H1 热度校验。
- 小时榜用于捕捉当天新机会；日榜 / 周榜 / 热榜用于判断候选题是否存在持续热度或公共扩散性。
- 日榜 / 周榜 / 热榜不得替代小时榜成为当天主采样入口。

生产边界：

- Trigger Candidate 只回答题目是否值得优先生产，不得输出 ACTIVE、结构、参数、核心判断或正文方向。
- 读者视角校准只回答视角，不回答内容；只能迁移旧 Production Card 已有能力，输出读者真实困惑、读者原始理解和实际读者范围。
- 读者真实困惑、读者原始理解、实际读者范围三个字段的唯一权威来源是选题包「3. 读者视角校准」节。Production Card 必须直接消费选题包中的这三个字段，不得重新生成或独立推导第二份版本；如认为选题包中的字段有误，必须退回选题包修正，不得在 Card 内部另写一份。
- Topic Package 只回答题目事实、必要上下文、是否值得写、重复检查、风险提示、`Answer_Benchmark_Top3`、`Existing_View_Coverage`、`Possible_Current_Gap`、`Existing_Parameter_Matches` 和 `New_Parameter_Observations`。
- `Answer_Benchmark_Top3` 只回答竞争环境、同题高赞回答已覆盖内容、`Possible_Current_Gap`、已有参数命中和待审核参数缺口。
- Possible Current Gap 不是正文方向；Production Card 可以采用、拒绝或重新推导。
- ACTIVE、核心判断、最终参数、结构和表达，必须在 Production Card 生成过程中由生产决策层推理得出，不得由 Topic、Trigger 或 `Answer_Benchmark_Top3` 提前决定。

采集任务必须分流：

- 选题候选采集：创作中心近期热点、推荐问题、邀请回答用于判断本账号可以答什么。
- 爆款变量训练采集：生产优先使用待生产问题页当前默认排序样本；长期规律研究使用知乎站内职场核心关键词高赞回答、全站热榜中可迁移问题和知乎热题中的高表现回答。

推荐问题只说明账号匹配，不说明平台爆款。低赞低评论的推荐问题可以进入账号实验，但不得作为平台爆款变量训练样本。

爆款训练最低门槛：单题 Top1 回答赞同数建议不低于 300；低于 100 默认不得作为爆款训练样本。Top5 中至少 3 条回答赞同数达到 100 以上，或该题具备明显高收藏、高评论、高热度信号。

平台分析不得再输出独立“平台规律”。平台样本只能输出变量证据卡，所有变量发现、命中统计和候选证据必须统一写入 `production_variable_library.md` 对应变量记录。

若变量已存在，只更新平台证据字段，不得创建同义重复变量。若变量不存在，日常 Codex 任务只能提交 `待审核` 参数缺口；经用户审核批准后，才可创建 `DISCOVERED` 状态变量。

统一状态链：

```text
待审核（不属于正式 Parameter 状态）
↓
用户审核通过
↓
DISCOVERED
↓
CANDIDATE
↓
REVIEW
↓
ACTIVE
```

`DEPRECATED` 为废止状态，长期无恢复证据后归档为 `ARCHIVED`。

平台样本经用户审核后只能推动 `DISCOVERED → CANDIDATE`。账号样本负责推动 `CANDIDATE → REVIEW → ACTIVE`。

正文生产节点只能触发 `production_variable_library.md` 中 `当前状态=ACTIVE` 且 `触发资格=是` 的变量。`CANDIDATE` 和 `REVIEW` 只允许作为指定单变量实验触发，`DEPRECATED` 和 `ARCHIVED` 禁止触发。

禁止新增“平台变量库”“账号变量库”或任何第二套参数体系。

变量生命周期固定为：

```text
平台采样
↓
新增变量（DISCOVERED）
↓
平台继续采样
↓
满足证据
↓
CANDIDATE
↓
Claude 正文节点实验触发
↓
账号验证
↓
REVIEW
↓
继续验证
↓
ACTIVE
↓
长期失效
↓
DEPRECATED
↓
长期无恢复证据
↓
ARCHIVED
```

正文生产节点不直接全量读取 `production_variable_library.md`。每次正式生产必须由 Claude 侧生成或刷新 `runtime/production_variable_snapshot.md`，只把本题命中的变量交给正文节点。

## 1.0.0 Codex 选题采集模式

收到以下任一输入时，Codex 自动进入选题采集模式：

1. 一个知乎问题。
2. 一个或多个知乎问题截图。
3. 用户要求采集、挑选、推荐或保存可回答问题。
4. 用户要求 Codex 自行去知乎采集、挑选或推荐今日可回答问题。

Codex 只执行到标准选题包入库：

```text
问题识别
↓
选题准入
↓
读取原问题和问题描述
↓
必要事实补充
↓
历史重复检查
↓
生成标准选题包
↓
保存到候选池
↓
停止
```

Codex 最终回复必须使用 `docs/Codex选题采集协议.md` 的最终输出格式。不得只回复文件链接，不得只回复“已生成”，不得输出 Production Card、结构实例化摘要、后台参数检查摘要、正文策略或正文。

### 1.0.0.1 Claude 交接规则

如果用户在同一轮或后续轮要求继续生产正文，Codex 只输出交接信息：

```text
Codex 已完成选题采集与入库。
当前任务结束。
后续正文、结构、表达、Patch 和正文 QA 由 Claude / GPT / 人工在对应节点处理。
```

Codex 不得把交接信息扩展为正文施工卡，不得补充唯一核心判断、核心反转句、分段结构、表达约束或 QA/Patch 建议。

正常选题采集任务，用户可见输出默认包含：

```text
1. 选题编号
2. 问题标题
3. 推荐级别
4. 是否重复
5. 是否需要事实核验
6. 保存位置
7. Codex任务结束，等待Claude接管
```

### 允许停止条件

Codex 选题采集模式只有以下情况允许停止：

- 无法从截图识别出任何具体问题。
- 无法取得真实知乎问题链接。
- 原问题或问题描述无法读取，且用户未提供足够信息。
- 历史重复检查无法完成。
- 存在事实、安全、合规风险，不能作为候选题入库。

不得以“未完成结构实例化”“未生成 Production Card”“未运行正文 QA”作为停止理由，因为这些不属于 Codex 选题采集范围。

允许停止时必须输出：

- 停止节点。
- 错误代码。
- 具体缺失项。
- 用户需要补充的唯一信息。

### 模式路由

正文生产类触发词：

- 写文案
- 生产正文
- 写回答
- 调用正文节点
- 按完整链路生产
- 根据这个问题回答

行为：Codex 只确认选题包状态并输出 Claude 交接信息，不继续生成正文、Production Card、QA、Patch、Validation 或 Release。

审计模式触发词：

- 检查流程
- 审计系统
- 只生成生产卡
- 不写正文
- 检查参数调用

行为：只执行用户指定的系统审计范围。若审计对象是正文或 Production Card，Codex 只检查协议边界和系统文件，不审单篇正文质量，不执行正文 Patch。

禁止因为输入是截图就默认进入审计模式。判断依据是用户意图，不是输入形式。

## 1.0 本地执行源硬门槛

正式生产前必须读取本地 runtime 执行快照。

Notion 是管理权威，负责协议设计、参数维护、规律验证、版本审批、复盘与升级决策。

本地 `runtime/` 是 Codex 日常生产的唯一执行权威，负责正式生产时的知识、结构、参数和规律调用。

Codex 日常生产不得实时读取 Notion，不得根据 Notion 页面临时改变运行规则。

只有标记为 ACTIVE 并已发布到 `runtime/ACTIVE_MANIFEST.md` 的内容，才能进入生产链。

Notion 内容发生修改，不代表立即生效；只有完成快照发布和版本更新后才生效。

runtime 与 Notion 冲突时：

- 日常生产按 runtime 执行。
- 系统维护时以 Notion 审批结果生成新的 runtime 版本。

必须输出本地执行源审计：

- 是否真正读取 `runtime/ACTIVE_MANIFEST.md`
- 读取了哪些 runtime 快照文件
- 哪些知识、结构、参数、规律命中
- 哪些知识、结构、参数、规律没有命中
- 是否存在快照缺失、版本不一致、状态非 ACTIVE 或关键内容为空
- 是否允许交给 Claude 正文生产节点

如果 runtime 清单缺失、快照读取失败、命中不足、关键内容为空，或无法判断是否读取成功，必须停止正文生产，只输出：

```text
【知识调用失败】

- 失败位置：
- 已尝试检索：
- 已读取页面：
- 缺失知识：
- 需要用户处理：

未完成知识调用前，我不会进入正式生产。
```

禁止在 runtime 知识调用失败后降级为仅使用 TOP10 事实包、通用经验或模型记忆继续调用 Claude 正文生产节点。

未列入 `runtime/ACTIVE_MANIFEST.md` 的 MD、事实包和历史资料只能作为辅助上下文，不能替代 runtime 执行快照。

## 1.1 五层职责

知乎OS分为五层：

| 层级 | 载体 | 回答的问题 | 职责 |
| --- | --- | --- | --- |
| L1 协议层 | Git/MD | AI 应该怎么干 | 总控协议、调度协议、Prompt模板、Skill、Router、输入协议 |
| L2 知识层 | Notion 管理源 / runtime 执行快照 | AI 依据什么干 | TOP文章、ACTIVE知识、用户画像、爆款规律、平台规则、评论规律、结构知识 |
| L3 执行层 | Codex | 今天具体干什么 | 读取选题采集协议、识别截图、读取原问题、生成选题包、保存候选池 |
| L4 平台层 | 知乎/头条 | 真实反馈是什么 | 曝光、阅读、评论、收藏、收益 |
| L5 学习层 | Notion复盘 | 下次如何优化 | 数据记录、假设、验证、复盘、更新知识、形成决策 |

Git/MD 只负责稳定协议，不参与日常学习。

Notion 负责知识增长、审批和学习闭环；runtime 负责 Codex 日常执行。

| 条件 | 是否必须 |
| --- | --- |

## 1.3.1 账号画像层

账号画像是长期低频数据层，不属于单篇内容变量，也不是正文 Prompt 参数。

账号画像回答的问题是：这个账号长期吸引什么人，什么内容更容易带来关注、收藏、评论、阅读和收益。

账号画像进入选题和复盘，不直接进入正文节点字段。

固定字段：

```text
L0｜账号画像
├── 性别
├── 年龄
├── 地区
├── 兴趣
├── 关注来源
├── 涨粉TOP文章
├── 收益TOP文章
├── 收藏TOP文章
├── 评论TOP文章
└── 阅读TOP文章
```

更新频率：

| 字段 | 更新频率 | 用途 |
| --- | --- | --- |
| 关注来源 | 半年 | 判断增长主要来自回答、主页或其它入口 |
| 性别 | 半年 | 校准表达、案例和默认读者 |
| 年龄 | 半年 | 校准问题意识和案例层级 |
| 地区 | 半年 | 校准产业、城市和工作场景 |
| 兴趣 | 季度或半年 | 校准选题方向 |
| 涨粉TOP文章 | 每月 | 建立关注转化排行榜，触发 L3 深度事实包 |
| 收益TOP文章 | 每月 | 判断商业价值 |
| 收藏TOP文章 | 每月 | 判断长期工具价值 |
| 评论TOP文章 | 每月 | 判断讨论和情绪触发 |
| 阅读TOP文章 | 每月 | 判断分发能力 |

当前已知画像结论：

- 粉丝主要来自回答，不是主页；资源继续优先投入回答，个人主页不作为当前主要增长杠杆。
- 活跃分层只作为平台背景统计，不进入 Prompt、不进入变量、不参与单篇复盘。
- 新增关注 TOP20 是高价值复盘入口，默认进入 L1，异常高关注转化样本优先进入 L3 深度事实包。
- 粉丝不是纯职场受众，而是组织、心理、人性、社会、管理混合受众；选题应增加组织心理、社会运行、人性、制度、博弈。
- 地域偏经济发达地区；案例优先互联网、制造业、大厂、民企、管理、老板、资源竞争。
- 性别偏男性；表达入口优先组织、权力、竞争、升职、老板、管理、资源、博弈。
- 年龄集中在 25-40 岁；默认读者是基层员工、主管、经理、中层和创业者。

生产关系调整为：

```text
账号画像（长期）
↓
选题
↓
Claude正文节点
↓
正文
↓
收益数据
↓
L0-L3复盘
```

账号画像只能影响选题准入、选题扩展、案例选择和样本复盘优先级；不得直接新增正文节点字段，不得未经验证修改 Prompt 或 ACTIVE 规则。

## 1.4 内容数据四层职责

知乎内容数据分为四层。四层不是四个数据量，而是四种数据职责。

知乎 L0 协议版本：V1.0。

协议状态：LOCKED。

L0 字段在 216 篇历史内容采集完成前禁止新增。除非发现已采字段存在数据错误，否则不得修改 L0 字段结构，避免中途返工。

| 层级 | 作用 | 唯一产出 | 是否长期维护 | 是否分析 |
| --- | --- | --- | --- | --- |
| L0 内容资产总账 | 建立全量索引 | 内容资产总账 | 是 | 否 |
| L1 分层样本 | 建立实验样本 | 分层样本清单 | 是，动态维护 | 少量 |
| L2 变量层 | 提取和验证变量 | 变量标注记录 | 是 | 是 |
| L3 深度事实包 | 建立证据链 | 深度事实包 | 是 | 是 |

### 1.4.1 各层进入条件

| 层级 | 进入条件 |
| --- | --- |
| L0 内容资产总账 | 内容已经发布或已存在历史记录 |
| L1 分层样本 | 命中抽样规则，如高收益、高阅读、高收藏、低阅读高收益、最近7天或异常样本 |
| L2 变量层 | 已被 L1 选中，且需要进行正文、首屏、结构、评论或变量分析 |
| L3 深度事实包 | L2 变量具有研究价值，且需要建立完整证据链支撑复盘、实验或决策 |

### 1.4.2 各层升级触发器

| 升级路径 | 触发器 |
| --- | --- |
| L0 → L1 | 内容命中抽样规则，需要进入实验样本清单 |
| L1 → L2 | 样本已完成基础筛选，且需要采集正文、首屏、结构、评论或变量 |
| L2 → L3 | 变量可能影响复盘、实验或决策，需要建立完整证据链 |

升级触发器只决定是否增加采集深度，不直接产生规律结论。

### 1.4.3 各层停止条件

| 层级 | 停止条件 |
| --- | --- |
| L0 内容资产总账 | 全部历史内容完成索引；之后只做新增内容的增量更新 |
| L1 分层样本 | 每个实验组达到目标样本数后停止扩采 |
| L2 变量层 | 新增样本很少出现新变量，变量开始收敛 |
| L3 深度事实包 | TOP10 或当前深度样本已经足够支撑本轮决策 |

L1 分层样本不能只按 Top 排序，必须保留对照组。默认抽样方向包括：

- 高收益
- 高阅读
- 高收藏
- 低阅读高收益
- 最近7天
- 异常样本

### 1.4.4 禁止越级升级

L0 永远不能直接升级到 L3。

任何内容进入深度事实包，必须依次经过：

```text
L0 内容资产总账
↓
L1 分层样本
↓
L2 变量提取
↓
L3 深度事实包
```

L0 只记录事实索引，不能直接推出变量有效、结构有效或规律成立。

未经 L2 变量标注和验证的数据，不得升级为规律、假设或决策依据。

当用户要求采集全部内容时，默认仅建立内容资产索引；正文、评论、同题高赞等高成本数据，必须由 L1/L2/L3 升级流程触发，不允许自动采集。

### 1.4.5 行为结果层数据源

行为结果层必须先解决数据归属问题。

公开问题页会同时展示题目、本人回答、同题其他答主回答、公共评论和相关推荐，不能直接作为本人单篇阅读、赞同、收藏、评论的归属来源。

本人回答的行为结果只认创作者后台：

| 字段 | 唯一归属口径 |
| --- | --- |
| 阅读、赞同、收藏、喜欢、分享、正向互动率、关注者转化 | `内容管理 -> 单篇内容 -> 数据` |
| 本人回答评论 | `内容管理 -> 单篇内容 -> 查看评论` 或 `评论管理 -> 单篇回答评论` |
| 正文、首屏、结构 | 可用公开回答页或后台正文摘录，但必须匹配 answer_id |
| 同题高赞、同题评论 | 只用于竞争环境观察，不进入本人行为结果层 |

如果页面数据无法匹配 answer_id，必须标注为 `待核验`，不得进入 L1/L2/L3 样本裁判。

### 1.4.6 收益结果层

收益参数不是生产参数，不与信息增量、解释增量、结构、首屏、评论机制放在同一层。

内容参数是原因变量，收益参数是结果变量。

信息增量、主变量、首屏、结构、评论机制，是生产前主动选择、正文中主动执行、复盘时主动验证的内容变量。

盐粒收益、千阅读收益、7天累计收益、30天累计收益，是知乎平台返回的商业结果，用来裁判内容变量是否值得继续实验、升级、降级或废弃。

知乎收益复盘的唯一盐粒口径是：`收益分析 → 致知计划 → 内容收益明细`。

普通 `收益分析 → 全部` 页面只记录实际到账的总收益，不等同于致知计划盐粒收益。若普通收益页为 0，但致知计划有盐粒收益，复盘必须以致知计划为准。

致知计划字段换算：

| 字段 | 来源 |
| --- | --- |
| 单篇盐粒收益 | 致知计划内容收益明细的 `累计收益` 或指定周期的 `本期收益` |
| 千阅读收益 | `盐粒收益 / 阅读量 * 1000` |
| 7天累计收益 | 致知计划最近 7 天收益明细 |
| 30天累计收益 | 致知计划最近 30 天收益明细 |

收益结果至少保留四个指标：

| 收益参数 | 作用 |
| --- | --- |
| 单篇盐粒收益 | 判断单篇实际变现金额 |
| 千阅读收益 | 排除阅读规模干扰，判断流量质量和商业价值 |
| 7天累计收益 | 判断短期兑现能力 |
| 30天累计收益 | 判断长尾收益能力 |

其中，千阅读收益是优先裁判指标。单篇收益高可能来自阅读规模，千阅读收益高才说明题型、结构或变量带来的流量更值钱。

正确复盘关系是：

```text
内容参数
↓
产生阅读、互动、停留等行为
↓
平台分发与用户价值判断
↓
形成盐粒收益
```

最终判断不是“内容参数评分高，所以文章有效”，而是：

```text
参数是否命中
+
收益是否提高
+
是否连续复现
=
是否升级为规则
```

单篇文章只负责提供证据，不直接产生规则。规则升级必须经过变量验证卡：

```text
L2 正文变量标注
↓
收益结果卡
↓
变量验证卡
↓
证据等级
↓
ACTIVE / Prompt 升级
```

### 1.4.7 五层复盘判断

知乎复盘按五层判断执行：

| 层级 | 问题 | 主要字段 |
| --- | --- | --- |
| 第一层：事实层 | 发布了什么，拿到什么数据 | 题目、发布时间、链接、阅读、互动、收益 |
| 第二层：内容变量层 | 使用了什么生产变量 | 唯一主变量、结构、首屏、信息价值、认知奖励、传播参数 |
| 第三层：行为结果层 | 用户行为反馈如何 | 阅读、赞同、收藏、评论、转发、停留代理信号 |
| 第四层：收益结果层 | 是否产生商业价值 | 盐粒收益、千阅读收益、7天收益、30天收益、相对中位数 |
| 第五层：规则升级层 | 是否影响系统规则 | 继续实验、升级 Prompt、升级 ACTIVE、降级、废弃 |

只有能够稳定提高盐粒收益，尤其能够提高千阅读收益的内容变量，才允许进入 Prompt 或 ACTIVE 规则升级讨论。

执行顺序固定为：

1. 先完成 L2 正文变量标注。
2. 再生成单篇收益结果卡。
3. 再汇总为变量验证卡。
4. 最后判断证据等级和规则升级。

同题 `Answer_Benchmark_Top3` 平台样本不是本人数据，只能进入 Topic Package 作为同题 Benchmark、竞争环境参考、现有参数命中证据和参数缺口观察来源，不得进入 L0/L1 行为结果统计。样本必须记录 Sample Source，默认排序与赞同排序不得混用。

### 1.4.8 变量验证卡

变量验证卡回答的问题不是“哪篇文章赚钱”，而是“哪个变量赚钱”。

变量验证卡是 Prompt / ACTIVE 升级前的强制证据层。单篇爆文、单篇高收益、单篇高千阅读收益，都不能直接升级为规则；必须先汇总到变量维度，看该变量是否在足够样本中稳定提高千阅读收益或盐粒收益。

固定字段：

```text
变量：
变量类型：
适用题型：
使用次数：
样本范围：
平均阅读：
平均盐粒收益：
平均千阅读收益：
7天平均收益：
30天平均收益：
成功样本数：
失败样本数：
成功率：
高收益样本：
低收益反证：
相对账号中位数：
相对同题型中位数：
相对同结构中位数：
证据等级：候选 / 实验 / 有效 / 稳定 / 废弃
升级动作：继续实验 / 升级 ACTIVE / 影响 Prompt / 降级 / 废弃
验证结论：
本变量验证了什么：
本变量没有验证什么：
下一轮实验要求：
```

变量升级阈值：

| 证据等级 | 条件 |
| --- | --- |
| 候选 | 单篇或少量样本出现收益信号，但样本不足 |
| 实验 | 已有 3 篇以上样本，正在验证是否复现 |
| 有效 | 同题型或同结构中多篇样本的千阅读收益高于可比中位数 |
| 稳定 | 跨多轮样本仍能提高千阅读收益或盐粒收益，且低收益反证可解释 |
| 废弃 | 多次使用后收益、阅读或互动表现低于可比中位数，或无法隔离变量作用 |

变量验证优先级：

```text
千阅读收益
>
7天累计收益
>
30天长尾收益
>
单篇总盐粒
>
阅读量
```

变量升级的最终判断：

```text
不是某篇文章爆了
而是某个变量在足够样本中稳定提高千阅读收益或盐粒收益
```

### 1.4.9 L0 自动检查

每次 L0 采集后必须输出自动检查结果：

- 内容类型分布。
- 关键字段 NULL 统计。
- NULL 来源是否符合内容类型差异。
- article_id 是否重复。
- 数值字段是否可排序。

如果回答、文章、视频等应有字段出现异常 NULL，必须报警并停止扩采。

如果内容类型天然缺少某字段，例如想法没有收藏字段，必须留空并在 notes 中说明，不得继承上一条或下一条内容的数据。

## 2. 截图识别协议

GPT 必须先从截图中识别以下字段：

- 问题标题
- 问题补充说明
- 话题领域
- 用户真实困惑
- 情绪张力
- 潜在争议点
- 可用立场

## 4. 历史结构记录

本节为历史内容路由记录，不属于正式生产结构权威。正式生产结构权威只读取 `runtime/知乎结构库快照.md` 中状态为 ACTIVE 的老师结构。

## 4.1 历史 ACTIVE 结构库

以下 ACTIVE 结构库是历史内容路由能力，不等于平台样本采集赛道。

平台样本采集必须遵守第二阶段采集边界：职场为唯一主赛道，组织管理和商业认知只能作为辅助来源，情感关系、心理认知、原生家庭、亲密关系和纯心理疗愈不得进入平台采样主链。

### ACTIVE-01 反常识洞察结构

适用：情感、人性、关系判断、社会习惯。

骨架：

1. 用一句反常识判断开头。
2. 指出大众误解。
3. 拆出真实机制。
4. 给出具体场景。
5. 提炼可迁移结论。
6. 以克制但有余味的句子收束。

### ACTIVE-02 认知升级结构

适用：职业、成长、人生选择、赚钱、长期发展。

骨架：

1. 先否定一个低维判断。
2. 抬高问题层级。
3. 解释真正的决策变量。
4. 给出判断标准。
5. 给出行动建议。
6. 用一句清醒结论结束。

### ACTIVE-03 机制拆解结构

适用：社会现象、热点争议、群体行为。

骨架：

1. 先说现象不是偶然。
2. 拆利益结构。
3. 拆情绪结构。
4. 拆传播结构。
5. 给出自己的判断。
6. 避免口号式结尾，用机制性总结收束。

### ACTIVE-04 经验清单结构

适用：消费决策、避坑、选择建议、实操问题。

骨架：

1. 直接给结论。
2. 列出判断标准。
3. 分情况讨论。
4. 给出避坑点。
5. 给出可执行建议。
6. 用一句决策原则结束。

### ACTIVE-05 心理机制结构

适用：内耗、拖延、自卑、关系焦虑、情绪痛苦。

骨架：

1. 先接住情绪，但不滥安慰。
2. 解释心理机制。
3. 指出行为循环。
4. 给出破局动作。
5. 重新定义问题。
6. 以温和但坚定的句子结束。

### ACTIVE-06 方法论结构

适用：学习、读书、写作、考试、技能训练。

骨架：

1. 先指出常见错误方法。
2. 给出核心原则。
3. 拆成步骤。
4. 提供练习方式。
5. 给出反馈标准。
6. 用可持续执行的建议结束。

## 5. 爆款案例分析协议

爆款案例分析协议改为平台变量证据提取协议。

正式候选题的 `Answer_Benchmark_Top3` 是 Codex 选题阶段的标准职责。它不是复盘增强项，也不由 Claude 在正文阶段补采。

知乎“默认排序”不等于“赞同数排序”。生产模块默认使用平台当前默认排序作为主要分析对象；历史赞同数排序作为长期规律研究对象。两者不得混用，所有样本必须记录采样来源。

日常正文生产优先从 Codex Topic Package 和 runtime 执行快照读取以下材料：

- `Answer_Benchmark_Top3`
- `Existing_View_Coverage`
- `Possible_Current_Gap`
- `Existing_Parameter_Matches`
- `New_Parameter_Observations`
- 已分析爆款样本
- TOP文章变量提取
- 选题库相邻问题
- ACTIVE知识
- 变量证据
- 历史收益证据

如果用户额外提供同题样本或要求严格竞品分析，只能作为补充材料标注来源，不替代 Codex 在 Topic Package 中已经完成的 `Answer_Benchmark_Top3`。

如果没有同题平台样本，不得伪称已读取 `Answer_Benchmark_Top3`；正式候选题应退回 Codex 选题采集补齐。只有不可访问、权限不足或用户明确要求快速跳过时，才允许标注为“同题样本缺失，基于 runtime 相邻样本提取”，并降级使用。

日常正式候选题默认采集 `Answer_Benchmark_Top3`。长期变量训练任务默认采集有效平台样本 Top5；赞同数 Top5 用于长期规律研究；最新回答样本可作为当前竞争环境补充。若页面前三条存在盐选节选、广告引流、无实质内容、偏题或明显过时回答，必须继续向下补足 3 个有效 `Answer_Benchmark_Top3` 样本。

只采问题不构成完整平台样本。进入长期变量提取前，必须完成每题有效 Top5 回答正文采集，并为每条回答记录 Sample Source、正文读取状态、回答链接、作者、发布时间、赞同、评论、正文全文、首屏方式、结构路径、解释机制、收藏点和评论触发点。未完成 Top5 回答正文读取的问题只能标记为 `QUESTION_ONLY`，不得进入长期变量提取、变量统计、参数升级、正文节点升级或 Prompt 升级。

特殊问题动态调整：

| 问题情况 | 抓取数量 |
|---|---|
| 日常普通问题 | 有效 Top5 |
| 回答总数不足5篇 | 全部有效回答 |
| Top5观点高度一致 | Top5即可 |
| Top5分歧明显 | 补到Top8 |
| 高价值、高竞争题 | Top10 |
| 新问题、回答数量少 | Answer_Benchmark_Top3 或全部 |
| 只需快速生产 | Answer_Benchmark_Top3 轻分析 |

平台样本分析必须形成问题级聚合结论，包含 Top5共同观点、Top5共同结构、重复最严重的内容、观点分歧、用户未被满足的问题、本篇差异化方向、推荐结构、推荐变量和禁止重复表达。

进入正文节点输入的只能是问题级聚合结论，不是 Top5 原文、逐篇拆解细节或排名信息。

平台样本分析不再输出“规律”，只输出变量证据：

1. FV：首屏变量，例如反常识、身份代入、利益相关、冲突钩子。
2. PD：推导深度变量，例如机制解释、利益结构、风险传导、因果链。
3. RR：阅读体验变量，例如短段推进、留白、节奏切换、认知缓冲。
4. CR：认知奖励变量，例如新定义、判断标准、迁移价值、收藏点。
5. BT：行为转化变量，例如评论诱因、收藏理由、分享理由。
6. Evidence：平台样本数、命中数、命中率、成功样本、失败反证和建议状态。

变量提取报告不得停留在描述层。每个变量必须补齐：变量定义、生效机制、证据统计、证据等级、适用题型、触发条件、禁用边界、正文节点调用方式、Claude Prompt调用方式和升级建议。缺少上述字段的报告标记为 `V0_DESCRIPTIVE_REPORT`，不得进入参数库、正文节点升级或 Prompt升级。

变量统计必须解释“为什么有效”。只写“反认知 5/5”“短段落 5/5”不构成参数；必须说明它如何制造预测误差、降低认知负荷、提高继续阅读率、收藏率、评论率或推荐信号。

## 6.1 规则升级闸门

任何新规则、新约束或新写法，在进入系统前必须先完成升级归属判断。

禁止因为单篇正文失败，直接把本题答案、本题机制或本题表达写入总 Prompt、总协议或通用 QA。

升级前必须先标注 `Rule Type`，再标注 `Scope`。

```text
Rule Type：
- Action｜动作规则：要求模型执行某个通用动作，例如继续追问、先解释再建议、形成迁移判断。
- Structure｜结构规则：规定内容组织顺序、段落结构或题型骨架。
- Mechanism｜机制规律：描述某类现象背后的稳定因果、利益、权力或组织规律。
- Expression｜表达技巧：规定语言、节奏、开头、转场、话术或可读性处理。
- Opinion｜具体观点：某一题的判断、立场、结论或机制命名。
- Evidence｜案例事实：事实、数据、案例、平台观察或单篇样本发现。

Scope：
- Global｜所有题都成立。
- Topic｜只在某一类题成立。
- Card｜只适合当前题。
- Hypothesis｜无法判断，或证据不足但值得观察。
```

升级矩阵：

| Rule Type | Global | Topic | 单篇正文节点 |
| --- | --- | --- | --- |
| Action | 允许进入总协议 / 正文 Prompt / 通用 QA | 允许进入题型结构 / 题型参数 | 只允许进入单篇正文节点 |
| Structure | 允许进入总结构协议，仅限所有题稳定成立 | 允许进入对应题型结构 | 只允许进入单篇正文节点 |
| Mechanism | 原则上不得直接 Global；必须有跨题验证后进入通用参数 | 允许进入 ACTIVE 规律，但必须经过多篇验证 | 只允许进入单篇正文节点 |
| Expression | 不进入总协议，除非是硬性反 AI 痕迹底线 | 允许进入题型表达协议 | 只允许进入单篇正文节点 |
| Opinion | 禁止进入 Global | 禁止进入 Topic，除非转化为已验证机制 | 只能进入单篇正文节点 |
| Evidence | 禁止进入 Global | 禁止进入 Topic，除非进入已验证样本库 | 只能作为本题证据或历史弱参考 |

`CANDIDATE` 不进入正式生产触发，只进入候选规则或验证记录。

无法判断时，不再直接升级，也不直接删除，必须标记为：

```text
Status：CANDIDATE
证据：单篇 / 多篇 / 数据不足
下一步：等待 3 篇以上同类样本验证进入 REVIEW；达到 10 篇稳定成立后，才允许申请 ACTIVE。
```

系统规则只能固化“动作”，不得固化“答案”。

允许进入总协议的规则示例：

- 正文必须先解释为什么，再进入怎么办。
- 正文不得停在现象、建议或口号。
- 机制推导必须形成可迁移判断。

不得进入总协议的规则示例：

- 本题必须写责任分布。
- 本题必须写组织共识不等于认知共识。
- 本题必须写某个行业、场景或案例。
- 本题发现的某个具体表达句式。
- 未经多篇验证的机制规律。

题型规则只能进入对应题型能力层。本题发现只能进入单篇正文节点，不得污染全局 Prompt。
