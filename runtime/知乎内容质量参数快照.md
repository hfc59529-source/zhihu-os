# 知乎内容质量参数快照

版本：PARAM-V3.0-TEACHER

执行版本：ZH-RUNTIME-V3.0-TEACHER

状态：ACTIVE

来源：由 Git 权威文件和治理确认结果发布到 runtime。Notion 仅可作为历史参考，不具备 Production Authority。

## 使用规则

Codex 正式生产时只允许调用本快照中存在且状态为 ACTIVE 的参数。

问题理解必须进入 DECISION 的 QT-QI 识别记录，并在 COMPILE 时压缩进 Execution IR 的 Structure / Acceptance Criteria，不再作为独立施工卡字段。

质量参数调用必须进入 Execution IR 或 AUDIT 的 Expected Source，不得作为 26 维清单展开给 WRITE。

Execution IR 只保留对正文有直接施工意义的表达约束、事实边界、结构实例和本 Run 验收义务。PD、RR、RE、BT、CR 只用于检查结构实例与 Acceptance Criteria 是否成立，不得决定正文骨架。

## V3 后台检查规则

正式生产必须先读取 `runtime/知乎结构库快照.md` 的 ACTIVE 老师结构，再用本快照做后台检查。

禁止：

- 用 PD / RR / RE / BT / CR 替代 ACTIVE 结构。
- 用 26 维审计结果拼正文段落。
- 把后台参数名作为 WRITE 的显性写作内容。

最低检查项：

1. 是否引用 ACTIVE 老师结构。
2. 是否完成本题结构实例化。
3. 是否存在具体场景或例子。
4. 是否存在 3-5 层因果追问链。
5. 是否存在明确推导终点。
6. 是否避免后台术语进入 Claude 卡。
7. 是否避免无来源数字、投资承诺、荐股、荐币和理财配置方案。

## QT-QI｜问题理解系统

### QT-00｜问题分类

状态：ACTIVE

调用条件：所有知乎 DECISION 默认调用。

输出要求：选择 1 个主问题类型，最多 1 个副类型；类型范围为事实型、解释型、判断型、预测型、建议型、决策型、情绪型、价值观型、经验型、机制型。

禁用条件：无。

验证方式：写入 DECISION 的 QT-QI 识别记录。

### QT-00.1｜题型价值优先级

状态：ACTIVE

调用条件：所有知乎 DECISION 默认调用。

输出要求：题型决定内容价值的主要来源，质量参数必须服务用户真实问题。解释型主要价值来自机制解释、因果推导和认知增量；建议型 / 解决题主要价值来自动作有效性、场景覆盖、话术可用性和执行边界；决策型主要价值来自选项比较、取舍条件、风险收益和停止标准；表达型主要价值来自可直接使用的话术、语气分寸和关系边界。

建议型 / 解决题硬约束：机制解释不超过正文 30%；具体场景、动作、话术和升级条件不少于正文 60%；认知升级只能在结尾完成；框架只作为快速判断器，不得替代场景化方案；每个建议必须回答怎么说、怎么做、保护什么边界、对方不配合时怎么办。

解决题正文生成协议：禁止直接进入解决方案；必须先识别用户隐藏约束，回答用户为什么“不敢这样办”；再用跟随式追问完成“现象→机制→规律→迁移”的底层逻辑推进，让读者知道为什么必须这样做；最后覆盖 3—5 个高频真实场景。机制必须带用户抵达方案，不得写成培训理论。

解决题防误导规则：记录不等于自动免责，只能证明过程、降低被简单归责的风险；交回决策不等于放弃专业提醒，必须说明已知风险、代价和不可逆后果；自保不等于绕过汇报链或公开对抗，升级必须在正常汇报链条内完成。

禁用条件：无。

验证方式：写入 DECISION 的 QT-QI 识别记录；若形成正文义务，由 COMPILE 写入 Execution IR.acceptance_criteria 或 Expression Constraints。

### QI-04.1｜用户隐藏约束

## PD｜推导深度

### PD-01｜现象识别

状态：ACTIVE

调用条件：所有知乎正文默认调用。

输出要求：识别问题表层现象、行动主体和读者真实困惑。

禁用条件：无。

验证方式：Execution IR.acceptance_criteria 中必须写明本 Run 正文义务。

### PD-02｜因果识别

状态：ACTIVE

调用条件：所有知乎正文默认调用。

输出要求：说明现象背后的直接原因，避免停留在态度判断。

禁用条件：无。

验证方式：Execution IR.acceptance_criteria 中必须写明本 Run 正文义务。

### PD-03｜机制推导

状态：ACTIVE

调用条件：所有知乎正文默认调用。

输出要求：唯一主变量必须完成机制终点推导：L1 现象解释、L2 机制解释、L3 机制终点、L4 可迁移规律、L5 最后一问检查。核心辅助变量至少完成 L2，普通辅助变量只允许解释，不得多线深挖。

L1｜现象解释：解释发生了什么，锁定行动主体和读者困惑。

L2｜机制解释：解释为什么发生，写清成本、收益、风险、权力、激励、信息、资源或利益。

L3｜机制终点：继续追问为什么该机制会稳定成立，必须推到利益分配、权力配置或组织运行规律，不得停在责任、利益、权力等中间概念。

L4｜可迁移规律：把机制终点抽象成可迁移判断，说明同类组织场景中何时也会成立。

L5｜最后一问检查：正文结束机制推导前必须自问“还能继续问为什么吗”。如果仍能继续解释，必须继续推导；只有已经回答题目中的行为为什么会稳定发生、相关主体为什么会持续这样选择、该机制为什么具有重复性，才允许进入结论或建议。

禁用条件：无。

验证方式：AUDIT 必须以 Execution IR.acceptance_criteria 或已发布 AuditRule 为 Expected Source，检查 L1-L5 是否完整、每层是否新增信息、是否形成机制终点和可迁移规律；任一失败判定 PD-03 Fail。

### PD-04｜利益结构

验证方式：调用时必须写触发证据；未调用时必须写未调用原因。

验证方式：调用时必须写触发证据；未调用时必须写未调用原因。

### PD-07｜人性动机

调用条件：题目涉及风险规避、控制需求、身份焦虑、公平感、责任规避或趋利避害。

## RR｜阅读体验

RR 负责读者理解内容时是否轻松、是否疲劳、是否能吸收。RR 不降低 PD 深度，不替代 RE 表达，不把 CR 金句数量当成阅读奖励。

Execution IR 不新增通用参数字段。RR 只能压缩进入 Expression Constraints、Acceptance Criteria 或已发布 AuditRule。日常只调用 2-4 个正文执行参数、3-6 个生成后检查参数，不得把所有 RR 参数全部写进每篇 Execution IR。

### RR-01｜认知负荷控制

状态：ACTIVE

参数目标：控制读者在单位篇幅内需要同时处理的概念、判断、因果链和抽象关系数量。

解决问题：连续认知输出过多、每段都要求读者判断、主判断被次要判断分散。

适用场景：所有知乎长文；机制型、组织题、职场题优先调用。

触发条件：正文存在多个判断、多个因果层或连续抽象推导。

执行规则：
- RR-01-01 核心判断数量：全文核心判断建议 1-3 个，唯一主判断必须能用一句话表达，其他判断必须服务主判断；不得每节都创造新的底层规律。
- RR-01-02 单段认知任务：每个自然段只完成描述现象、展示场景、解释一个原因、推导一个机制、给出一个判断或提供一个行动建议中的一种主要任务。
- RR-01-03 连续认知上限：连续出现 2 个新判断后，必须进入场景、对话、动作、现实观察、简短例子或总结停顿；禁止连续 3 个以上新判断。
- RR-01-04 因果链长度：单次显性因果推导建议 2-4 层，超过 4 层必须拆成“现象→场景→原因→缓冲→机制→判断”。

禁止事项：一个段落同时承载现象描述、权力分析、利益分析和行动建议；一次性展示 5 层以上箭头式推导。

合格示例：领导问“还有意见吗？”没人说话。五分钟后，会议纪要写着：全体同意。沉默没有被记录成沉默，它被记录成支持。

不合格示例：同一段连续解释表达成本、权力资源、风险传导、组织博弈和个人行动建议。

QA 检查：提取全文可单独成立的判断句；超过 5 个标记“认知主线分散”，无法确定唯一主判断标记“主判断缺失”；连续 3 段均以抽象判断为核心，标记“连续认知过载”。

严重级别：主判断缺失为 BLOCK；连续认知过载为 REVISE。

与其他参数关系：PD 决定推导深度，RR-01 决定一次让读者处理多少；CR 决定奖励类型，RR-01 控制奖励数量。

### RR-02｜信息密度控制

状态：ACTIVE

参数目标：降低单位字数中的新概念数量，避免文章句句有道理但读者无法消化。

解决问题：概念堆积、抽象句过多、长句负荷过高、同义重复解释。

适用场景：所有机制型、解释型、职场组织型回答。

触发条件：正文出现权力、资源、责任、成本、收益、博弈、共识、风险、边界、结构、机制、传导、激励等抽象词。

执行规则：
- RR-02-01 概念引入速度：每 300 字原则上不新增超过 2 个核心概念；新概念出现后必须解释或展示；同义概念应合并。
- RR-02-02 抽象句比例：每连续 3 段中，至少 1 段包含具体对象或现实动作。
- RR-02-03 句子负荷：一句话原则上只表达一个主要判断；超过 60 字进入检查，超过 80 字默认标记长句负荷过高。
- RR-02-04 解释冗余：同一观点最多允许 1 次提出、1 次解释、1 次场景证明、1 次总结。

禁止事项：连续使用未定义抽象词；相邻 3-5 段换词重复解释同一个观点。

合格示例：“表达成本”，说白了就是：你一开口，先承担后果的是你。

不合格示例：连续 200 字堆叠责任边界、权力结构、利益机制、组织博弈、风险传导，但没有人物或动作。

QA 检查：200 字内出现 5 个以上抽象名词，标记“概念密度过高”；连续 3 段没有人物、场景或动作，标记“连续抽象”。

严重级别：概念密度过高为 REVISE；连续抽象且影响理解为 BLOCK。

与其他参数关系：RE 控制语言自然度，RR-02 控制信息吸收速度。

### RR-03｜认知缓冲

状态：ACTIVE

参数目标：在高认知内容之间加入不要求读者继续推理的吸收区。

解决问题：形式上有分段和停顿，但大脑没有真正休息。

适用场景：机制解释后、核心判断前后、连续抽象推导之后。

触发条件：完成一个机制解释、连续两个新判断、连续两段抽象分析。

执行规则：
- RR-03-01 场景缓冲：使用会议、工作群、邮件、汇报、复盘会、领导办公室或项目现场承接当前机制，30-120 字，不展开新机制。
- RR-03-02 对话缓冲：使用真实职场短句，例如“还有意见吗？”“那就先按这个推进。”“大家都没有意见吧？”
- RR-03-03 动作缓冲：用低头看电脑、翻材料、群里没人回复、邮件抄送、纪要发出后没人补充等动作代替抽象解释。
- RR-03-04 观察缓冲：允许使用“你会发现……”“很多会议都是这样。”“奇怪的是……”等简短观察句。
- RR-03-05 停顿缓冲：核心判断前后可用短句、独立段落和留白，但禁止每个判断都金句化。

禁止事项：用 500 字虚构人物经历制造无关故事；领导一次说出完整理论；过度戏剧化假对话。

合格示例：领导问：“大家都没有意见吧？”没人说话。会议结束后，纪要写着：一致同意。

不合格示例：为了证明机制，虚构一个完整公司案例和人物经历。

QA 检查：核心机制之后是否有场景、对话、动作、观察或停顿承接；缓冲是否引入新机制。

严重级别：缺少缓冲为 REVISE；缓冲虚构事实为 BLOCK。

与其他参数关系：RR-03 承接 PD 的深推导，服务 RE-10 真人观察感。

### RR-04｜阅读节奏

状态：ACTIVE

参数目标：让正文在“思考”和“理解”之间交替，而不是持续施加认知压力。

解决问题：解释→解释→解释→解释→总结，读者一路被迫计算。

适用场景：所有知乎长文默认调用。

触发条件：正文连续抽象解释达到 3 段、300 字、2 个机制或 3 次因果连接。

执行规则：
- RR-04-01 基本节奏单元：推荐“现象→场景→解释→判断→缓冲→下一层解释”。
- RR-04-02 段落长度变化：全文应有 1-2 行短段、3-5 行中段和少量 5-8 行长段；禁止全文同长度，禁止全文一句一段。
- RR-04-03 标题密度：1500-2500 字回答建议 3-5 个正文小标题，禁止每 100-200 字设置一个标题。
- RR-04-04 解释切断点：连续抽象解释达到阈值时，用场景、对话、动作、例子或短判断切断。
- RR-04-05 认知峰值分布：首屏给一个判断，中段放最深推导，后段降低密度进入行动边界，结尾不新增理论。

禁止事项：用大量小标题解决疲劳；用一句一段制造虚假轻松；结尾继续新增机制。

合格示例：先展示会议沉默，再解释表达成本，再给一句判断，再进入责任传导。

不合格示例：连续 1500 字解释机制、权力、利益、责任，没有场景或停顿。

QA 检查：连续抽象解释最大值、连续解释段落最大值、段落长度分布、标题密度和结尾是否过载。

严重级别：连续 5 段以上抽象解释为 BLOCK；连续 3 段解释为 REVISE。

与其他参数关系：RR-04 是节奏总控，调用 RR-03、RR-05、RR-06 作为具体手段。

### RR-05｜现实承接

状态：ACTIVE

参数目标：确保所有抽象机制都能落到读者见过的现实中。

解决问题：正文依赖术语，不依赖现实解释。

适用场景：职场、组织、家庭、情感、成长等现实题；抽象机制较多时默认调用。

触发条件：正文出现核心机制、抽象概念或行动建议。

执行规则：
- RR-05-01 机制—场景绑定：每个核心机制至少绑定一个现实场景，例如表达成本对应会议上第一个提出异议的人，权力定义共识对应会议纪要写“一致同意”。
- RR-05-02 抽象词翻译：抽象概念首次出现后，用普通人语言翻译一次。
- RR-05-03 用户经历映射：正文中至少出现一个读者可直接对照自身经历的节点，如领导问有没有意见、群里没人回复、会议纪要写全体通过。
- RR-05-04 真实语言控制：人物语言要短、含糊、符合组织沟通习惯。

禁止事项：只使用概念不提供现实解释；把现实人物写成理论讲师。

合格示例：“责任传导”，就是决定是大家一起定的，出问题却会追到具体做事的人头上。

不合格示例：只写责任传导、组织共识和权力资源，不写会议、邮件、群消息或执行现场。

QA 检查：每个核心机制是否绑定现实场景；抽象词是否翻译为普通语言；现实语言是否自然。

严重级别：核心机制无现实承接为 REVISE；真实案例伪造为 BLOCK。

与其他参数关系：RR-05 保障 RR 可吸收，RE-10 保障表达像真人。

### RR-06｜阅读奖励

状态：ACTIVE

参数目标：让读者在阅读过程中获得阶段性确认、发现和记忆点。

解决问题：文章有收获但缺少点头、发现、判断和行动奖励。

适用场景：所有需要收藏、判断工具或行动边界的知乎回答。

触发条件：正文完成核心机制、权力责任关系或行动出口时。

执行规则：
- RR-06-01 点头奖励：用熟悉场景、真实细节、常见对话或行为观察，让读者产生“确实是这样”。
- RR-06-02 发现奖励：先展示细节，再让读者发现结论，例如没人明确支持，纪要却写全体同意，最后得出沉默被记录成支持。
- RR-06-03 判断奖励：全文建议保留 2-3 个可单独成立的判断句，不得超过 5 个，不得每节都制造金句。
- RR-06-04 行动奖励：行动建议保留 1-3 个动作，如提醒风险、交回决策、守住责任边界。
- RR-06-05 结尾奖励：结尾只收束主判断、给行动边界或留下迁移判断，不新增机制。

禁止事项：把 CR 金句数量当作 RR 阅读奖励；每段都强行总结或制造金句。

合格示例：沉默不会被记录成沉默。它最后会被记录成支持。

不合格示例：每节结尾都写“真正的问题是……”并堆出多个金句。

QA 检查：判断句数量、行动建议数量、结尾是否新增理论、奖励是否来自场景发现而不是口号。

严重级别：奖励过多造成主线分散为 REVISE；结尾新增理论造成主轴漂移为 BLOCK。

与其他参数关系：CR 决定认知奖励目标，RR-06 决定奖励节奏和可吸收性。

### RR-07｜阅读疲劳检测

状态：ACTIVE

参数目标：在生成后识别“逻辑正确但读起来累”的正文。

解决问题：连续抽象、连续解释、认知峰值过多、场景不足、长句疲劳、段落机械化、结尾过载。

适用场景：所有知乎正文生成后自检和 QA。

触发条件：正文完成后默认执行。

执行规则：
- RR-07-01 连续抽象疲劳：连续 3 段没有人物、动作、场景或具体对象，高风险。
- RR-07-02 连续解释疲劳：连续 3 段均以因果解释为主，高风险。
- RR-07-03 认知峰值过多：全文超过 5 个独立核心判断，高风险。
- RR-07-04 场景不足：1500 字以上正文少于 2 个现实场景，中风险。
- RR-07-05 人物语言不足：现实题全文没有人物语言或交流片段，中风险。
- RR-07-06 长句疲劳：超过 60 字句子多于 5 句，或超过 80 字句子多于 2 句，中风险。
- RR-07-07 段落机械化：70% 以上段落长度高度接近、大量一句一段或每节同构，中风险。
- RR-07-08 标题培训感：大量使用第一步、第二步、机制一、机制二且像教学课件，中风险。
- RR-07-09 抽象名词堆积：连续 150 字内出现 6 个以上抽象概念，高风险。
- RR-07-10 结尾过载：结尾 20% 篇幅仍在新增机制、变量或理论，高风险。

禁止事项：把程序化检测当成完整语义判断；脚本只能辅助，最终由 QA 判定语义类指标。

合格示例：QA 输出连续抽象段落最大值、连续解释段落最大值、现实场景数量和超长句数量。

不合格示例：脚本声称准确判断“普通读者一定能理解”。

QA 检查：无高风险项且中风险项不超过 2 个为 PASS；1 个高风险或 3 个以上中风险为 REVISE；连续 5 段以上抽象解释、超过 5 个核心判断或普通读者测试失败为 BLOCK。

严重级别：按 PASS / REVISE / BLOCK 输出。

与其他参数关系：RR-07 是生成后检查层，不作为正文显性内容。

### RR-08｜认知吸收校验

状态：ACTIVE

参数目标：检查读者是否能复述文章，而不仅是作者是否完成推导。

解决问题：正文输出认知很多，但普通读者无法记住主线。

适用场景：所有长文 QA；机制型、组织题和建议型优先。

触发条件：正文完成后默认执行。

执行规则：
- RR-08-01 一句话复述：普通读者读完后，应能用一句话说出文章主要判断。
- RR-08-02 三点复述：读者最多记住三个关键内容，通常是为什么会发生、真正风险是什么、应该怎么做。
- RR-08-03 概念替换测试：删除参数名和理论名后，正文仍应能理解。
- RR-08-04 普通读者测试：无管理学、组织行为或商业背景的读者，应能理解发生了什么、为什么、自己怎么办。
- RR-08-05 跳读测试：只看标题、加粗句、每节首段和结尾，仍应能理解文章主线。

禁止事项：让读者必须记住五个以上步骤才能理解；让行动建议依赖大量术语。

合格示例：读者能复述“公开支持不一定是认知一致，而是反对成本高于支持成本，所以普通员工要提醒风险、交回决策、守住边界。”

不合格示例：删除责任边界、风险传导等术语后，正文无法说明现实中发生了什么。

QA 检查：一句话复述、三点复述、概念替换、普通读者和跳读测试。

严重级别：一句话复述失败或普通读者测试失败为 BLOCK；三点复述失败为 REVISE。

与其他参数关系：RR-08 检查 PD 和 CR 是否被读者吸收，不改变其深度目标。

## RE｜表达体验

### RE-01｜视觉块大小

状态：ACTIVE

调用条件：所有知乎正文默认检查。

输出要求：段落短，推进清楚，避免大段压迫。

禁用条件：无。

验证方式：写入 RE 调用与写作约束。

### RE-02｜停顿点

状态：ACTIVE

调用条件：所有知乎正文默认检查。

输出要求：关键判断后留出停顿，避免连续输出抽象推理。

禁用条件：无。

验证方式：写入 RE 调用与正文落位。

### RE-03｜视觉呼吸感

状态：ACTIVE

调用条件：正文包含机制、利益和博弈推导时默认调用。

输出要求：每 2 到 4 段有一次节奏变化或场景承接。

禁用条件：短答不需要完整长文结构时可不调用。

验证方式：调用或未调用原因写入参数调用。

### RE-04｜新概念出现速度

状态：ACTIVE

调用条件：正文存在核心概念、变量或机制命名时调用。

输出要求：一级核心概念最多 1 个，二级概念最多 3 个。

禁用条件：无新概念时可不调用。

验证方式：调用或未调用原因写入参数调用。

### RE-08｜AI痕迹控制（AIC）

状态：ACTIVE

调用条件：所有知乎正文默认调用。

输出要求：禁止机械编号、PPT 式总结、连续定义概念、并列罗列代替推导。

禁用条件：无。

验证方式：正文 QA 硬闸门；AIC 低于 90 判定 FAIL。

### RE-09｜机械结构检测

状态：ACTIVE

调用条件：所有知乎正文默认调用。

输出要求：禁止“第一、第二、第三”和“三个原因/建议/前提”等学生作文结构。

禁用条件：无。

验证方式：正文 QA 硬闸门。

### RE-10｜真人观察感

状态：ACTIVE

调用条件：所有知乎正文默认调用；建议型 / 解决题、职场题和组织题优先级最高。

输出要求：正文必须像一个人在观察和回想，而不是像系统在整理答案。开头优先从场景、细节、情绪或反常识观察进入；每 300 字至少出现一次具体观察；每 500 字至少出现一次现实场景或对话；禁止连续用“观点 → 解释 → 作用 → 总结”的段落模板推进；减少“本质、核心、真正、实际上、第一层、第二层、第三层、做了三件事、三个作用”等总结词和分层词；允许留白、跳跃和一句话成段；优先让读者点头，再让读者思考。

禁用条件：纯事实查询、数据报告或明确要求学术/培训文风时可降级。

验证方式：写入 RE 调用与写作约束；正文 QA 检查是否存在连续理论段、连续总结句、观察缺失或培训教材感。

## 参数状态治理

低频不等于低价值。参数淘汰不得仅依据调用次数，必须依据“适用机会、调用命中、结果贡献、能力重叠”综合判断。

每 20 篇或每月审计一次参数状态。每个参数记录适用题数量、实际调用数量、应调用未调用数量、调用后的结果表现、与其他参数的重叠程度、当前状态和下一周期处理。

关键指标：

```text
调用命中率 = 实际调用次数 ÷ 适用机会次数
有效贡献率 = 出现正向结果的调用次数 ÷ 有效调用次数
```

参数状态：

- ACTIVE：正常调用，已有证据支持。
- LOW-FREQ：低频但有明确适用场景，继续保留。
- OBSERVE：调用少或贡献不明确，进入观察周期。
- MERGED：与其他参数高度重叠，合并到上级参数。
- DEPRECATED：验证无独立贡献，停止日常调用但保留历史记录。

适用机会不得用实际调用次数代替。连续两个复盘周期无独立贡献的参数，先进入 OBSERVE；完成对照验证后，才允许转为 MERGED 或 DEPRECATED。

进入 DEPRECATED 后只从生产路由隐藏，不物理删除历史证据，防止以后重复创建。
