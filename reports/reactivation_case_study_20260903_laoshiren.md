# Reactivation Case Study｜老实人二次放量

Status：ACTIVE RESEARCH CASE（研究线，不进入生产规则）

Created：2026-09-03

关联实验：`research/experiments/EXP008.md`

## 研究结论边界

当前暂停继续造正文规则，开始专门验证：

```text
二次放量为什么发生？
```

本 Case Study 不解释“老实人为什么写得好”，而是追踪：

```text
平台为什么突然重新给它流量？
```

当前只有一个强 Reactivation 样本，因此不得从本样本反推出“老实人题材容易二次爆”“某种写法稳定触发二次放量”等生产规则。

发布时间：2026-08-18

### 核心增量

```text
2026-08-30 → 2026-09-03：
累计阅读：3,711 → 14,238，增加约 10,527
累计收益：265 → 773，增加约 508 盐粒
```

窗口数据存在重叠，不能精确定位哪一天开始放量；但累计值差异足以确认 2026-08-30 至 2026-09-03 期间发生了数量级更大的新增分发。

### 待回查变量

一旦可采，优先补：

```text
1. 阅读增量：日级 / 小时级增长曲线
2. 互动增量：赞同、评论、收藏在放量前后是否先变化
3. RPM 变化：二次放量前后的盐粒 / 千阅读是否下降或稳定
4. 问题状态：问题本身是否同期重新活跃、关注/回答/热度是否变化
5. 推荐入口：是否来自推荐、搜索、问题页、通知、站外等可见线索
```

当前不可解释为：

```text
正文更好 → 必然二次放量
```

当前只能解释为：

```text
知乎存在至少一个值得研究的 Reactivation 分发阶段。
```

## 分发轨迹类型

| 类型 | 分发轨迹 | 样本 |
|---|---|---|
| A | 首轮一般 → 突然二次爆发 | 老实人 |
| B | 首轮不错 / 有流量 → 快速死亡 | 什么性格的人适合当领导；领导心腹很少有异性；劳务派遣 |
| C | 首轮结束 → 持续长尾 | 经理/总监上不去 |

该对照方式优先于继续盲标原来 18 篇 matched pair。原 EXP008 不删除，继续作为更大的 Distribution Model 保留；本 Case Study 是 EXP008 下的更窄问题。

## 新采集方式

从下一轮开始，新文章至少记录：

```text
1h / 3h / 6h / 12h / 24h / 72h / 7d
```

7 天后继续记录：

```text
14d / 21d / 28d
```

一旦发现某篇文章突然加速，立即补采：

```text
1. 当时累计阅读、赞同、评论、收藏
2. 最近窗口收益、累计收益、RPM
3. 问题页状态：关注、浏览、回答数、高赞占位、是否出现新增高互动回答
4. 可见入口线索：推荐、搜索、问题页、站外、通知等
5. 加速前一观测点与加速后一观测点的差值
```

目标是让下一次 Reactivation 不再只剩：

```text
2026-08-30：3,711
2026-09-03：14,238
```

而是尽量定位：

```text
哪一天 / 哪个小时开始加速
是否先有互动率变化
问题本身是否重新起量
是否进入更大推荐池
```

## 双循环

```text
生产线
正常选题 → 系统写作 → 发布
                    ↓
研究线
时间序列采集 → 发现异常放量
                    ↓
              Case / Control
                    ↓
              找共同变量
                    ↓
              主动实验验证
                    ↓
              验证成功
                    ↓
              才进入生产规则
```

生产端口径：

```text
继续正常发布。
暂时不要为了本发现改变写法。
暂时不要继续新增正文规则。
```

研究端优先级：

```text
P0：建立 Reactivation Case Study，并持续补齐时间序列。
P1：回查 Case A 与 B/C 对照组在二次放量前后的平台状态差异。
P2：只有当共同变量反复出现，再设计主动实验。
P3：主动实验验证成功后，才进入生产规则。
```
