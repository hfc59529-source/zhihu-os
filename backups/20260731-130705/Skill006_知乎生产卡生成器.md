# Skill006｜知乎生产卡生成器 V1.3

Status：ACTIVE

## 目标

将 Notion 知乎系统压缩成 Claude 可直接消费的 Claude 版 Production Card。

Codex 不负责正文创作。

Claude 不负责读取 Notion。

职责彻底分离。

## Codex 职责

Codex 只做流水线，不直接创作正文。

职责只有三个：

1. 读取。
2. 压缩。
3. 校验。

绝不绕过 Production Card 直接写正文。日常正式生产模式下，Codex 只交付可复制 Production Card；只有用户明确要求“生产正文”“写回答”“调用正文节点”“按完整链路生产”时，才在 Production Card 校验通过后继续调用正文生产节点。

## 准入规则

日常生产不再强制要求读取同题前三高赞回答。

只要以下系统参数读取成功，即可进入 Claude 版 Production Card 生成：

1. 当前选题可完整识别。
2. 已从 `production_variable_library.md` 生成本题 `runtime/production_variable_snapshot.md`；历史资产检索可作为账号验证证据摘要，但不得替代变量权威。
3. 结构库存在可用 ACTIVE 结构。
4. 质量参数库默认正文参数读取成功。
5. 能基于 Notion 相邻样本、TOP 变量、ACTIVE 知识或历史收益证据提取爆款规律。
6. 历史资产检索已执行；命中不足时必须标注“历史证据不足”，但不得单独阻止 Production Card。
7. PD 参数路由器运行成功。
8. QT-QI 问题理解路由器运行成功。
9. 阅读体验参数路由器运行成功。
10. 行为转化参数路由器运行成功。
11. 参数调用锁定卡生成成功。

同题前三高赞回答只作为增强项：

- 用户提供同题高赞样本时读取。
- 用户明确要求竞品分析时读取。
- 当前系统参数命中不足时，可作为补充证据读取。

没有同题前三高赞回答，不得单独作为停止 Production Card 的原因。

按 `08｜总AI执行中心` 的调度协议，额外加载：

- `知乎内容质量参数库`
- `是否默认=True`
- `适用于=知乎正文`
- `调用阶段=正文生成`
- `优先级=P1/P2/P3`

Skill006 必须读取质量参数库默认正文参数，先完成 26 维质量参数总审计，再按本题需要压缩为分层调用结果。读取参数库不等于调用全部参数。

```text
RR-06｜阅读奖励
RR-07｜阅读疲劳检测

BT-01｜收藏动作
```

Production Card 生成前必须先完成 `QT-QI｜问题理解系统`：

```text
L0｜问题分类：事实型 / 解释型 / 判断型 / 预测型 / 建议型 / 决策型 / 情绪型 / 价值观型 / 经验型 / 机制型
L1｜用户问题解析：提问动机、真实问题、当前认知、认知缺口、认知目标、阅读奖励、情绪状态、行为预期
L2｜问题形成机制：触发来源、信息来源、决策阶段、搜索目的、情绪来源、风险感知、价值预期
L3｜路由参数：主变量、辅助变量、PD调用、RR调用、RE调用、BT调用、首屏策略、结尾策略、风险限制
L4｜AI执行规则：IF条件、THEN调用、禁止调用、优先级、冲突处理、默认值
L5｜验证指标：命中率、收藏率、评论率、阅读率、收益率、是否升级参数状态
```

`问题理解调用` 是 Production Card 的上游识别字段，不计入 `质量参数调用` 的核心/辅助参数数量。

参数审计必须区分：

1. 强制底线参数。
2. 本篇核心调用参数。
3. 本篇辅助调用参数。
4. 本篇不调用参数。
5. 未调用原因。
6. 适用但未调用的路由风险。

如果没有完成 26 维总审计，不允许交付 Production Card。

`质量参数调用` 字段必须写清参数分层：

- 强制底线参数：只放生成前必须遵守的表达底线和 QA 底线。
- 本篇核心调用参数：正文内容参数控制在 3-6 项。
- 本篇辅助调用参数：表达参数控制在 2-4 项。
- 本篇不调用参数：必须写原因，便于后续验证参数选择是否正确。
- 行为目标：只允许 1 个主要目标，最多 1 个次要目标；当前阶段禁止把关注作为知乎生产目标。

QA 参数不计入正文调用数量，只在生成后和终检阶段执行。禁止以“默认调用或条件触发”为理由判定全部参数均调用。

低频参数不得因调用次数低直接排除。审计低频参数时，必须先判断本题是否存在适用机会；若适用但未调用，必须在未调用原因中标注“路由漏调风险”，不得写成“低频无价值”。

参数淘汰依据是适用机会、调用命中、结果贡献和能力重叠，不是调用次数。连续两个复盘周期无独立贡献的参数，先进入 OBSERVE；完成对照验证后，才允许转为 MERGED 或 DEPRECATED。

`本篇重点执行` 字段只写本题最关键的 5-10 条质量要求。

禁止把参数库说明、评分标准、验证指标、Notion 页面名、审计过程或分析过程写入 Production Card。

禁止读取：

1. 历史实验
2. 旧协议
3. TEST
4. Candidate
5. 历史 Prompt

只有用户明确要求“生产正文”“写回答”“调用正文节点”或“按完整链路生产”时，才允许自动调用 `templates/Claude正文生产Prompt.md` 和 `docs/知乎正文推理协议 V1.0.md`，由 Claude 生成正文。

## 自动填充规则

### 0. ACTIVE 规律回流

生成 Production Card 前，Skill006 必须先完成 ACTIVE 规律回流调用。

输入：

```text
题型：
场景：
用户意图：
历史资产检索摘要：
```

读取源：

```text
runtime/知乎ACTIVE规律快照.md
```

输出：

```text
推荐主变量：
推荐辅助变量：
推荐结构：
禁用变量：
命中 ACTIVE 规律：
未命中原因：
```

边界：

- Skill006 不得直接读取 L2 正文变量矩阵、05 单篇复盘库或 05.5 规律验证库来决定 Production Card。
- 只有已经发布到 runtime 的 ACTIVE 规律，才能反向影响生产。
- 如果 ACTIVE 规律未命中，必须标注“ACTIVE 规律未命中”，继续按内容路由、结构库、`production_variable_library.md`、生产变量运行时快照、质量参数库和历史资产检索生成 Production Card。
- 禁止把未验证变量、Candidate、Experiment、单篇复盘结论或 Notion 临时页面写入 Production Card。
- ACTIVE 命中结果只能压缩进现有字段，不得新增 Production Card 字段。

### 1. 唯一主变量

先读取 ACTIVE 规律回流结果，再从 `production_variable_library.md` 生成 `runtime/production_variable_snapshot.md`，最后读取运行时快照。

优先选择 ACTIVE 规律命中的推荐主变量；若未命中，再按运行时快照中的命中变量、题型、历史资产检索和质量参数路由选择唯一主变量。

`HYPOTHESIS` 只允许作为指定单变量实验或回溯验证调用，不得指导日常正文生产。`EXPERIENCE` 只允许在 Production Card 中标注为实验性调用，不得覆盖 ACTIVE 变量。`DEPRECATED` 禁止生产调用。

输出：

```text
唯一主变量：
管理成本
```

### 2. 辅助变量

最多三个。

优先使用 ACTIVE 规律回流给出的推荐辅助变量；若存在禁用变量，必须从辅助变量候选中排除，并在生产前分析或未调用原因中说明。

输出示例：

```text
辅助变量：
1. 组织视角
2. 风险传导
3. 利益重分配
```

禁止超过三个。

- 如果正文生产阶段发现题型、结构、证据或变量不成立，只能退回 L1 重做卡，禁止由正文节点自行修正。

### 6. 参数调用

先生成 `问题理解调用`：


填写规则：

- 问题分类只选 1 个主类型，最多 1 个副类型。
- 用户意图必须覆盖真实问题、当前认知、认知目标、情绪状态和行为预期。
- 用户隐藏约束必须识别用户不能做什么、害怕失去什么或不能承受什么代价，例如不能得罪领导、不能失去工作、不能影响晋升、不能显得能力差、不能增加过高执行成本。
- 路由结果必须写明将调用或限制的 PD / RR / RE / BT。
- 执行规则必须写成 IF/THEN 或“必须/禁止”格式。
- 验证指标只写本题最相关的 1-3 个指标。

读取 `知乎内容质量参数库` 中满足以下条件的默认正文参数：

```text
调用阶段=正文生成；
优先级=P1/P2/P3。
```

`本篇重点执行` 只保留本题最关键的 5-10 条质量要求，例如推导深度、机制解释、利益分析、场景承接、阅读节奏、收藏驱动力、AI 痕迹控制、评论驱动力。

## Claude版 Production Card 模板

Production Card 的字段名称、顺序和模板结构，唯一权威为：

`templates/Production Card模板.md`

Skill006 不得复制维护第二套字段模板。

当 `templates/Production Card模板.md` 更新时，Skill006 只按该模板生成和校验，不得沿用历史字段结构。

## 字段规则

Claude 版 Production Card 当前固定 17 个字段：

1. 问题
2. 问题链接
3. 平台
4. 题型
5. L1冻结卡
6. 唯一主变量
7. 辅助变量
8. 变量证据
9. 问题理解调用
10. 认知奖励目标
11. 质量参数调用
12. 本篇重点执行
13. 核心机制
14. 正文结构
15. 禁止推导
16. 结尾任务
17. 写作约束

字段数量和顺序以 `templates/Production Card模板.md` 为唯一权威；上方列表只用于解释当前模板，不得手工维护第二套模板。

`认知奖励目标` 必须指定 1 个主CR，最多 1 个辅助CR，并写清目标判断能力。禁止写泛化参数 `CR｜认知奖励`。

变量作用必须写在 `辅助变量` 字段内，每个变量一句话。

`核心机制` 禁止只填写名词、变量名或抽象概念。

必须写成完整的机制判断句，直接冻结正文推导终点。

`核心机制` 至少同时回答：

```text
现象是什么
↓
机制为什么发生
↓
背后的利益、权力或组织规律是什么
↓
这个规律在什么同类场景还成立
```

`核心机制` 必须包含机制终点：正文最终要推导到的利益分配、权力配置或组织运行规律。

`核心机制` 必须包含可迁移规律：读者以后判断同类组织场景时可以复用的条件句。

禁止停在责任、利益、权力、风险、资源等中间概念；必须继续写清这些分布为什么会稳定制造题目中的现象。

禁止示例：

```text
风险传导
利益重分配
组织信任
责任边界回收
```

允许示例：

```text
某个现象并不是由单一态度造成，而是由当前场景中的成本承担、收益归属和选择权分布共同塑造。只要同类场景中仍然存在相同的成本、收益和选择权配置，相似行为就会重复出现。
```

禁止出现：

- MASTER
- ACTIVE
- Notion
- 命中页
- 未命中
- 审计
- 协议版本
- 调度信息
- 制作过程
- 分析过程
- 缺少 `===Production Card Begin===`
- 缺少 `===Production Card End===`

## 自检规则

Production Card 输出完成后，Codex 必须自检。

### 检查一

是否只有 1 个唯一主变量。

否则：`Fail`。

### 检查二

辅助变量是否小于等于 3 个。

否则：`Fail`。

### 检查三

核心机制是否来自数据库原文。

核心机制是否为完整判断句，而不是名词、变量名或抽象概念。

核心机制是否已经写清“现象 → 机制 → 利益/权力/组织规律”的推导终点。

否则：`Fail`。

如果 AI 生成：`Fail`。

### 检查三点五

是否存在 `L1冻结卡` 字段，并包含题型、结构版本号、至少 3 条冻结证据清单和禁止后改项。

冻结卡内题型是否与上方 `题型` 一致。

否则：`Fail`。

### 检查四

是否存在 `问题理解调用` 字段，并包含问题分类、用户意图、用户隐藏约束、形成机制、路由结果、执行规则和验证指标。

否则：`Fail`。

### 检查五

是否存在 `质量参数调用` 字段，并包含强制底线参数、本篇核心调用参数、本篇辅助调用参数、本篇不调用参数和行为目标。

否则：`Fail`。

### 检查六

是否存在 `本篇重点执行` 字段，且包含 5-10 条本题重点质量要求。

否则：`Fail`。

### 检查七

正文结构是否来自模板。

否则：`Fail`。

### 检查九

Production Card 是否超过一页。

超过：`Fail`。

### 检查十

Claude 版 Production Card 是否只包含固定字段。

否则：`Fail`。

### 检查十一

是否存在 `===Production Card Begin===` 和 `===Production Card End===`。

否则：`Fail`。

### 检查十二

是否存在变量证据、调用理由和证据等级。

否则：`Fail`。

自检失败时，只输出 `Fail` 和失败项，不交付 Claude。
